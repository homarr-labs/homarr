## Version and execution guardrails

For future user-authorized subagents, prefer `openai/gpt-6.1-sol` with high thinking, within the user-authorized medium-to-xhigh range. Look up exact available model and thinking/variant IDs when dispatching; use the supported selection rather than guessing identifiers. This preference does not itself authorize delegation.

Pin before copying APIs. Evidence snapshot: stable `nitropack@2.13.4`; released `nitro@3.0.260903-beta` is beta despite `latest`; inspected main is `cef5305050325a36601ff118b9651d43a0f9ba58`. Release-tag source/package exports arbitrate implementation; current docs/Context7 can describe main. On storage/cache work, check released `nitro/storage` versus main `nitro/kv`, unbounded released defaults versus main bounded-cache options. On task/listener work, check beta shutdown/socket gaps and deduplication caveats. On ORM work, check db0’s Drizzle v1/RC requirements against Homarr `0.45.2`. Reach the corresponding note for exact sources rather than assuming these observations apply to a later pin.

Use executable Docker/startup evidence for the Node production baseline; Bun installation does not prove Bun serving. Treat missing RAM/image/latency/DX observations as unavailable, and obtain approved budgets before acceptance comparisons. All research artifacts belong to this existing worktree. This handoff authorizes no code/manifests, Linear edits, branches, commits, pushes, new worktrees, glossary/ADR/root-agent edits or new research by itself; obtain task-specific authorization through the active branch. GitHub Pages remains outside scope.
