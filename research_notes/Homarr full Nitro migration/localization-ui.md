# AJN-509 — Localization and shared frontend replacements

Research captured 2026-10-10. **Recommendation, not an approved library/product decision or a compatibility result.** Preferred seam: keep Homarr's catalogs and public translation facade, implement it with standalone **`use-intl`**, and replace Next-owned request/routing/provider glue with explicit request-local locale/bootstrap services. Keep Mantine forms, modal machinery, notifications and UI; adapt their navigation, transport and asset edges rather than replacing them wholesale.

### Catalog reconciliation

Read-only flattening found **36** JSON catalogs, only string leaves. English has 4590; every other catalog has **4597**, containing the same English keys plus seven `board.snapshot.*` keys (`failed`, `take`, `description`, `playground`, `downloadedDescription`, `failedDescription`, `downloaded`). Preserve these extra translations; their presence is not proof the feature remains assigned or currently reachable. Blank strings are material: e.g. Hebrew **654**, Finnish **749**, English UK **646**, Japanese **613**, simplified Chinese **3**; English **0**. Source fallback merge is necessary for real data, not hypothetical edge handling.

Named rich tags found across catalogs include `here`, `url`, `b`, `bName`, `time`, `checkoutDocs`, `docsLink` and `<unk>` in some translated content. A regex occurrence does **not** prove well-formed tags or compatible ICU. Examples/call sites to preserve:

- `widgets/src/_inputs/widget-app-input.tsx`: `tApp.rich('description', {here: …})` renders app-creation link.
- Management integration connection error (`integration-test-connection-error.tsx`): rich `url` callbacks alongside status/reason; `test-connection-certificate.tsx`: rich docs link.
- Group `_reserved-group-alert.tsx`: documentation callback; invite form: `b` warning that copy is one-time; Assistant `assistant-runtime-controls.tsx`: rich reset `<time>`.
- `components/navigation/dynamic-breadcrumb.tsx`: `t.has(labelKey)` and fallback labels. No production `t.raw`/`t.markup` consumers were found by the focused translator-method search; both are nevertheless part of the currently exported translator object.

No blanket claim that every existing translation is valid, complete or linguistically equivalent is made. For the replacement, prove parser/renderer behavior against preserved data, and report existing malformed entries distinctly from migration regressions.

## 2. Library comparison against actual catalogs and first-party evidence

### Preferred: standalone `use-intl`, not `next-intl/server` under a new host

Official documentation explicitly supports ordinary React and non-React apps with `use-intl`, omitting Next routing, awaitable APIs and RSC request integration. Installed **4.13.1** confirms:

- `next-intl/dist/esm/development/index.react-client.js` reexports provider/hooks from `use-intl/react` and core from `use-intl/core`; standalone package dependencies contain Intl/ICU utilities, **not Next**. `/core` and `/react` are public conditional exports. `core/createTranslator.d.ts` exposes string call, `rich`, `markup`, `raw`, `has`, scoped namespace types; `core/index.d.ts` exports `createTranslator`, `createFormatter`, `AppConfig`, message-key types. [U1, U3]
- `use-intl/react` exports `IntlProvider`, `useTranslations`, `useLocale`, `useMessages`, `useFormatter`, `useNow`, `useTimeZone`. `IntlProvider.d.ts` receives **explicit locale/messages/timeZone/now/formats/error behavior**. It does not infer Next request config.
- Next server conditional entry uses `next-intl/config`, React request caching and request headers; generic SSR does not supply those automatically. `NextIntlClientProviderServer.js` inherits request config/timezone/messages, unlike standalone provider. Current Homarr request config supplies neither timezone nor now; installed Next integration computes default server timezone, but provider intentionally does **not** invent now when absent. Standalone port must specify the desired basis; don't claim current hydration is already deterministic. [U3]
- Current ICU implementation delegates to installed `intl-messageformat` (11.1.1). The same pinned standalone version removes one unnecessary parser/API migration, although loader/context/SSR compatibility still must be demonstrated. Reusing latest rather than 4.13.1 would require a version-diff and behavior proof, not an assumed harmless upgrade.

**Why preferred:** current nested catalogs/scoped hooks/rich callbacks/formatter methods are natively represented. Most consumers can keep `@homarr/translation` imports, reducing edit conflicts without imposing a temporary tRPC/Next compatibility layer. There is no documented full-Homarr RAM/bundle advantage asserted for this choice. Extraction/minification/precompilation/namespace partitioning are independent optional optimizations, not necessary to get off Next.

## 4. Minimal target adapters (proposed interfaces, no code changed)

Avoid a universal framework facade hiding all behavior. Prefer five explicit seams with small data contracts, keeping stable consumer aliases only where they genuinely match.

1. **Catalog/translator seam** — dependency-light `CatalogLocale`, `TranslationObject`, key/namespace types, locale metadata and helper callbacks; pure `loadMessages(locale)` returning immutable selected+English merged nested messages; `createTranslatorFor(snapshot, namespace?)` / `createFormatterFor(snapshot)` built from selected engine. Browser `/client` retains `useI18n`, `useI18nMessages`, `useCurrentLocale`, `useCurrentIntlLocale`, adds formatter/now hooks so releases/Scalar have no library bypass. Server passes request/locale snapshot explicitly, optionally a closure `requestI18n.get(namespace)`; no process-global current locale and no Next server/config entrypoint in target graph.
2. **Locale seam** — request resolver consumes recognized legacy prefix, supported cookie and validated instance default; returns canonical route and `catalogLocale`, `intlLocale`, direction and persistence intent. Browser `changeLocale` loads selected messages/MRT/Day.js resources, persists `homarr.locale`, commits provider+HTML lang/dir coherently and invalidates locale-dependent route/query data. Keep existing pending/no-op same-locale semantics. A full document reload is a viable low-complexity option but must be approved for draft loss/UX; SPA switch needs ordered/cancel-safe resource work and authentication-independent guest support.
3. **Render formatting snapshot** — serialized public data records catalog locale, intended message-engine locale, Intl locale, direction, message/catalog revision (or build identity), timezone, now epoch and relevant culture preferences. Immutable HTML/bootstrap uses this exact snapshot; Date restored intentionally before provider. Cache key varies on all **output-affecting** locale/catalog/culture/timezone/theme inputs, not browser header guesses. Time freshness belongs to renderer/widget contract, not a frozen global translator.
4. **Navigation/cache seam** — typed internal Link/route targets, raw safe external anchor behavior; route-owned search/page models and push/replace/refresh callbacks to shared inputs. Mutation outcomes list affected client resources/routes; Query invalidation and Router loader invalidation run independently of backend revision updates. Never expose `invalidateAnyPath(path)` merely to recreate Next server action. Central route-tree registration is single-writer, components/hooks can be ported against typed callbacks first.
5. **Asset/head seam** — stable public branding/media URLs vs Vite-imported known assets, Native/Mantine image policy (alt, dimensions, fit, lazy/eager, error fallback), self-hosted Inter/CSS variable and explicit safe head/script descriptors. Nitro renderer owns document/CSP/script/asset-manifest emission; UI consumes URLs, not Next image/font objects. Unknown remote input never becomes trusted script/font/image-fetch configuration.

**SSR detail:** carry engine locale separately if normalized. If translator uses `zh-CN` but `useCurrentLocale` aliases engine `useLocale`, current storage key `cn` disappears; wrapper must return catalog key from locale context, while formatter uses intended Intl locale. Conversely passing raw `cn` to all Intl constructors retains existing inconsistencies. Human decides this mapping; acceptance samples must include Chinese/Hebrew/Crowdin, not only English/French.

**Request isolation detail:** pure immutable catalog data can be memoized by locale/build; mutable translator caches, router, QueryClient, language instances, Day.js global selection and Zod global error config must not carry another request's locale/identity. This is independent of whether HTML is cached. Existing cached SSR fixture's request isolation cannot certify the new multi-locale provider stack.

## 6. Human decisions and acceptance gates

### Choices still needing a human resolution

1. **Engine/workflow**: recommended `use-intl@4.13.1` first, or intentionally adopt FormatJS/i18next/Lingui and their flattening/rich/type/compile tooling. Any later upgrade is permitted but not researched as automatically equivalent. No RAM/JS ranking exists.
2. **Locale behavior vs corrections**: keep no-prefix URLs, cookie-only preference and disabled Accept-Language recommended. Approve preserving search/hash on switches, canonical message-engine Intl mappings (especially `cn`/`zh`/`cr`), malformed translation handling and raw environment-formatting cleanup rather than treating these as invisible implementation details.
3. **First paint/timezone policy**: server timezone + serialized now for deterministic populated SSR, user/widget zone where known, or deterministic placeholder until browser zone known. Existing app mixes server defaults and browser-native formatting; adopting user's timezone on first paint requires trustworthy public render/cache variants, not arbitrary client header trust.
4. **Locale switching/drafts**: SPA atomic switch vs reload; pending/error/retry policy; preserve open modal/form/editor state or explicitly communicate unsaved-work loss. Cross-tab behavior is not currently established by locale hook.
5. **Crowdin**: keep JIPT with initialization after safe hydration vs different DOM ownership/isolation; this can affect live-translation editing. Cannot silently drop `cr` because DOM rewriting is awkward.
6. **Fonts/image delivery**: recommended native image for current bounded local uses and self-hosted Inter. Human approves any new optimizer, font substitution, glyph coverage or external font requests with privacy/offline/CLS consequences.
7. **RTL**: preserve Hebrew current capability, explicitly approve target fixes and verification breadth. Mantine's support does not decide board placement/drag semantics, charts, custom CSS or third-party widget mirroring.
