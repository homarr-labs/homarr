# Integration/provider preservation for the full Nitro migration

## Scope, provenance and result

Read-only research on 2026-10-10, branch `rework-hono`, HEAD `66e2199f9cd1e4026249c3763413988bab8664c4`. Source was inspected as present in this checkout. Existing uncommitted `.scratch/`, `apps/nitro-experiment/`, reports, research notes, manifest/lockfile and ignore-file work was left unchanged. The only output of this worker is this note. No app imports, network requests, credentials, installs, containers, builds, tests, lint/typecheck or Linear writes were used. The live map was **not** refreshed because this assignment forbids live requests; its local research contract and question are [RESEARCH.md](../../.scratch/nitro-full-migration/RESEARCH.md) and [issues/integrations.md](../../.scratch/nitro-full-migration/issues/integrations.md).

**Outcome:** keep every one of the **89 registered kinds (88 non-Mock plus Mock)**. The definition and lazy-creator key sets match, with no missing or extra factory keys. There are **30 native Stats provider modules and 59 other factory entries**. Generic Stats implements **86 kinds = 30 native + 56 existing-client adapters**; `ical`, `bindery`, `wazuh` are not implemented in Stats, but their native clients/capabilities must remain. Generic HTTP eligibility declares **87 kinds**, excluding only `ical` and `truenas`; eligibility is not proof that every credential mode works. `qBittorrent` username/password mode is intentionally native-only for this HTTP surface. These are static source reconciliations, **not executed compatibility results**. Sources: [definitions](../../packages/definitions/src/integration.ts), [creator](../../packages/integrations/src/base/creator.ts), [native Stats registry](../../packages/integrations/src/stats/providers.ts), [existing Stats adapters](../../packages/integrations/src/stats/existing.ts), [Stats dispatch](../../packages/integrations/src/stats/index.ts), [HTTP coverage specification](../../packages/api/src/test/integration-http-auth-coverage.spec.ts).

Most provider parsing, mappings, SDK call sequences and domain types are reusable service logic. There are **no production `next/*` or tRPC imports in `packages/integrations/src`**. Framework coupling is concentrated in management pages, API procedures, middleware and composed request flows. Runtime coupling is real: Node TLS/crypto/HTTPS/AsyncLocalStorage, Undici/Axios/SDK transports, certificate trust and proxy/DNS policy, encrypted Redis sessions, two Redis history consumers, image-proxy registrations and persistent upstream connections. No evidence requires replacing every provider library or rewriting upstream APIs. Recommendation: put these dependencies behind framework-neutral server ports; retain upstream protocol behavior and adapt the host. This is not a decision to retain Redis, tRPC, Drizzle or any particular SDK permanently. [Package manifest](../../packages/integrations/package.json), [base](../../packages/integrations/src/base/integration.ts), [HTTP infrastructure](../../packages/core/src/infrastructure/http/request.ts), [session store](../../packages/integrations/src/base/session-store.ts).

The older [storage/background note](../Homarr%20Nitro%20migration%20experiment/storage-background.md) is useful evidence for existing state semantics, not a final-stack mandate. The [stack-choice handoff](../Homarr%20Nitro%20v3%20stack%20choices/AGENT-HANDOFF.md) explicitly leaves final runtime/persistence undecided and permits library changes. The fixture is not provider acceptance. Widget rendering/options belong to `widgets.md`; common cache/scheduler/persistence decisions belong to `persistence-background.md`; transport registrations belong to `endpoints-transports.md`.

### Known discrepancies to carry into the parity ledger

1. Stats selection includes `bindery` and `wazuh`, but `getStatsMetrics` returns `[]` and `fetchStatsAsync` rejects unsupported kinds; iCal is correctly excluded. This is **existing mismatch**, not authorization to remove either integration or fabricate metrics. Human/product decision: retain the existing empty/unsupported state or make a separately specified capability-map correction. [Widget map](../../packages/definitions/src/widget-integration-map.ts#L36), [Stats dispatch](../../packages/integrations/src/stats/index.ts).
2. The integration-create MCP description says a nonempty secret array is mandatory and gives a Proxmox example inconsistent with the registry. Actual schema allows `[]`, and many providers require no secrets; Proxmox requires `username, tokenId, apiKey, realm`. Preserve actual validation/registry behavior, reconcile generated descriptions centrally, not via arbitrary new upstream APIs. `attemptSearchEngineCreation` is accepted and appears in the form but no effect is implemented by the inspected create mutation. [Schema](../../packages/validation/src/integration.ts), [router](../../packages/api/src/router/integration/integration-router.ts#L225), [form](../../apps/nextjs/src/app/[locale]/manage/integrations/new/_integration-new-form.tsx).
3. Generic HTTP mode matching is exact by saved secret-kind set; it is not the same as test-connection alternative selection. qBittorrent password credentials are intentionally rejected there, even though native download operations accept them. Uptime Kuma's optional API key authenticates generic HTTP with empty-username Basic but **native monitor reads still use public status-page endpoints**. [Auth resolver](../../packages/integrations/src/http-auth.ts#L29), [HTTP test specification](../../packages/api/src/test/integration-http-auth-coverage.spec.ts), [Uptime Kuma](../../packages/integrations/src/uptime-kuma/uptime-kuma-integration.ts).
4. `mock` is hidden in onboarding and Docker discovery, but can be created directly; both `MockIntegration` and separate `mockWidgetData` shortcuts are necessary. Do not equate Mock's small category list with every fixture-enabled surface. [Definition](../../packages/definitions/src/integration.ts#L1019), [Mock class](../../packages/integrations/src/mock/mock-integration.ts), [fixture exports](../../packages/integrations/src/mock/widget-data.ts).
5. `personalAccessToken`, `privateKey`, `githubAppId`, `githubInstallationId` are defined secret kinds, but there is **no registered GitHub integration/client** in this checkout. `octokit` and `maria2` dependencies likewise have no production import under integration source; aria2 uses its own JSON-RPC proxy. Do not count manifest dependencies/secret names as providers. Retain durable values when importing old data; removal of unused dependencies is a separate implementation decision. [Definitions](../../packages/definitions/src/integration.ts#L11), [manifest](../../packages/integrations/package.json), [Aria2](../../packages/integrations/src/download-client/aria2/aria2-integration.ts).

## 2. Exhaustive provider ledger

Legend: **R** = domain client/parser/mapping reusable; **A** = hosting/infrastructure adapter required; **A-session**, **A-history**, **A-image**, **A-SDK**, **A-stream** identify additional seams. Every row has shared **A-transport/test/security** obligations even if labelled R. No provider is classified for whole-service replacement on present evidence. Upstream wire paths below are **existing source behavior**, not suggested replacement endpoints.

Credential shorthand: `K` = `apiKey`; `U/P` = `username,password`; `none` = empty array; alternatives separated by `or`. Definitions retain their ordering/default, public/private flags and optional values. **F/L** columns specify fixture obligations and matching **future opt-in live acceptance** for that row. They extend shared gates F0/L0 below; no live calls were performed or authorized here.

## 3. Management, data, authorization and secret preservation

### Durable schema and configuration

Integration rows contain `id,name,url,kind,appId`; linked app deletion sets appId null. Secret rows are keyed by `(integrationId,kind)`, store encrypted `value` plus `updatedAt`, and cascade on integration deletion. Per-user/group delegated use/interact/full permissions and item→integration attachments are separate relations. There is **no general per-integration options JSON column** here: operation arguments and widget option contracts are separate from connection credentials. The PostgreSQL schema has a parallel integration model; durable IDs, kinds, encrypted values, revisions, relations and permissions need preservation regardless of target storage choice. [SQLite](../../packages/db/schema/sqlite.ts#L192), [PostgreSQL](../../packages/db/schema/postgresql.ts), [relations](../../packages/db/schema/sqlite.ts#L802).

`externalUrl` is derived from linked app href, not a replacement for internal API `url`. It affects links and cache identity. Base URL helpers append service paths while keeping configured subpaths; `externalUrl` falls back to API URL, and `webSocketUrl` transforms http→ws/https→wss. Tests need prefixed deployments and separate external links, not only bare localhost. iCal's actual feed is a **private URL secret**; Wazuh may have a second indexer origin and optional dashboard origin; these cannot be flattened into one arbitrary client endpoint. [Base URLs](../../packages/integrations/src/base/integration.ts#L70), [middleware](../../packages/api/src/middlewares/integration.ts), [Wazuh](../../packages/integrations/src/wazuh/wazuh-integration.ts).

Credential privacy is registry-owned: public `username,tokenId,realm,topic,patchmonApiKey,githubAppId,githubInstallationId,slug,wazuhIndexerUrl,wazuhIndexerUsername,wazuhDashboardUrl`; private `apiKey,password,personalAccessToken,opnsenseApiKey,opnsenseApiSecret,patchmonApiSecret,url,privateKey,wazuhIndexerPassword`. `privateKey` alone is multiline. “Public secret” means disclosed to an authorized full-access editor, **not universally public**. Keep encryption material/server crypto out of browser imports; use shared domain types instead of the two download types' current `@homarr/db/schema` type coupling. [Secret registry](../../packages/definitions/src/integration.ts#L11), [byId redaction](../../packages/api/src/router/integration/integration-router.ts#L211), [download items](../../packages/integrations/src/interfaces/downloads/download-client-items.ts), [status](../../packages/integrations/src/interfaces/downloads/download-client-status.ts).

### Native versus arbitrary request authorization

Native read middleware checks allowed kinds and user/query policy **before decryption**, including integration visibility through attached boards/items; interact checks delegated/global interact permission for every selected integration. Public board read access is not arbitrary HTTP permission. Full access controls config/secrets and **all arbitrary HTTP methods including GET**, because arbitrary reads can leak credentials or trigger upstream changes. Endpoint conversion must reproduce policy, not replace all native reads with generic integration_request. [Native middleware](../../packages/api/src/middlewares/integration.ts), [query policy](../../packages/auth/permissions/integration-query-permissions.ts), [arbitrary selection](../../packages/api/src/router/integration/integration-http.ts#L26).

Generic request accepts exactly one ID/name/kind selector (ordered first full-access match for non-ID selectors), relative path scoped to saved origin/base prefix, safe static headers with stored auth precedence, JSON/raw bodies, seven HTTP methods and `confirmed=true` for DELETE. It disallows absolute/protocol-relative paths, escapes/redirects, GET/HEAD bodies, oversized inputs; executes with no cache/no retries, 15-second timeout, 10-KiB body, 16-KiB headers, 1-MiB response. It returns upstream `ok,status,statusText,data`; HTTP success can still contain upstream application errors. Response/error redaction covers stored and derived credentials, query/body auth plus encoded/JSON/base64 representations. Timeout after a write is ambiguous: never automatically retry. These contracts also feed Custom JSX integration connections; the executor remains extended-feature-owned, the credential resolver integration-owned. [Request schema/execution](../../packages/api/src/router/integration/integration-request.ts), [connection/auth resolution](../../packages/api/src/router/integration/integration-http.ts), [auth types](../../packages/integrations/src/http-auth.ts).

### Cache, cancellation and runtime facts

- Shared response identity includes integration ID/kind/API URL/external URL, keyed fingerprints of secret values and updatedAt, plus operation options. Shared namespaces/generation/lock tokens prevent stale completion after config edits. Default L1 TTL is 10 seconds, max 1000 entries/100 upstream work entries, 60-second request deadline; configurable stale-on-error uses a five-minute default stale window. Downloads explicitly 10 seconds; organizer/list/request-stats 60 seconds; media releases five minutes with stale fallback; smart-home entity state and Beszel history Stats use zero TTL. Preserve each handler's source options, not a uniform Nitro route cache. [Identity](../../packages/request-handler/src/lib/integration-request-handler.ts), [request lifecycle](../../packages/request-handler/src/lib/request-handler.ts), [shared cache](../../packages/request-handler/src/lib/shared-cache.ts), consumer files above.
- **Deadline ≠ physical cancellation.** `createIntegrationRequestHandler` passes a signal but most consumer callbacks ignore it and call client methods without a signal. The request handler aborts/races its own controller and tracks unsettled work; it does not itself bind AsyncLocalStorage. Existing Stats adapters explicitly use `withHttpRequestSignalAsync`, which propagates through core fetch/Axios but not automatically through every SDK or raw websocket. Native Stats providers use explicit signal. Target client ports should carry operation signal/deadline and keep unsettled-work guards when a transport cannot cancel. [Handler](../../packages/request-handler/src/lib/request-handler.ts#L163), [calendar example](../../packages/request-handler/src/calendar.ts), [existing Stats signal binding](../../packages/integrations/src/stats/existing.ts#L17), [HTTP signal](../../packages/core/src/infrastructure/http/request-signal.ts).
- Stats has one-hour freshness and one-minute retry after error, persistent stable snapshot per integration, max 128 local pending requests, per-source 120-second lock plus four shared refresh slots, lease renewals, 60-second work deadline and generation/identity rechecks. Existing Stats dispatch has a **second local max-128 legacy pending guard** so an ignored abort cannot start duplicate work immediately. Preserve last good values and error/stale timestamp; a scalar metric absent from a provider stays absent. Physical scheduler/locking choice is persistence worker's decision. [Stats snapshot implementation](../../packages/request-handler/src/stats.ts), [dispatch guard](../../packages/integrations/src/stats/index.ts).
- Encrypted session envelopes use SuperJSON, version/type marker and keyed configuration fingerprint over ID/URL/sorted secret kind+value. Unsupported legacy/mismatched/corrupt sessions are ignored; TTL is caller-owned; set failure is logged rather than guaranteed persisted. Consumers: Pi-hole v6, Technitium, OMV, Glances version cache, Synology, UniFi generic HTTP, Beszel, Wazuh. Synology has a 600-second write on one path and no TTL on another; other session TTL/retry policies likewise vary. Do not turn “session store exists” into an invented universal expiry policy. [Store](../../packages/integrations/src/base/session-store.ts), concrete sources in provider table.
- Two direct relative Redis imports are real coupling: Dashdot CPU history and OPNsense interface history. Adapt to a history port retaining ordered timestamps/window/sample limits, not a scheduler inside each client. No other provider should need to depend on Redis channel symbols. [Dashdot](../../packages/integrations/src/dashdot/dashdot-integration.ts), [OPNsense](../../packages/integrations/src/opnsense/opnsense-integration.ts).
- Plex, Gotify, Immich and Tracearr consume image-proxy registrations with private upstream URLs/headers. Browser-safe random/HMAC mappings and their lifetime/invalidation must remain service-owned; returning raw authenticated upstream URLs is not parity. [Image proxy](../../packages/image-proxy/src/index.ts), provider sources above.
- Connection ownership is uneven. Core `fetchWithTrustedCertificatesAsync` creates a dispatcher when none is provided, but has no general finally-close; base testing creates fetch and Axios agents without explicit disposal. SDK methods often construct clients/agents per operation. Plex releases and Overseerr detail calls explicitly close owned dispatchers; Beszel cancels body, releases reader and closes stream dispatcher in finally; TrueNAS static maps share open sockets across instances but lack public global teardown; ArchiveTeam's ws snapshot has its own timer and no shared certificate options/signal path. These are **source-level lifecycle risks**, not measured leaks. Target runtime must own pools/close hooks and handle credential/trust changes without closing another caller's resource. [Core fetch](../../packages/core/src/infrastructure/http/request.ts), [base test](../../packages/integrations/src/base/integration.ts), [Plex](../../packages/integrations/src/plex/plex-integration.ts), [Overseerr](../../packages/integrations/src/overseerr/overseerr-integration.ts), [TrueNAS](../../packages/integrations/src/truenas/truenas-client.ts), [Beszel](../../packages/integrations/src/beszel/beszel-integration.ts#L431), [ArchiveTeam](../../packages/integrations/src/archive-team-warrior/archive-team-warrior-integration.ts#L59).

Public read results separately normalize errors. Do not leak raw SDK cookies/request bodies/credential URLs through an oRPC error cause; do not assume every rich test diagnostic is already safe just because logging is sanitized. [Decorator](../../packages/integrations/src/base/errors/decorator.ts), [public errors](../../packages/request-handler/src), [rich mapper](../../packages/api/src/router/integration/map-test-connection-error.ts).

Integration refresh is request-driven; Stats refresh is not an integration cron fleet. Cron package's integrations dependency is not evidence of a current provider consumer. [Job registry](../../packages/cron-jobs/src/index.ts), [jobs](../../packages/cron-jobs/src/jobs), [Stats service](../../packages/request-handler/src/stats.ts).

## 6. Proposed framework-neutral ports and contract-first batches

These are proposed interfaces, **not code/API approval**. Prefer existing domain interfaces under `packages/integrations/src/interfaces` and provider types; do not introduce `any`-based generic RPC bodies or rename metrics. Keep infrastructure implementations server-only.

### Shared client/credential/result contracts

1. **Catalog/capability manifest:** stable `IntegrationKind` keyed definition plus explicit operation capabilities/credential modes. Distinguish `download.read` from provider no-op controls, generic HTTP eligibility from supported auth alternatives, and Stats metric availability from widget selection. Reuse definition metadata and current factory types, then reconcile discrepancies before declaring capability flags authoritative. Browser catalog contains required field names/public flags only, no secret values or transport objects.
2. **Authorized connection snapshot:** immutable `{id,kind,name,internalUrl,externalUrl,configurationRevision}` plus server-owned secret accessor `has(kind)`/`read(kind)` and keyed fingerprint. Repository/policy resolves one/many allowed kinds and action **before** decrypting. Credential update semantics retain null=keep, omitted=remove and optional alternatives; decrypt failures stay actionable but safe. URL and credentials must come from the same authorized snapshot. Provider clients never receive oRPC/Next/session context or fetch raw DB records.
3. **Operation context:** `{signal,deadlineAt,requestId,clock}` passed explicitly to read/action/stream operations. Abort before credential exchange and between pages; where an SDK cannot cancel, maintain pending-work ownership until settlement, suppress late cache writes, and report capability accurately. Mutation retries remain provider-specific and limited to recorded auth/session recovery, never blanket network retries after ambiguous success.
4. **Trusted outbound transport:** separate JSON/text/raw-response metadata request ports (unknown input payload parsed by the provider) and owned SDK bridges for Axios/Node-HTTPS/Undici/ws. Honor configured base paths, CA/hostname/proxy/DNS policy, auth injection/redaction, method/body/redirect limits and cancellation. Different transports need adapters, not an arbitrary API rewrite. Lease-owned `release`/runtime `close` distinguishes shared pool ownership from per-operation client ownership.
5. **Credential-session store:** generic server-only get/set/clear retaining versioned encrypted envelope, configuration fingerprint and optional absolute expiry/remaining TTL. Persistence worker supplies backend atomicity/lifetime. Clients keep provider refresh/retry/logout semantics. Config/delete/trust change emits invalidation and evicts connection state, not only response cache. A migration can cold-login only under an explicit state-lifetime decision, not accidental TTL loss.
6. **History/image/connection ports:** typed append/read-window for Dashdot/OPNsense; private image registration returning opaque public handle for Plex/Gotify/Immich/Tracearr; identity+revision-keyed upstream connection manager with acquire/release/invalidate/drain. TrueNAS needs bounded/closed pooled sockets and revision-aware keys; Beszel stream ownership retains reader/body/agent cleanup and reconnect policy. Common scheduler selects timing; providers do not install their own fleet.
7. **Result contracts:** preserve native domain outputs/nullable fields/units/options and Date semantics. Read-cache envelope retains `{data,timestamp,expiresAt,staleUntil}`; Stats retains `{values,updatedAt,retryAt,error,stale}`. Test result is discriminated success/error category with authorized sanitized certificate details; arbitrary HTTP returns `{integration,ok,status,statusText,data}`; stream events use bounded async iterable with terminal error/abort semantics. Error normalization distinguishes auth, certificate, request/deadline, status, parse, unknown; no raw upstream credential-bearing cause in public results.

## 7. Acceptance gates, true blockers and human decisions

### F0 — fixture obligations for every provider row

- Factory resolution/kind preservation; all credential alternatives/optional fields and required secret failure; no secret in browser exports/logs/error causes/cache identities/serialized results. Test create→edit with masked values→switch mode→remove optional values→delete and session/cache/connection invalidation. No speculative unit tests were added; reuse relevant existing fixtures when future testing is explicitly authorized.
- Every table-listed native method/result and every Stats metric projection has sanitized golden fixture(s), empty/nullable/partial/invalid/application-error payloads, exact units/state/date/link mapping and option-boundary cases. Transport-free response harness is already available as [simulateResponseContractAsync](../../packages/integrations/src/base/response-contract.ts); it alone does not cover HTTP, SDK handshakes, TLS or ownership.
- Shared prefix URL/external URL fixture; native vs arbitrary auth distinction; trusted CA/hostname/proxy behavior through the correct transport; pre-abort/deadline/body cancellation, pagination abort, no duplicate unsettled calls, action no-retry after ambiguity, resource teardown. Variant providers get distinct fixture cases; success of inherited base is insufficient for a subclass override.
- Authorized native query/interact/full-access denial and public-board read boundary; config revision changes cannot serve old credentials' results; invalidation fences late responses/session connections. Cache snapshot/restart/expiry/history semantics use fake store contracts first, then physical acceptance with persistence worker.
- Existing specs are evidence of available assertions, **not execution**. Particularly relevant sources: [integration test directory](../../packages/integrations/test), per-provider `src/**/test` files, [HTTP auth coverage](../../packages/api/src/test/integration-http-auth-coverage.spec.ts), [integration request fixtures](../../packages/api/src/test/integration-request.spec.ts), [management specs](../../packages/api/src/router/test/integration). Do not run credential/live-network tests implicitly when invoking a broad suite; Beszel's existing spec reads environment-based live targets.

### L0 — future live acceptance, opt-in and per-provider

For **each non-Mock provider**, record deployed server/API version, chosen credential alternative, runtime/library versions and base-path/TLS/proxy topology; then perform exactly its table-listed bounded reads and connection check on authorized fixtures. No maintained live version matrix was found here; mark unknown versions explicitly. Capture sanitized request/response mapping evidence, not real keys or copied user media. Required permissions are the minimum for the existing operation; never grant broader credentials to bypass a failure.

Every mutating capability additionally requires a human-approved disposable target and explained effects, before executing controls, deletions, note edits, media requests, alert changes or smart-home actions. Restore reversible changes; for irreversible deletes, confirm disposable state and disk effects first. A timeout/error is not proof no write occurred; inspect state before any retry. Neither a Mock demonstration nor a successful native `testConnectionAsync` establishes full provider parity. For streaming/connection providers, prove repeated subscribe/unsubscribe, aborted client, auth expiry/reconnect, credential/trust changes and runtime shutdown. For image providers, fetch an issued opaque image URL while authorization secrets remain server-side. Persistence worker owns restart/shared-state tests; widget worker demonstrates actual rendered consumption after service proof.

### True blockers for final compatibility, not bulk reuse

1. **Target runtime and outbound lifecycle contract.** Current Node-only TLS/ws/HTTPS/Axios/forked SDK behavior is not edge-portable by changing imports. Choose/pin runtime and define who owns dispatcher/socket/agent close, trust refresh and operation cancellation. Native source reuse can proceed using fakes, but production compatibility cannot be asserted before row-level proof.
2. **State/crypto/identity continuity.** Existing encrypted credentials, delegated permissions, config fingerprints, session TTL/invalidation, sample histories, Stats snapshots and image mappings need explicit persistence/crypto ports. Removing Redis without reproducing those semantics is not “integration adapter done.” Physical decisions remain persistence/identity workers'.
3. **Cancellation gaps and config-aware pooled connections.** Most native handler paths do not forward signals; SDK cancellation cannot be assumed. TrueNAS pooling is keyed by ID rather than URL/credential revision (test evicts), has no public drain-all; unsuccessful update/test can alter cached state. Warrior's websocket bypasses the HTTP trust injection used by its HTML probe. These need specified lifecycle adaptation and acceptance, not measured leak/performance claims.
