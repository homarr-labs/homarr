# Homepage integration comparison and delivery report

Homepage source is pinned to [b8ed72a03fc401ba5a856ac76d40e5063d284d4d](https://github.com/gethomepage/homepage/tree/b8ed72a03fc401ba5a856ac76d40e5063d284d4d). This inventory covers **all 160 service-widget documentation pages**, excluding their index. Homepage information widgets, core Docker/Kubernetes decorations, and generic dashboard features are not counted as named service integrations.

Homarr coverage is checked against the providers and adapters in PR #6863 (`feat/new-integration-stats`). It adds 24 new provider kinds and scalar adapters for 55 existing real kinds plus Mock. **68 documented Homepage entries have some statistics coverage, 88 remain pending, and 4 are out of scope for a new named scalar provider.** These counts are entries in Homepage's service docs, not the number of Homarr providers; aliases, broader service scopes, and providers absent from that documentation prevent one-to-one totals.

## Legend and estimation limits

- ✅ Implemented statistics coverage. It does **not** mean full Homepage feature/field parity, nor a live acceptance test for every Homarr adapter.
- 🔵 Pending implementation; feasible unless a specific external constraint is stated.
- ❌ Not relevant to a new scalar provider (wrapper/video feed), with a reason. No service is declared technically impossible merely because it is unfinished.
- 🟢 Low: a small read-only summary API; 🟡 Medium: service authentication, pagination, multiple calls, or aggregation; 🟠 High: additional protocol/session/version work; 🔴 External: account/plan/credentials or live validation prerequisites.

Effort is an **initial engineering estimate** for adding a useful statistics subset, not reproducing Homepage's complete UI. Sources are pinned per entry. Pending services have not all been installed; schema/version/authentication details must be checked before implementation. Existing adapters deliberately expose their established Homarr fields. For example Beszel exposes a system count here, Nextcloud exposes retrieved notifications, and Synology system metrics do not imply Download Station support.
