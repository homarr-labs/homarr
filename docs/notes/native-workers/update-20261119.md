# Homarr 2.13.1 worker branch update — 19 November 2026

Updated `feat/worker-relay-prototype-20261021` from Homarr 2.5.2 to the latest default-branch commit checked on 19 November: `b440fdd574c9daa229f5cf64f7b2532770799664` (2.13.1). This brings in 313 upstream commits. Local recovery branch: `feat/worker-relay-before-update-20261119`, pointing to the previous head `6ba400ba6761b38e5ab899c7867e802a3c455495`.

The branch keeps the normal Homarr interface, one primary encrypted worker, native oRPC procedures, the standalone Bun/Hono worker and the classic deployment. Existing deployment instructions remain in [report.md](./report.md); this note records the upgrade and its validation.

## Compatibility changes

- Ported new upstream board, theme, per-user item state, integration, Workshop, Smart Home, Wazuh and Thingport behavior into the existing native API and frontend. API-key read-only restrictions cover all native procedure bases; an explicitly invalid key returns 401 instead of falling back to cookies.
- Kept historical worker migration SQL and timestamps. Appended and reconciled upstream migrations for SQLite and PostgreSQL, including existing classic databases where the migration journal would otherwise skip earlier worker migrations.
- Moved upstream board query snapshots/prefetch into backend-owned modules; browser and backend share pure widget query-input helpers. Worker publication contexts cannot read the server-side snapshot cache.
- Updated shared request handling, cancellation, DNS defaults, backup/media handling and OAuth consent scopes to the current upstream behavior. Added atomic hash compare-and-swap to both local state and Redis adapters for mock Smart Home state.
- New widget publication respects saved selections. Downloads retain category/completed filters; Wazuh retains visible views and thresholds; Smart Home catalogs, live updates, history and forecasts remain scoped to saved controls. Mutations remain denied to viewers. Thingport GLB/STL media retain their reviewed capability kind.
- Corrected management API/certificate pages that had regained direct backend imports during the merge. They now call existing backend endpoints. The imported native graph caused a reproducible frontend page-collection SIGSEGV; removing that dependency fixes it without changing build concurrency.
- Classic packaging now copies better-sqlite3 13's package-relative N-API prebuilds for Node migrations/CLI. The small worker continues to use Bun SQLite and excludes better-sqlite3, React, Next and Mantine from its emitted runtime graph.
- Updated Bun to 1.4.4 and the upstream development Node pin to 26.13.0. Production image stages retain upstream's Node 24.22.3 Debian runtime; the mini worker uses its separate Alpine Bun stage.

Upstream still pinned Next.js 16.4.2. The build detected known vulnerabilities, so this branch additionally pins **16.4.6**, the current same-minor patch release. The [official advisory](https://github.com/vercel/next.js/security/advisories/GHSA-pc58-hwjq-p385) lists 16.4.5 as patched; [16.4.6 release notes](https://github.com/vercel/next.js/releases/tag/v16.4.6) describe the subsequent fixes. The lockfile was regenerated with Bun 1.4.4.
