# Homarr v2 GitHub PR and issue audit

Audit date: 2026-09-03

Repository: [`homarr-labs/homarr`](https://github.com/homarr-labs/homarr)

Audited branch: [`release/v2`](https://github.com/homarr-labs/homarr/tree/release/v2) at [`ac62e5bfd6731651b75345b8bb6a07882fad8daa`](https://github.com/homarr-labs/homarr/commit/ac62e5bfd6731651b75345b8bb6a07882fad8daa)

## Executive findings

- The authoritative release roll-up is open PR [#6545, `feat!: release v2`](https://github.com/homarr-labs/homarr/pull/6545). It targets `feat/onboarding-rebuild` from `release/v2`; it is not a merged release record. Its current head is the audited branch SHA above.
- PR #6545 describes an eight-layer review stack: [#6356](https://github.com/homarr-labs/homarr/pull/6356), [#6503](https://github.com/homarr-labs/homarr/pull/6503), [#6502](https://github.com/homarr-labs/homarr/pull/6502), [#6450](https://github.com/homarr-labs/homarr/pull/6450), [#6482](https://github.com/homarr-labs/homarr/pull/6482), [#6555](https://github.com/homarr-labs/homarr/pull/6555), [#6569](https://github.com/homarr-labs/homarr/pull/6569), and the roll-up itself. All eight PRs remain open as of the audit.
- GitHub's pull-request API returns **95 PRs whose base is `release/v2`**: **84 merged, 9 closed without merge, and 2 open**. The complete ledger is in the appendix.
- The best public summary and media source is open beta issue [#6600](https://github.com/homarr-labs/homarr/issues/6600). Its feature list broadly matches the branch, but its “~30% less RAM (hopefully)” line is marketing shorthand. The underlying benchmark was workload-specific, and the open performance layer [#6555](https://github.com/homarr-labs/homarr/pull/6555) explicitly declines to claim a latency improvement.
- Two proposed article claims are not supported by the audited evidence: **“Custom Widgets use 80% less memory”** and **a new general automatic-user-provisioning feature**. The closest auth change is opt-in, verified-email OIDC linking in merged PR [#6445](https://github.com/homarr-labs/homarr/pull/6445), which is account linking rather than general provisioning.
- Closed-unmerged mega-PR [#6582](https://github.com/homarr-labs/homarr/pull/6582) is explicitly excluded by PR #6545. Only the audited subset merged through [#6609](https://github.com/homarr-labs/homarr/pull/6609) should be described as present.

## Method and evidence rules

This audit used only first-party GitHub PR, issue, commit, comparison, tree, and repository-content API records. I read the full authored descriptions of the roll-up, all seven lower stack layers, all 95 PRs directly targeting `release/v2`, the related feature-lineage PRs listed below, and the relevant v2 issues. Automated reviewer summaries were not treated as evidence when an authored description or branch file was available.

“Shipped on the audited branch” means the merge commit is contained in `release/v2` at the snapshot SHA, or the feature is directly observable in a file served by GitHub at that SHA. An open PR description establishes design intent, not a merge. The current heads of #6502, #6450, #6482, #6555, and #6569 each contain two commits not in the roll-up ancestry, so their descriptions must be paired with merged PR or snapshot evidence before making a categorical release claim.

## Sourced feature inventory

### 1. Homarr Assistant and MCP

- The provider-agnostic Assistant has three entry points—user menu, command menu and dashboard widget—and supports model/provider discovery, encrypted provider credentials, attachments, mentions, Markdown, sources, usage display and private conversation history. Mutating tools require explicit approval and permission checks. Sources: [#6482](https://github.com/homarr-labs/homarr/pull/6482), [#6636](https://github.com/homarr-labs/homarr/pull/6636).
- The community-funded Homarr provider is offered through Workshop with per-day quota accounting, GitHub-backed identity and a zero-data-retention provider policy; its PR says prompt and response content is not retained. Source: merged [#6563](https://github.com/homarr-labs/homarr/pull/6563) at [`2a2e336ad008`](https://github.com/homarr-labs/homarr/commit/2a2e336ad0088ef5c91648b62c9c884b32359461), 2026-08-12.
- Assistant tools can act on Homarr, review/apply CSS and author Custom Widgets. Merged [#6743](https://github.com/homarr-labs/homarr/pull/6743) made MCP context task-specific, completed the public MCP tool surface, added lazy component discovery and independent JSX validation, and persisted the exact validated preview revision. Its authored evaluation reports 85/86 cases and a reduction from 30 to 23 tool calls and 49,660 to 27,532 input characters; those are authoring-evaluation figures, not end-user latency or memory figures.
- The branch contains MCP migration/validation commits, but issue [#6543](https://github.com/homarr-labs/homarr/issues/6543), “Upgrade to MCP v2 (spec 2026-07-28),” remains open. Safe release wording is **“an MCP tool surface for agents”** rather than an unqualified claim of complete compliance with that future-dated spec.
- Demo mode can stream canned Assistant output without real provider credentials, and the demo dashboard includes an Assistant widget. Sources: merged [#6524](https://github.com/homarr-labs/homarr/pull/6524) and [#6529](https://github.com/homarr-labs/homarr/pull/6529).
- Storage and loading fixes in [#6530](https://github.com/homarr-labs/homarr/pull/6530) covered MySQL message content/order and loading Assistant code only when enabled. Its authored bundle comparison was login 3.81 MB → 2.40 MB and board 5.35 MB → 4.56 MB; these are route-bundle figures, not RAM measurements.

### 2. Custom Widgets v2 and Community Workshop

- Custom Widgets v2 is a full visual workbench with General, API sources, Requests, Options, JSX and Preview sections; desktop uses side-by-side code/preview and small screens use a Configure/Preview switch. It exposes validation diagnostics, a redacted request journal and S/M/L preview fixtures for live/loading/empty/error states. Sources: [#6356](https://github.com/homarr-labs/homarr/pull/6356), merged [#6390](https://github.com/homarr-labs/homarr/pull/6390), [snapshot authoring guide](https://github.com/homarr-labs/homarr/blob/ac62e5bfd6731651b75345b8bb6a07882fad8daa/apps/docs/docs/management/custom-widgets/authoring.mdx).
- A Custom Widget can use multiple fixed-origin API sources and encrypted credentials. Named requests support GET, POST, PUT and PATCH for queries or actions; DELETE is action-only. Actions run only through `ActionButton` or `ToggleSwitch`, never during board load, and can invalidate cached queries. Sources: [snapshot request/security guide](https://github.com/homarr-labs/homarr/blob/ac62e5bfd6731651b75345b8bb6a07882fad8daa/apps/docs/docs/management/custom-widgets/requests-and-security.mdx), merged [#6480](https://github.com/homarr-labs/homarr/pull/6480).
- Saved widget options can feed paths, query values and JSON request bodies. Supported controls include text, textarea, number, switch, select, multi-select, slider, date, time, color, icon, URL, duration, time zone and JSON; dynamic choices may come from a load query. Source: [snapshot authoring guide](https://github.com/homarr-labs/homarr/blob/ac62e5bfd6731651b75345b8bb6a07882fad8daa/apps/docs/docs/management/custom-widgets/authoring.mdx).
- Safety is concrete rather than aspirational: same-origin enforcement, network-scope and redirect validation, SSRF protection, board permissions, request/response/body/depth limits, timeouts, encrypted credential injection, action rate limits and confirmation requirements. Anonymous visitors may run queries for Custom Widgets on public boards, but mutations remain authenticated. Sources: [snapshot security guide](https://github.com/homarr-labs/homarr/blob/ac62e5bfd6731651b75345b8bb6a07882fad8daa/apps/docs/docs/management/custom-widgets/requests-and-security.mdx), merged [#6558](https://github.com/homarr-labs/homarr/pull/6558), closing [#6557](https://github.com/homarr-labs/homarr/issues/6557).
- AI-assisted creation uses one self-contained prompt and one fenced JSON result; credentials are entered separately. Later work added lean on-demand resource discovery, preview revision tracking and explicit action safety. Sources: merged [#6695](https://github.com/homarr-labs/homarr/pull/6695), [#6700](https://github.com/homarr-labs/homarr/pull/6700), [#6743](https://github.com/homarr-labs/homarr/pull/6743).
- The Community Workshop supports publishing, browsing, installing, updating, rating/reporting and sharing Custom Widgets and CSS from the same Homarr deployment. Sources: merged [#5984](https://github.com/homarr-labs/homarr/pull/5984), [#6542](https://github.com/homarr-labs/homarr/pull/6542), and beta issue [#6600](https://github.com/homarr-labs/homarr/issues/6600).
- Custom JSX v1 compatibility was absent from the initial #6390 implementation but restored by the review fixes: legacy widgets retain encrypted credentials, enter an explicit migration state and are atomically replaced after validation. Sources: merged [#6446](https://github.com/homarr-labs/homarr/pull/6446), [#6451](https://github.com/homarr-labs/homarr/pull/6451), [#6480](https://github.com/homarr-labs/homarr/pull/6480).
- **No audited PR, issue, benchmark or snapshot guide supports “Custom Widgets use 80% less memory.”** Do not publish that number. The only release memory study is dashboard-wide #6537, discussed below.

### 3. Drag-and-drop, containers, sidebars and responsive layouts

- The board grid moves to dnd-kit with transactional placement, collision handling, drag overlays, eight-direction resize, keyboard/touch cancellation and rollback. Merged follow-ups repair target selection, portals, containment and handle layering. Sources: [#6503](https://github.com/homarr-labs/homarr/pull/6503), merged [#6597](https://github.com/homarr-labs/homarr/pull/6597), [#6607](https://github.com/homarr-labs/homarr/pull/6607), [#6717](https://github.com/homarr-labs/homarr/pull/6717).
- Category/dynamic sections are unified into containers supporting labels, collapse, nesting, resizing, rails/sidebars and cross-container moves. Scrollable containers were added in merged [#6629](https://github.com/homarr-labs/homarr/pull/6629); clipping/overflow/header-space defects were subsequently fixed in [#6714](https://github.com/homarr-labs/homarr/pull/6714), [#6727](https://github.com/homarr-labs/homarr/pull/6727) and [#6750](https://github.com/homarr-labs/homarr/pull/6750).
- Responsive layouts are presentation variants of one board: protected Base and Mobile layouts plus removable custom layouts, with independent item positions/sizes and Reset from Base. The selected layout is preserved across viewport changes rather than silently replaced. Sources: [#6450](https://github.com/homarr-labs/homarr/pull/6450), merged [#6734](https://github.com/homarr-labs/homarr/pull/6734). Mobile has no sidebars by design after [#6565](https://github.com/homarr-labs/homarr/pull/6565).
- Multi-select is real and broader than a visual card refactor: hold Ctrl on Windows/Linux or Command on macOS while selecting board items, then move the complete selection to a canvas, rail or container, delete with undo, or clear selection. A move is offered only if every selected item fits. Source: merged [#6642](https://github.com/homarr-labs/homarr/pull/6642) and its [documentation commit](https://github.com/homarr-labs/homarr/commit/f3014fe2712ed11d35d5398bd2fe6727133e20c4).
- Mobile receives a compact saved header layout, mobile-safe menus and corrected widget interactions. Only the account action remains mandatory in the compact layout. Sources: merged [#6715](https://github.com/homarr-labs/homarr/pull/6715), [#6730](https://github.com/homarr-labs/homarr/pull/6730).
- The board switcher is a searchable, responsive, keyboard-navigable preview grid reached from the profile action or `Shift+C`; it excludes the current board. Sources: merged [#6660](https://github.com/homarr-labs/homarr/pull/6660), [#6670](https://github.com/homarr-labs/homarr/pull/6670). Persisted board reordering is **not** established—related issue [#6643](https://github.com/homarr-labs/homarr/issues/6643) remains open.

### 4. Widgets and dashboard interaction

- Widgets gain responsive dense layouts and an advanced focus mode accessible by Shift-hover, keyboard trigger or context menu, with focus restoration. The production compact defaults were deliberately restored in merged [#6710](https://github.com/homarr-labs/homarr/pull/6710), while advanced views and richer data paths remain available. Sources: [#6502](https://github.com/homarr-labs/homarr/pull/6502), [#6710](https://github.com/homarr-labs/homarr/pull/6710).
- The widget settings dialog is a large unified workspace with a live preview, grouped options and in-place app/integration editing. Sources: merged [#6667](https://github.com/homarr-labs/homarr/pull/6667), [#6630](https://github.com/homarr-labs/homarr/pull/6630).
- Bookmarks support direct URLs, favicon fallback, a searchable picker and layout variants. Compact grid cards use a fixed 56 px size with an optional “Expand cards to fill row” choice. Sources: merged [#6666](https://github.com/homarr-labs/homarr/pull/6666), [#6747](https://github.com/homarr-labs/homarr/pull/6747).
- Utility-widget work redesigned Weather and Clock and added Air Quality, Countdown and Timer. The initially added Today widget was later removed by #6642, so it must not be listed as shipped. Sources: merged [#6638](https://github.com/homarr-labs/homarr/pull/6638), [#6642](https://github.com/homarr-labs/homarr/pull/6642).
- Media, calendar, Beszel, Docker and System Resources received targeted layout and readability fixes across [#6627](https://github.com/homarr-labs/homarr/pull/6627), [#6605](https://github.com/homarr-labs/homarr/pull/6605), [#6652](https://github.com/homarr-labs/homarr/pull/6652), [#6647](https://github.com/homarr-labs/homarr/pull/6647), [#6646](https://github.com/homarr-labs/homarr/pull/6646), [#6713](https://github.com/homarr-labs/homarr/pull/6713) and [#6756](https://github.com/homarr-labs/homarr/pull/6756).
- Contextual tips explain multi-select, advanced focus, right-click actions, keyboard/touch use, containers, move/resize controls and widget capabilities. Source: merged [#6648](https://github.com/homarr-labs/homarr/pull/6648).

### 5. Onboarding, Docker discovery and authentication

- Onboarding is rebuilt as a responsive, keyboard-accessible setup studio that discovers services, lets the user review selections and transactionally creates the first board. It connects app/integration/search setup and surfaces Assistant, Workshop and MCP. Source: [#6569](https://github.com/homarr-labs/homarr/pull/6569).
- Docker discovery scans reachable Docker-compatible hosts, prioritizes label-described services over image matching and still suggests unlabeled containers from images and published ports. It can create apps, encrypted-credential integrations, grouped board containers and compatible widgets. Sources: [snapshot Docker-label guide](https://github.com/homarr-labs/homarr/blob/ac62e5bfd6731651b75345b8bb6a07882fad8daa/apps/docs/docs/integrations/docker-labels/index.mdx), merged discovery foundation [#5607](https://github.com/homarr-labs/homarr/pull/5607), release commit [`d28dd380e5b6`](https://github.com/homarr-labs/homarr/commit/d28dd380e5b6e46c1c3aee959f651aec4b1c76d7).
- Native labels require `homarr.name` and `homarr.href`; optional labels cover group, icon, description, ping URL, stable ID, target board, integration kind, widget kind and hiding. When `homarr.name` is absent, Homarr also accepts Homepage's `homepage.name`, `homepage.href`, `homepage.group`, `homepage.icon` and `homepage.description`. Source: [snapshot Docker-label guide](https://github.com/homarr-labs/homarr/blob/ac62e5bfd6731651b75345b8bb6a07882fad8daa/apps/docs/docs/integrations/docker-labels/index.mdx).
- Docker tooling supports endpoint filtering, direct socket/host endpoints, multi-endpoint environment configuration, selected-endpoint queries, URL-prefilled setup, endpoint health, actions/logs and partial-error reporting. Source: merged [#6625](https://github.com/homarr-labs/homarr/pull/6625). The broader universal-create/Docker proposal #6582 was not merged; only the audited subset in [#6609](https://github.com/homarr-labs/homarr/pull/6609) is safe to claim.
- Auth pages were unified directly on the branch in commit [`409e8ed71ab0`](https://github.com/homarr-labs/homarr/commit/409e8ed71ab041e96aa8a54eb73f53732ed96fed); [#6687](https://github.com/homarr-labs/homarr/pull/6687) polished the login backdrop and native wordmark.
- Merged [#6445](https://github.com/homarr-labs/homarr/pull/6445) adds an explicit `AUTH_OIDC_ENABLE_DANGEROUS_CREDENTIALS_LINKING` opt-in. A strictly verified OIDC email can link to an existing credentials user while preserving password login, groups, permissions, boards, settings and API keys. This fixes duplicate-account creation for that case; it is **not evidence for a new general automatic-user-provisioning feature**.
- The v2 beta issue warns testers to back up and use a new Docker volume before trying the beta. Source: [#6600](https://github.com/homarr-labs/homarr/issues/6600).

### 6. Header, branding, global CSS and navigation

- Users can compose left/center/right header content, add board shortcuts, choose a compact search affordance and recover from a hidden header. Instance branding covers app name, logo, favicon, primary/secondary colors, whether the primary color is locked, default corner radius, authentication greeting/background/overlay and auth-page visibility. Sources: merged [#6690](https://github.com/homarr-labs/homarr/pull/6690), [snapshot branding form](https://github.com/homarr-labs/homarr/blob/ac62e5bfd6731651b75345b8bb6a07882fad8daa/apps/nextjs/src/app/%5Blocale%5D/manage/settings/_components/branding-settings-form.tsx).
- Global server CSS is edited in branding settings, reuses the board/Workshop CSS editor and is server-rendered. Board CSS wins later in the cascade. Source: merged [#6753](https://github.com/homarr-labs/homarr/pull/6753).
- The command menu is a unified local-first catalog for apps, commands, preferences, Assistant, web, media and people, with shortcuts, board switching, permission/capability fallbacks and centralized throttling for remote providers. Source: merged [#6692](https://github.com/homarr-labs/homarr/pull/6692).
- Routine destructive confirmations were shortened to same-control two-click confirmation with Escape/blur/outside-click/four-second reset, while complex or high-risk operations retain dialogs. Board/group/invite creation, duplication, preview dimensions, DNS timing, access assignment, API secrets, certificate upload, rename, Workshop report and weather search were streamlined inline. Source: merged [#6688](https://github.com/homarr-labs/homarr/pull/6688).
- The permission matrix calculates access scope separately from create capabilities and filters application, integration and home-stat data server-side. Source: merged [#6612](https://github.com/homarr-labs/homarr/pull/6612). Issue [#6608](https://github.com/homarr-labs/homarr/issues/6608) remains open despite being referenced by that work, so do not say every permissions defect is closed.
- The brief opt-in header auto-hide feature from [#6738](https://github.com/homarr-labs/homarr/pull/6738) was reverted by merged [#6740](https://github.com/homarr-labs/homarr/pull/6740). It is not a v2 feature.

### 7. Performance, caching and release behavior

- Merged response-caching work centralizes integration metadata, lazy widget modules and browser TanStack caching, then adds a bounded server L1 plus optional Redis L2, canonical request hashing, stale-on-error behavior, integration invalidation, in-process deduplication and renewable distributed locks. Source: merged [#6691](https://github.com/homarr-labs/homarr/pull/6691).
- Eligible public widget query data is restored from a session-scoped cache after reload while background refresh runs. Source: merged [#6669](https://github.com/homarr-labs/homarr/pull/6669).
- Open experiment [#6537](https://github.com/homarr-labs/homarr/pull/6537) used a restored real backup with four boards, 51 widgets and 11 integrations. Its authored table reports: anonymous peak 376.6→279.3 MiB (−26%), boot idle 130.5→62.4 MiB (−52%), after sign-in 247.4→142.9 MiB (−42%), dashboard loaded 293.4→170.4 MiB (−42%), four tabs 366.5→258.2 MiB (−30%), after soak 323.7→200.8 MiB (−38%), and peak Node RSS 430.7→336.2 MiB (−22%). It also reports CPU +18% and says a measured board-load slowdown was unreliable/not established.
- [#6555](https://github.com/homarr-labs/homarr/pull/6555) deliberately retains only a safer measured subset. Therefore a defensible public line is **“around 30% lower memory in a specific four-tab benchmark, with larger and smaller changes in other phases”**, not “30% less Chrome RAM” as a universal guarantee. Do not claim faster page latency from this PR.
- Release-preparation PR [#6746](https://github.com/homarr-labs/homarr/pull/6746) says merging `release/v2` into `dev` does not publish production. A deliberate `dev`→`main` merge starts Semantic Release; main/beta can be rebuilt from the latest release tag. The audit does not establish that v2 was production-released.

## Uncertainties and blockers

1. The release stack and roll-up remain open. This audit establishes the contents of `release/v2` at one SHA, not that v2 has been merged to `main`, tagged, published or deployed to production.
2. Five lower stack PR heads have two commits beyond their merge bases with the roll-up. Their live descriptions are useful design summaries but are not exact snapshots of `release/v2`.
3. GitHub associates PRs imperfectly. The 95-row appendix is exhaustive for `base=release/v2`; the related-lineage table covers feature PRs explicitly linked, inherited through the stack, or required to substantiate a user-visible claim. It is not a claim that every historical `dev` ancestor was v2-exclusive.
4. PR #6637's review composites show what reviewers inspected. Only its two authored fixes—preserving the active responsive layout during Reset from Base and preserving scroll position between Media Missing tabs—are direct shipment claims from that PR.
5. Preview URLs and user-attachment URLs are live external artifacts and can disappear. Copy selected release images into the documentation repository before publication if long-term stability is required.
6. The public beta's “~30% less RAM (hopefully)” is not a universal guarantee. Use the measured scenario and range, and avoid a latency claim.
7. No authoritative audited source supports “80% less Custom Widget memory” or general automatic user provisioning. Those require new evidence or must be omitted.
