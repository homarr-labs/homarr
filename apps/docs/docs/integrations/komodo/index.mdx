The Komodo integration gives Homarr a read-only overview of the servers, stacks, and deployments visible to a Komodo API key. Homarr never starts, stops, deploys, or modifies Komodo resources.

### Adding the integration

<AddingIntegration />

:::info URL configuration
Use the root URL of your Komodo Core instance, for example `https://komodo.example.com`. Do not add `/read` or another API path. Homarr appends the required RPC paths automatically.
:::

### Secrets

Komodo authenticates API clients with a key and secret sent in request headers. Both values are stored as encrypted, non-public Homarr secrets and are never added to request URLs.

The API key uses the permissions of its Komodo user. It must be able to read the servers, stacks, and deployments that you want to display.

### API requests

Homarr makes only the following authenticated `POST` requests:

- `/read/GetVersion` when testing the connection
- `/read/ListServers`
- `/read/ListStacks`
- `/read/ListDeployments`

Resource list requests use `limit: 0` so the overview includes every resource visible to the API key. Successful responses are cached for one second. During a temporary Komodo error, Homarr can continue serving the most recent successful response for up to five minutes. The widgets request data at their configured refresh interval.
