After Homarr starts, open its URL. An unfinished installation redirects to the onboarding screen at `/init`. Choose
**Get started** for a new installation or **Restore backup** to import a compatible SQLite backup.

<Callout type="info" title="Persist /appdata before you continue">
  Onboarding writes the administrator and board configuration to the database. If onboarding returns after a restart,
  check that `/appdata` is writable and persisted. See the
  [Docker installation guide](/docs/getting-started/installation/docker).
</Callout>

## Complete onboarding

Onboarding is split into six short sections. Integrations, Workshop, Assistant, and MCP are optional; skip them when you
only need a working board.

<Cards>
  <Card icon={<IconAdjustments />} title="1. Essentials">
    Choose the language, theme, usual server address, and anonymous analytics preference.
  </Card>
  <Card icon={<IconSearch />} title="2. Discover">
    Review the database, Docker, Kubernetes, Assistant, and Workshop capabilities Homarr can reach.
  </Card>
  <Card icon={<IconPlugConnected />} title="3. Connect">
    Import detected services or add integrations manually. Unfinished integrations can be skipped.
  </Card>
  <Card icon={<IconLayoutDashboard />} title="4. Board">
    Set the board name, colors, corner radius, column count, and optional sidebars.
  </Card>
  <Card icon={<IconSparkles />} title="5. Extend">
    Optionally connect the Workshop, configure an Assistant provider, or review the MCP endpoint.
  </Card>
  <Card icon={<IconChecklist />} title="6. Review">
    Check the final summary, then build the board. Homarr opens the exact board it configured.
  </Card>
</Cards>

The final screen links directly to the new board and the management area. Board layout, integrations, apps, and
appearance can all be changed later.

## Core concepts

### Boards

A **board** is a dashboard page containing apps, widgets, and Containers. Boards can be public or restricted to users
and groups. Each user can choose a home board.

![Board management with board previews](./img/after-installation-boards.png)

See [Boards](/docs/management/boards) for responsive layouts, access control, appearance, and home-board settings.

### Apps

An **app** is a saved shortcut: a name, URL, icon, and optional status check. Add an App tile or a Bookmarks widget to
show apps on a board.

![App management with saved shortcuts](./img/after-installation-apps.png)

See [Apps](/docs/management/apps) or [Icons](/docs/advanced/icons).

### Integrations

An **integration** is a server-side connection from Homarr to a supported service such as Sonarr, Home Assistant, or
Docker. Integrations provide data and actions to widgets. They can also be linked to apps.

![Integration catalog with compatible widgets](./img/after-installation-integrations.png)

See [Managing integrations](/docs/management/integrations) and the
[integration catalog](/docs/integrations).

### Widgets

A **widget** is a board tile. Some widgets work on their own; others require one or more integrations. Configuration,
supported integrations, and non-obvious limitations are documented on each widget page.

![Board in edit mode with the add-content menu](./img/after-installation-widgets.png)

See the [widget catalog](/docs/widgets).

### Containers and rails

A **Container** groups board items and can be nested. A **rail** reserves a fixed area at the left or right of a
responsive layout. Both are configured in board edit mode.

![Board layout settings with fixed sidebars](./img/after-installation-containers-rails.png)

See [Boards](/docs/management/boards#containers-and-rails).

### Users, groups, and permissions

Users inherit permissions and default boards from their groups. Resource-specific access can further restrict boards
and integrations.

![Group permission settings](./img/after-installation-users-permissions.png)

See [Users and groups](/docs/management/users) and [single sign-on](/docs/advanced/single-sign-on).
