## Combine integrations

Add each service under **Management → Integrations** using its URL and credentials; the linked guides below cover service-specific tokens and API ports. Add a **Statistics** widget, select those integrations, then add the fields you want to display. You can combine, for example, Sonarr shows, Paperless-ngx documents and Navidrome songs in one widget. Several fields from one integration reuse one snapshot; separate instances of the same service remain separate sources.

Choose cards, compact rows or grouped tables. Saved settings control labels, ordering, visibility and abbreviated values. The demo board includes all three layouts with deterministic Mock data, so it needs no service credentials.

Click a metric to toggle its full value and related fields from the same integration. Advanced view, available from the widget context menu, lists every available field from the selected integrations in collapsible integration groups, including fields not placed on the compact grid. Table mode uses the same groups for your selected metrics. Both views reuse the same source snapshots.

The hover toolbar's view controls change layout, number formatting, visibility, and order locally. They do not update the shared board and reset on page reload. Persistent metric selection and ordering belong in the widget settings.

## Refresh and saved values

Statistics are snapshots, fresh for one hour. Opening the dashboard reads the shared cache first. Only sources without a saved snapshot load automatically while the dashboard is visible; saved snapshots refresh on demand, with at most four source refreshes running across the deployment. Multiple fields from the same source share a retrieval. A source may make several requests internally. Legacy clients may finish their network request after the refresh deadline; timed-out callers release their refresh slot, and repeat calls to that source are suppressed in the same process until the original request settles.

**Right-click → Refresh** and the toolbar's **Refresh statistics** both bypass the freshness window. The context menu shows the age of the oldest successful snapshot displayed by this widget, not the time Homarr last read the cache. A failed refresh keeps that original age. There are no stale-data badges on the metrics. Existing values stay visible during refresh. Failed refreshes retain the last successful values and their original timestamps; automatic retries for sources without a saved snapshot wait at least a minute. Hour-old traffic, player counts, CPU readings, and playback sessions are snapshots rather than live monitoring.

The latest successful snapshot has no time-based expiry. Redis eviction, cache loss, and integration changes can remove it. This is a cache, not a historical archive. Redis must be available for refresh coordination. Dedicated widgets retain their existing refresh behavior.

## Access and availability

Every cached read and refresh checks the integration's query permission. Credentials stay in the integration configuration on the server. Updating its URL or credentials invalidates old snapshots. Removing an integration from this widget makes its entries unavailable until removed or reassigned.

Only fields supported by the provider appear in the metric picker. Missing optional values display a dash; malformed upstream responses fail the source refresh rather than silently becoming zero. Read-only RPC/GraphQL calls are supported alongside GET APIs. The widget does not execute service controls or arbitrary URLs.
