The Assistant widget puts the app-wide assistant on a board. It uses the same active conversation as the user-menu and
command-menu surfaces, so messages and approvals stay synchronized.

An administrator must first configure and enable Assistant in **Management → Assistant**. Signed-out users are prompted
to sign in, while an incomplete or disabled configuration shows an unavailable state.

### Adding the widget

<AddingWidget />

The default size is ten columns by four rows and shrinks to fit narrower boards. Short layouts show an **Open
assistant** action instead of compressing the conversation controls; increase the widget height to keep the complete
conversation inline.

Responses continue when the widget leaves the viewport. Drafts and attachments remain local to each visible Assistant
surface, and private conversation data is never stored in board settings. Normal Homarr permissions and approval rules
still apply to every action.
