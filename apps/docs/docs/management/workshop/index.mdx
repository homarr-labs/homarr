# Use Workshop

[Open Workshop](/workshop) to browse, inspect, vote on, report, download, and publish Custom JSX v2 widgets.

Submissions publish immediately. Authors can edit or delete their own submissions, while Workshop administrators can
review reports and delete any submission. Deleting a Workshop submission never removes widgets already installed in a
self-hosted Homarr instance.

Workshop validates widget JSON in the browser before publishing. Homarr validates it again before installation. Widget
exports must not contain credentials; users configure required credentials only after importing a widget.

Votes and reports are unique per user and submission. Listings expose vote totals without exposing voter identities.
Reports include a category and explanation. Administrators can see the reporter, dismiss the report, or delete the
reported submission.

Workshop deliberately has no comments, email notifications, approval queue, moderator roles, user bans, or audit-history
system.

## Access control

Workshop uses PocketBase collection API rules for access control:

- Anyone can browse submissions and vote totals.
- Signed-in users can publish, vote, and report.
- An author can update or delete only their own submission.
- Workshop administrators can read and dismiss reports and delete any submission.

The frontend uses PocketBase's normal record create, update, and delete APIs. There are no custom deletion endpoints or
deletion hooks. PocketBase superusers bypass collection API rules, as documented in
[API rules and filters](https://pocketbase.io/docs/api-rules-and-filters/).

Set `users.isAdmin` from the PocketBase dashboard to grant Workshop administration access. The users collection update
rule prevents ordinary users from granting this flag to themselves.

## Configure GitHub sign-in

The central Workshop PocketBase service controls authentication. Register this callback in the GitHub OAuth application:

```text
https://<workshop-host>/api/oauth2-redirect
```

Self-hosted Homarr origins, including localhost and custom domains, do not need separate GitHub callbacks. The Workshop
host completes authentication in a popup and returns the result to the calling Homarr page.

PocketBase permits all origins by default. If the deployment uses `--origins` or a restrictive reverse-proxy CORS policy,
it must permit self-hosted Homarr origins. See [PocketBase routing and CORS](https://pocketbase.io/docs/go-routing/).

Homarr shows a visible error when the provider is misconfigured or the popup is blocked, cancelled, or times out.
