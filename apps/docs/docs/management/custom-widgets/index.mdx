# Custom Widgets

Custom JSX v2 is the only Custom Widget format in Homarr. A definition contains metadata, API sources, named requests, widget options, and JSX.

Homarr encrypts source credentials separately. Homarr does not include credentials in an export.

Homarr does not support old display types, reusable connections, widget packs, or compatibility modes.

## Audience and prerequisites

This documentation is for Homarr administrators and Custom Widget authors. You must understand HTTP, JSON, API authentication, and self-hosted network routing.

For a private API source, you must understand DNS, TLS, reverse proxies, and container networking.

To write a template manually, you must understand JSX and Mantine. An AI-generated definition requires the same security and capability review.

## Understand the definition

```ts
interface HomarrCustomWidgetV2 {
  $schema: "homarr-custom-widget-v2";
  name: string;
  description?: string;
  iconUrl?: string;
  sources: CustomWidgetSource[];
  requests: CustomWidgetRequest[];
  optionsSchema: CustomWidgetOptionsSchema;
  defaultOptions: Record<string, unknown>;
  template: string;
}
```

Exports, imports, the UI, MCP, and Workshop validate this schema. Homarr rejects files that use an old format.

If a definition is missing, its tile shows **Custom widget unavailable**. The other board items continue to operate.

The browser renders the safe JSX template. The Homarr server executes named requests and injects encrypted credentials.

The browser does not receive API source credentials.

## Create and configure a Custom Widget

Open **Management → Custom Widgets → Add custom widget**. The workbench contains sections for information, sources, requests, widget options, JSX, and preview.

Use the fixed navigation to go to a section.

Select a definition from the searchable board widget picker. The picker immediately shows the widget options.

Invalid widget options prevent board insertion. If an update invalidates existing options, the item opens the configuration repair form.

## Import, export, and publish

An export contains one canonical JSON document without credentials. An import validates the document before Homarr creates the definition.

The import review shows origins, authentication modes, network scopes, methods, actions, and required board permissions. File, clipboard, and Workshop imports use this review.

The review gives credential fields for each authenticated source. Homarr encrypts entered values and excludes them from the imported document.

A definition shows **Credentials missing** when a source needs credentials. You can import a definition without credentials.

The indicator disappears after you configure all required source credentials.

The [Workshop](/docs/management/workshop) publishes valid widgets immediately. Users can vote on a submission or report it.

Workshop administrators can inspect reported posts and delete any submission. This deletion does not remove installed copies.

## Examine bundled examples

Homarr adds four disabled examples during database setup. These examples use the same schema as user definitions.

Homarr does not overwrite an example after a user changes it. Select an example to examine its manifest and JSX.
