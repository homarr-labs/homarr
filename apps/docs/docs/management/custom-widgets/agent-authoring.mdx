# Agents and skills.sh

An external agent creates widgets one at a time through Homarr's MCP server. The harness owns any multi-widget task list; Homarr does not create packs or multi-widget drafts.

<a className="button button--primary" href="https://www.skills.sh/homarr-labs/homarr/homarr-custom-widget">
  View the Custom Widget Skill on skills.sh
</a>

Install the Agent Skill directly from the verified Homarr repository:

```sh
npx skills add https://github.com/homarr-labs/homarr --skill homarr-custom-widget
```

The portable skill is a tool-agnostic authoring reference. Connected workflow and tool instructions come from Homarr's native MCP prompt instead, so the same complete skill can also be embedded safely in the UI's offline copy/paste prompt.

The source lives at [`.agents/skills/homarr-custom-widget`](https://github.com/homarr-labs/homarr/tree/dev/.agents/skills/homarr-custom-widget). There is no ZIP archive. After the skill exists on the repository's default branch, run the command once to register installation activity, verify the skills.sh page, and request official maker attribution for `homarr-labs` through skills.sh. Repository code cannot grant that attribution itself.

## MCP discovery

- Prompt: `homarr-custom-widget-author`
- Resources: `homarr://custom-widgets/schema`, `components`, `components/{name}`, `examples/{name}`, and `skill`
- HTTP: `GET /api/custom-widgets/authoring-prompt` and `GET /api/custom-widgets/skill`

The authoring-prompt tool description intentionally contains only one sentence. Workflow instructions live in the prompt and link to resources.

`GET /api/custom-widgets/skill`, the MCP tool, and the MCP resource return the live `SKILL.md` with:

```ts
{
  name: "homarr-custom-widget";
  version: string;
  skillMd: string;
  skillsShUrl: string;
  sourceUrl: string;
  installCommand: string;
}
```

They do not return an archive URL or hash.

## Agent loop

1. Fetch the prompt, live schema, and component catalog.
2. Read the external API documentation.
3. Build and validate one definition without saving.
4. Create a preview session and test its queries/actions.
5. Open the returned preview URL with browser tools.
6. Set a supplied credential with the dedicated secret-write permission, or ask the user through the ten-minute Homarr credential URL.
7. Inspect the redacted journal and patch until valid.
8. Create the widget, then repeat for the next requested widget.

Credential URLs are scoped to one definition/preview, source, and required fields. The agent receives only pending/completed status. Plaintext is encrypted immediately and never returned.
