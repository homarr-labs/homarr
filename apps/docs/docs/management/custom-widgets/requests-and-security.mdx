# Configure requests and security

Each Custom Widget has one or more API sources. Most definitions use one `default` source.

Add another API source when the widget must combine APIs. For example, a calendar can combine Sonarr and Radarr.

An API source supports these authentication modes:

- No authentication
- Bearer token
- Basic authentication
- API-key header
- API-key query parameter

Homarr encrypts credentials for each definition, API source, and credential type. A duplicate or export does not contain credentials.

## Configure named requests

Named requests support GET, POST, PUT, PATCH, and DELETE. The `kind` value controls runtime behavior.

The HTTP method does not determine whether a named request is a query or action.

- A load query runs automatically.
- A manual query runs with `SubFetch`.
- A query can include a body.
- An action runs after a user action.
- An action can require confirmation.
- An action can invalidate named queries.

A successful action removes each declared query from the browser cache and server cache. Homarr then runs the query again.

Path parameters use `{name}`. Structured query and body templates use `{ "$param": "name" }`.

Give each declared parameter an explicit value source. For a load query, use `optionsBinding` with an option reference or a primitive value.

For a manual query or action, send all parameters with the component `params` prop. Homarr does not bind matching names automatically.

## Understand request protection

All named requests use the Homarr server executor. The executor applies these security controls:

- Source origin
- Network scope
- DNS validation
- Redirect validation
- SSRF protection
- Board permissions
- Rate limits
- Request limits
- Parameter limits
- Body limits
- Timeouts
- Response size limits
- Encrypted credential injection

Static headers cannot replace authentication, routing, proxy, cookie, or hop-by-hop headers. Homarr rejects static values that look like credentials.

The `public` network scope permits public destinations. The `private` network scope also permits private LAN destinations.

The `loopback` network scope also permits loopback destinations. The SSRF policy blocks sensitive infrastructure ranges for all network scopes.

Each named request requires view, modify, or full board access. The server checks this permission before it contacts the API source.

A DELETE request always requires full access and confirmation. Homarr does not cache actions, retry actions, or run actions on load.
