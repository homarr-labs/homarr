## Method and caveats

- **Runtime:** Node 24.22.1, development React/jsdom, actual DOM reconciliation, Mantine and QueryClient. Each widget receives 2,000 rows (225,511 serialized bytes), 40 Text nodes, 8 icons and four helper kinds. Stable-board runs mount, warm up five times, then retain 10 updates; other scenarios retain their original iteration counts. Translation, transport, notifications and modals are stubbed. No layout/paint, production compilation or full-app claim. Order: baseline-1 → candidate-1 → baseline-2 → candidate-2 → baseline-counts → candidate-counts. Measurement window: 22:00:24–22:00:49 UTC.
- **Runtime limits:** single-widget publication and query-update timings are modest/noisy; filter/sort/map differs by only about 2%. Do not promote precise speedups there. The 50-SubFetch query fixture still renders SubFetch 510 → 510; its timing includes a fixed 5 ms settle. `evaluationContexts` insertion points match neither revision, so missing counters do not establish zero work for it. Array.from at 2,000 entries is slower by about 0.01–0.02 ms; tiny sanitization is slower by less than a microsecond. The 100,000-input Array.from case measures capped allocation/output, not unrestricted throughput. Original microbenchmark output parity is not asserted. Heap samples are retained without a memory-savings claim.
- **Router:** actual lazy appRouter, migrated in-memory SQLite, encryption/decryption, loopback HTTP/Undici with a 1 ms upstream delay. Each scenario has three warmups and 30 samples/run. Cold uses fresh definitions/items, warm uses cached replies; cold upstream requests remain 20 → 20 and warm 0 → 0. This is 20 queries in one invocation, not 20 widgets. Driver-result bytes are serialized SQLite results, not transfer/wire bytes or heap. Counts occur inside timings. Original status, permission-revocation and cross-user-denial checks passed; no exact returned-payload or Authorization-echo parity assertion exists.
- **Redaction:** approximately 933 kB, four synthetic secret inputs; sparse payload echoes apiKey once per 100 records. Thirty warmups, 120 samples/run, two calls averaged per sample. Original checks are not an exhaustive credential-representation security audit. Server order is baseline-1 → candidate-1 → baseline-2 → candidate-2 for router, then response, all before the prompt edit.
- **Workbench:** production React/esbuild fixture, agent-browser 0.39.2 and Headless Chromium 152.0.0.0; 1440 × 1000, scale 1, forced light theme and identical generated data. Order before1 → after1 → before2 → after2, 22:02:14–22:04:02 UTC. Five warmups + 20 retained samples; counts include all 25 edits. Timings wrap synchronous programmatic flushSync updates and exclude the following 20 ms wait, presentation and deferred work. The same 200-field response stays mounted while a separate sample draft changes to `{"test":i}`; not replacement/parsing of a new 200-field response each edit. Tree/row counts are component renders, not allocations or fresh tree construction. Initial response mounting remains one serialization, two tree renders and 402 row renders on both revisions.
- **Workbench limits:** completion samples are 300 batch averages after 50 warmups, 20 calls/batch; p95 is not individual-call latency. The single completion-label signature matches across all runs, not general completion correctness. Form results are counts only: 10 form renders/subscriptions remain 10, with one settled definition build/template analysis/preview update on both. Editor cold-load, cache creation and first reference opening are not timed; untimed mount counts vary and remain unnormalized.
- Apple M4 Max, macOS 27.2 arm64; dependency versions/hashes are retained. Instrumentation and local JIT/GC/host contention affect timings. No production INP, trusted keystroke-to-paint, Next.js page, PostgreSQL, Redis, WAN, TLS, end-to-end Homarr or isolated-optimization causal claim is established.

## Archive integrity and reproduction

`runtime/*.jsonl` retain all 32 records/run **byte-for-byte**, including every sample in the separate counts runs. `workbench/browser-*.json` retain every original field, sample, raw count object and completion signature. Server files select only original 20-query router results and redact-* results, with checks and exact per-sample operations intact. No numeric values are rounded or regenerated.

`provenance.json` records original report, summary, raw, harness and snapshot SHA-256s, exact field selections and packaged hashes. Absolute checkout/output/executable paths are replaced by the documented `<baseline>`, `<candidate>`, `<output>` and `<node-24.22.1>` tokens or omitted by explicit selection. Hostnames are omitted. No generated bundles, databases, logs, credentials or personal paths are archived; source hashes do not contain source contents.

The importer compares all 14 complete runtime snapshots, 16 complete pre/post server snapshots per checkout for router/response, and both complete scoped-source/bundle-input workbench maps before selecting compact source-hash files. Equal maps are stored once. Runtime retains emitted repository inputs, harness and root configuration; server retains Custom Widget, DB, custom-widget API-router, benchmark and root files plus full tracked-content digests; workbench retains scoped source and non-node_modules physical bundle inputs. Original full snapshot hashes remain in provenance. Dependency module maps are omitted for size, so the packaged subset alone cannot independently recreate the original full-map stability checks.

From the repository root:

```sh
node scripts/benchmarks/custom-widgets/summarize-consolidated.mjs
EVIDENCE_SOURCE=/absolute/path/to/original-consolidated node scripts/benchmarks/custom-widgets/summarize-consolidated.mjs
```

The first command verifies all packaged hashes and recalculates every retained timing from raw samples. The optional second also verifies all original input hashes. `import-consolidated.mjs` regenerates the selected data/provenance from that original directory without changing it; `RESULTS.md` is the human interpretation. Follow the root benchmark README to run fresh measurements on frozen checkouts; do not overwrite this archive. Quality/blind-authoring evidence belongs to the separate `custom-widget-authoring` lane and is not included here.
