## Implemented policy and limits

- Only strict synthetic `owner`/`viewer` selections are accepted; identities are loaded from the fixture repository and schema-validated. Missing/mismatched fixture identity fails closed, not fabricated. Owner reads/edits both owner-owned boards; viewer/anonymous get public reads only. Public owner variant is `owner`; viewer/anonymous share `public-reader`, containing no personalization or token.
- Private denial is `FORBIDDEN` (403); the shared existing board-read service returns `NOT_FOUND` (404) for missing records. Denial data is a fixed reason, never board content. Owner write/source-control guards require an active stored session and exact mutation checks. No GET/HEAD/OPTIONS mutation succeeds, including server direct calls carrying a read request context.
- Tokens are 32 cryptographically random bytes encoded as opaque hex. Incoming cookies are bounded to 8192 characters; malformed/duplicate session cookies are anonymous. Cookie is host-only, `Path=/; HttpOnly; SameSite=Strict`, with 900-second Max-Age and absolute expiry under the configured loopback HTTP origin. Secure is intentionally absent for this HTTP-only local fixture, not a production configuration.
- Process-local map is capped at **64 sessions / 15 minutes**, never sliding. Cleanup occurs on lookups/changes; the oldest insertion is evicted at capacity. Configurations exceeding these bounds or missing/invalid session settings deny session authority. Replacement revokes the old token, logout deletes it and expires its cookie, and shutdown clears/disables the store. Nothing is persisted, so a new process starts cold.
- Guards recheck the actual cookie against the live store and absolute expiry, not just `context.session`. A retained request context loses authority after expiry, eviction, identity replacement, or logout. Renderer must call the live guard before **every artifact delivery**, including cache hits and delivery after awaited rendering. There is no auth cache behind render TTL.
- Request origin/URL/Host must match the configured canonical loopback HTTP origin. Supplied Origin must match even on reads; foreign, opaque/null, malformed, cross-site/same-site metadata, credentials-bearing URLs, and mismatched hosts are denied. Mutations additionally require POST/PUT/PATCH/DELETE and an explicit matching Origin. Controlled internal HTTP GET reads may omit Origin with the correct local Host/URL; controls still require an owner mutation.
- SessionState returns only the schema-sanctioned synthetic identity/expiry or anonymous state. Tokens exist only in the store and cookie response header, not DTO/bootstrap/logs. SessionControls renders a fixed checking state on SSR and fetches current status only after mounting, so shared public HTML does not freeze the current user. Initial confirmed status, later identity changes, expiry timer, focus/poll refresh, and read failures reconcile/mask access. Status polling is 15 seconds; absolute expiry also schedules a bounded callback. Fixture/local/nonproduction warning is visible.

## Narrow editor epoch seam addendum

**Editing-complete, source-only follow-up.** Changed only `apps/nitro-experiment/src/features/session/session-transition.ts` and this appended addendum. No consumer/server/shared files, other notes, Linear, or roster were touched; no active implementation from other workers was read. No lint/typecheck/build/probes/tests/server/ports/database/install or new research ran for this follow-up. The earlier probe/review evidence predates this seam and does not validate it; narrow read-only review and composed race observations remain pending.

Exact additive exports, all from `src/features/session/session-transition.ts`:

- `captureSessionTransition(queryClient: QueryClient): number | null`: returns the QueryClient-local generation only when unblocked and no runner operation is active; otherwise returns null. No notification or mutation beyond normal store lookup.
- `isSessionTransitionCurrent(queryClient: QueryClient, epoch: number): boolean`: requires the same generation, unblocked state, and no active runner. No notification or mutation beyond normal store lookup.
- `invalidateSessionTransition(queryClient: QueryClient, capturedEpoch: number): void`: checks the same current predicate synchronously. Only a current epoch begins a new masked generation through `beginSessionTransition`; stale epochs and blocked/running states are no-ops. It never unmasks, acquires a runner slot, or queues work. A later accepted normal SessionControls/Recovery runner can reconcile and recover this mask.

The store adds only a scalar generation, initially zero. Every successful begin increments it synchronously before masking/notifications, even when already blocked; accepted runners use that same begin. Completion never resets it, and rejected overlapping runners neither begin nor increment. Generation exhaustion is terminal/fail-closed rather than wrapping or reusing a captured generation.

Runner settlement captures its prior generation **before** beginning, so synchronous subscriber reentrancy cannot make it adopt a newer begin. Successful work unmasks only if the generation is still exactly its own increment. A raw begin advancing the generation during an active managed operation therefore remains masked after that old runner settles; failure/supersession still releases the single operation slot. Existing hook/notifier/runner signatures and conservative managed raw-completion behavior are unchanged; no identity/principal/token or queue was added.

Editor consumption: capture before starting a save and refuse to proceed on null; after every await and immediately before cancellation, invalidation, `onCommitted`, or local UI writes, require the captured epoch to remain current. For UNAUTHORIZED/FORBIDDEN saves or failed fresh-loader reconciliation, conditionally invalidate that captured epoch. This masks current access without letting an old editor callback modify a newer identity operation. Consumer integration and actual browser/race checks are coordinator/editor-owned and unobserved here.
