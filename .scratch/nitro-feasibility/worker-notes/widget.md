## Implemented boundaries and bounds

- The sole upstream URL is `config.origin + "/fixture/source"`. Server fetch sends only an Accept header, omits credentials, disables HTTP caching and rejects redirects. Final response URL, JSON media type, declared and actual byte size, fatal UTF-8 decoding, and the existing strict `sourcePayloadSchema` are checked. The source is initially healthy with **42 items** and exposes no production data, environment input, credential, or arbitrary URL.
- Existing canonical local-request policy permits controlled source GETs without Origin but with the correct local URL/Host. Source reads accept only exact `/fixture/source` GETs with no query. Controls use live owner plus mutation-Origin authorization, not session truthiness. Raw controls accept exact `/fixture/source/control` POST JSON with no query; authorization is repeated after awaiting body input through `controlSource`. Both wrappers emit no-store and fixed safe error bodies. A source-only `X-Fixture-Source-Error` header distinguishes timeout/saturation/source failures without exposing exceptions.
- Widget cache keys contain only canonical origin and board ID. Retention is **2 entries / 32 KiB conservatively accounted encoded key/entry bytes / 5 seconds freshness / 60 seconds maximum observation age**. Expired entries are pruned on access/storage; insertion uses LRU eviction; oversized entries bypass retention. A failed attempt retries after at most 5 seconds but never extends the original observation's stale limit.
- At most **2 upstream refreshes** are active. Identical board/origin reads join one flight; saturation returns last-good stale or cold unavailable rather than enqueueing work. Each flight owns a **750 ms** abort deadline covering fetch and body reading, with a **4096-byte** response limit. Retained flights contain only a controller and promise whose producer captures scalar origin/version/key and finite widget limits, never a request, context, principal, repository, Router or QueryClient. Individual request cancellation rejects delivery without aborting another request's shared refresh; no per-waiter abort listeners or retained waiter queue are added.
- Source timeout mode deliberately waits at most **1500 ms**, longer than the fetch deadline. At most **2** such delays and **2** raw control-body reads are admitted, with no queue. Raw body reads are bounded to **4096 bytes / 750 ms**. Abort listeners/timers are detached on settlement. Close disables new work, aborts these source tasks and active upstream controllers, clears cached bytes/entries, and awaits the bounded upstream promises. Final shutdown behavior remains unobserved.
- `readWidgetSnapshot` authorizes before lookup/work and again after every awaited cached/joined/refreshed result, immediately before delivery. It also checks cancellation and closed state at delivery, drops expired last-good data, and schema-parses a fresh DTO rather than handing retained mutable objects to callers. Warm private entries cannot substitute for a fresh live authorization decision.
- Accepted validated HTTP observations alone advance the widget generation and observation timestamp. Failures retain the last accepted generation/time/data with a fixed stale error; cold/expired failures return unavailable with null data/time. Controls advance a separate internal source version, invalidate cached freshness for both boards, and prevent older active refreshes from retaining their result. Control output reports the latest **accepted widget generation**, not a fictitious fetched value. Each later accepted refresh advances generation, feeding the renderer's existing snapshot/key identity.
