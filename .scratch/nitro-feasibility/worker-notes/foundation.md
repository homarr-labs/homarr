## Consumable signatures and trusted boundaries

- `src/contracts/schemas.ts`: explicit strict schemas and exported inferred types for immutable board/identity IDs, `BoardContent`, `BoardRecord`, `BoardProjection`, read/save inputs/outputs, widget snapshots/generation, session inputs/state/logout, source payload/control, `BoardSnapshot`, `RenderIdentity`, `RenderAssets`, `Bootstrap`, and `RenderArtifact`. Shared error map: `NOT_FOUND`, `UNAUTHORIZED`, `FORBIDDEN`, `BAD_REQUEST`, `CONFLICT {currentRevision}`, `NOT_IMPLEMENTED`, `SERVICE_UNAVAILABLE`.
- `BoardRecord = {id, ownerId, visibility, revision, content}` is **server-only data**. `BoardProjection = {id, visibility, revision, content, capabilities:{canEdit,variant}}` omits owner/session/token data. Content is `{label, columns:1..4, widget:{displayLabel}}`; labels are 1..80 characters. Owners/visibility cannot be changed by save input.
- `src/contracts/rpc.ts`: `rpcContract` names `board.read`, `board.save`, `widget.read`, `session.current/select/logout`, `source.control`. `src/server/api/implementer.ts` exports `rpc = implement(rpcContract).$context<RequestContext>()`; capability procedures implement only their declared contract branches.
- `src/server/api/client.ts`: `FixtureClient = RouterContractClient<typeof rpcContract>`, `createBrowserClient(): FixtureClient`, `createFixtureQueryUtils(client)`. Same-origin `/rpc` Fetch link, same-origin credentials. `src/server/api/root.ts`: `apiRouter`, `createServerClient(context)` executes validated procedures without HTTP, retaining the current request context.
- `src/server/database/repository.ts`: `createFixtureRepository(database: Database): FixtureRepository`, `initializeFixtures(database): Promise<void>`. Repository signatures: `readBoard(BoardId): Promise<BoardRecord|null>`, `compareAndSave(BoardSaveInput): Promise<BoardCommitResult>`, `readIdentity(IdentityId)`, `listIdentities()`, `readSeedWidget(BoardId): Promise<WidgetSnapshot>`.
- `BoardCommitResult` discriminates `{status:"saved",board}`, `{status:"conflict",currentRevision}`, `{status:"not-found"}`. Commit is one parameter-bound SQLite `UPDATE ... WHERE id=? AND revision=? ... RETURNING` statement; content/revision change together. No awaited read-then-write or promise-shaped transaction is used. Revision overflow fails as conflict. **The repository does not authorize; editor service must guard before calling CAS.**
- `src/server/database/lifecycle.ts`: `initializeDatabase`, `getFixtureRepository`, `closeDatabase`. A shared initialization promise gates requests. `INSERT OR IGNORE` seeds absent owner/viewer identities, public/private boards owned by owner, and fixture widget snapshots; it never rewrites existing edits. Nitro plugin owns close, awaits render/session/widget cleanup hooks, then DB disposal.
- `src/server/context/request.ts`: `createRequestContext(request): Promise<RequestContext>`. Trusted server context is `{request,signal,responseHeaders,repository,session,config}`. `SessionPrincipal = {identity,expiresAt}` or null; never serialize the context/principal. Session resolution hook is `resolveSession(request, repository, config): Promise<SessionPrincipal|null>`.
- `src/server/access/guards.ts`: `assertLocalRequest(context)`, `assertMutationRequest(context)`, `authorizeBoardRead(context,record): AccessCapabilities`, `authorizeBoardWrite(context,record): void`, `authorizeSourceControl(context): void`. These are the access worker's common policy hooks for HTML, APIs, widgets, saves and controls. Mutation guards require supported write methods, exact Origin/Host and local URL; read-only methods cannot mutate. Rendering must call the live read policy **before each cache delivery**, not just cache creation.
- `src/server/api/board-read.ts`: `readAuthorizedBoardRecord(context,boardId): Promise<{record,projection}>`, `readAuthorizedBoard(context,boardId): Promise<BoardProjection>`, `boardReadProcedure`. REST can wrap the shared service with its own oRPC OpenAPI metadata and the existing schemas, without modifying the central typed procedure.
- Widget service: `readWidgetSnapshot(context,boardId): Promise<WidgetSnapshot>` reauthorizes the board. `controlSource(context,input): Promise<{mode,generation}>`; source HTTP wrappers call `handleSource(context)` / `handleSourceControl(context): Promise<Response>`. Use `context.config.origin + "/fixture/source"` as the sole server upstream; browser widgets use `client.widget.read`, never this source endpoint.
- `src/contracts/ui.ts`: `WidgetSlotProps {board,snapshot,client,queryClient}`, `EditorSlotProps {board,client,queryClient,onCommitted(board):Promise<void>}`, `SessionSlotProps {client,queryClient,onSessionChanged():Promise<void>}`, `BoardViewerProps {snapshot,client,queryClient,onCommitted,onSessionChanged}`. The editor does not need to patch the widget component: committed `board.content.widget.displayLabel` flows through props.
- `src/app/router.tsx`: `createAppRouter({adapter,client,assets,bootstrap?,queryClient?}): AppRouter`. `BoardDataAdapter.readSnapshot(boardId): Promise<BoardSnapshot>` selects server direct-caller versus browser same-origin execution. Every factory call defaults to a fresh QueryClient; Query dehydrate/hydrate callbacks are installed. `/boards/$boardId` loader uses this adapter. Commit/session callbacks invalidate Router; capability workers still own Query reconciliation and lost-access clearing.
- `src/app/root.tsx` is the full-document root with fixed en/light Mantine, asset links and Router `<Scripts>`. It calls the viewer-owned `BootstrapScript({bootstrap?})`. `Bootstrap` includes exact snapshot, render identity, assets and JSON-normalized router/query states; schema cross-checks board ID/revision/widget generation/capability variant. Serialize safely in the viewer module; do not retain live request/router/QueryClient objects.
- `src/entry-server.tsx` merges exact Nitro `?assets=client`/`?assets=ssr` imports and delegates `renderPage(context,assets): Promise<Response>`. `src/entry-client.tsx` invokes viewer-owned `hydrateApplication(): Promise<void>`. Those workers can wire manual SSR/hydration wholly within their owned modules using the shared factory/root; no entrypoint edit is required. Cleanup hooks may become asynchronous; the plugin already awaits them.

## Registrations, finite defaults and safe unfinished behavior

- Central Nitro handlers: `/rpc/**`, `/api/**`, `/openapi.json`, `/api-docs`, `/fixture/source`, `/fixture/source/control`. Catch-all page rendering is Nitro's Vite server entry. Nitro's competing OpenAPI generator remains disabled. All app responses receive `Cache-Control: no-store`; wrapper applies response headers including multiple session cookies.
- Development/start defaults bind **127.0.0.1:3100**. `NITRO_FIXTURE_ORIGIN` must be a loopback HTTP origin and defaults to `http://127.0.0.1:3100`. Container may set `NITRO_HOST=0.0.0.0` but must publish only host loopback and match its browser origin. Never use root `with-env` or real appdata. A fresh per-build UUID lives in Nitro runtime config; optional `NITRO_FIXTURE_BUILD_ID` must be 1..128 characters. Restarting one built artifact retains its baked build identity; this is not a source/lock hash.
- Config in `src/server/context/config.ts`: render **32 entries / 8 MiB total / 1 MiB artifact / 30 s age / 4 in-flight**; live widget **2 entries / 32 KiB / 5 s fresh / 60 s stale / 2 in-flight / 750 ms deadline / 4096-byte source / 5 s polling**; sessions **64 entries / 15 min TTL**. These are finite placeholders for capability owners to enforce, not existing cache/session implementations or performance claims.
- Initial seed is **42 items**, generation **0**, insertion observation timestamp; read adapter explicitly returns stale/`not-implemented`, never claims a fresh HTTP observation. Seed has its own finite **24-hour** insertion retention, then returns unavailable. Initial component displays label/value/observation/generation/status and explicitly says refresh is unavailable; no polling occurs. Real widget owner replaces this temporary seed policy with bounded live-source state.
- Anonymous typed public reads work; all private reads and saves/source writes deny. Session lookup always returns null; selection/logout return 501 after mutation checks. Editor mounts nothing. `/` returns an honest diagnostic JSON response; public page returns 501 after authorization, private page 403. SSR/bootstrap script/hydrator are deliberately inert until AJN-500, not a client-only implementation masquerading as SSR. REST/docs/source return 501 and reveal no private data.
