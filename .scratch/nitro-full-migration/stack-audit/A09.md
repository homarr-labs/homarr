## Placement and nominal boundary

- Concrete clients, credential-bearing `http-auth.ts`, base classes/errors/test services, Stats provider algorithms, and owned runtime/bindings are backend-only. Decoupling from frontend does not move business algorithms into a frontend app or invent protocol agents. Retain genuine class identities and the single lazy creator; delegate source algorithms to the already proposed native-client directories only after coordinator authorization.
- `IntegrationInstanceOfKind` resolves concrete factory results. Base protected input/helpers and private `createUrl`, plus per-client fields, remain nominal barriers; every recorded barrier line is a declaration candidate, not proof of a missing method. `runtime/executor.ts:193–203` still requires that concrete result. A public `Pick` checks signatures only; it cannot construct the original class or intercept Core imports.
- `index.ts` → `src/index.ts` eagerly reexports server clients, server Wazuh errors, and Node `response-contract.ts`. Browser callers must use genuinely pure contract leaves or a separately reviewed contract-only export. `src/types.ts` is a mixed schema/enum/type barrel, not evidence that the package root is browser-safe. `stats/index.ts` imports existing clients and a guard from `stats/-runtime`; `getStatsMetrics` is therefore not automatically a browser-pure entrypoint.
- Most `*-types.ts`, interface leaves, and Zod schema files can remain shared contract candidates. Exceptions: llama.cpp/PatchMon/WUD type files instantiate `ParseError` from `@homarr/common/server`; Technitium types mix schemas with an `IntegrationError` subclass and credential-session shape; Stats types expose Undici transport/header and private auth contracts. Download item/status leaves have type-only DB dependencies and UI action closures; media-release configuration has a type-only Mantine dependency. Keep those distinctions rather than labeling all type-named files browser-pure.

## Construction, authentication, and transport trace

Current base construction stores input; the decorator walks prototypes and wraps function-valued methods, not getters. Session-store field initializers/constructors in Beszel, Glances, OMV, Pi-hole v6, Synology, Technitium, UniFi, and Wazuh synchronously require runtime resources and fingerprint configuration. Their backing acquisition occurs during construction, before later business calls. The resource context must surround factory construction, not just method invocation. Pi-hole factory also performs HTTP detection and broadly catches failures; cancellation/trust errors must not be hidden as version selection. Technitium factory itself is construction-only; negotiation is lazy.

`Integration.testConnectionAsync` invokes the bound test transport; `StatsIntegration` explicitly builds its fetch context from leased fetch/Axios/dispatcher. This does **not** redirect other clients' default Core functions. Several testing implementations use supplied transport while their ordinary/authentication methods retain Core transport. QBittorrent's `getClientAsync` additionally performs `getAppVersion` before its requested operation. SDK login, version detection, retries, fan-outs, body reads, and speculative pages must all share the operation owner; closing or aborting only a top-level promise is insufficient.

No direct Next.js/tRPC imports or direct process-environment reads were found in the safe package text. This is not complete framework independence: Core HTTP/certificate/logger imports, Common server helpers, image proxy, Redis histories, and Node ALS/transport remain runtime edges. Logger creation occurs at module load in many clients. Nextcloud additionally registers global ICAL timezones and extends Dayjs at module load; SABnzbd extends Dayjs duration. Root import therefore has construction/registration effects even without provider I/O.

## Additional framework-glue cuts not explicit enough in the existing plan

1. **Historical state, not cache invalidation alone:** DashDot `dashdot-integration.ts:93–108,175–180` pushes CPU samples to a direct cross-package Redis history helper, keeps capacity 100, and reads a 15-minute window for source load averages. OPNsense `opnsense-integration.ts:64–104` stores capacity-15 interface histories and returns the latest pair. Removing DashDot's side-effect Redis import does not remove these value-producing edges. Existing runtime contracts have no history capability; cache bindings only invalidate caches. Coordinator/A08/A10 must classify and supply real owned history semantics, key isolation, ordering/retention and concurrent-update behavior before a KV substitution. Do not infer transactional history updates from generic KV.
2. **OPNsense is also streaming:** CPU reads consume `/api/diagnostics/cpu_usage/stream`, skip first-chunk samples, bound reads to ten iterations, and await reader cancellation in `finally` (`132–185`). The network-home bucket needs the same real owned HTTP streaming/body-retirement capability, not just the Beszel system bucket.
3. **Module-global auth/discovery state:** Jellyfin `68–109` coalesces in-flight authentication across instances using `createKeyedFingerprint`; the key lacks configuration/trust lifetime identity and followers inherit the initiator's request. Synology `synology-client.ts:52,351–388` caches API definitions globally, keyed by integration ID/API name, not changed URL or trust identity; neither is removed by delegating HTTP. Move ownership/currentness and follower cancellation policy through a reviewed coordinator seam; do not silently delete coalescing/discovery behavior or share across incompatible trust snapshots.
4. **Contract/export and build glue:** separate credential/transport/error values from browser contracts, retain schema behavior and type-only DB/UI links deliberately, preserve lazy chunk discovery without assuming Turbopack, and retain decorator compilation semantics. Package export/dependency edits remain manifest-writer/coordinator work. `tooling/typescript/base.json` aliases `@homarr/node-unifi` to installed `@types/node-unifi`; decoupled backend resolution must preserve or explicitly replace this declaration join. `unifi-controller-types.ts` uses the distinct `node-unifi` type spelling.
5. **Bounded helpers:** Traefik's helper is not browser-pure despite its small size: it delegates a 2 MiB bounded body read to Common server code. Node-only response fixture simulation also must not leak through shared runtime exports. Preserve guards/errors, not an unbounded parser substitute.

These are coordinator/dependency handoffs, not fresh leases or a second registry. Image registration, raw socket release, sessions/currentness, and physical settlement remain the existing closure-plan holds. Backend root is only the proposed `apps/backend`; no relocation is authorized here. Q16/Q17/Q18 and principal/SQL-COMMIT coherence are unchanged.
