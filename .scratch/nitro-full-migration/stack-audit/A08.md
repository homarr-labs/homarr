# A08 — Core/Redis read-only cutover audit

## Coverage and authority

Read `STACK-CUTOVER.md`. Current coordination ceiling is **32 agents**, not a cache capacity. Inventory uses `git ls-files --cached --others --exclude-standard -- packages/core packages/redis`: **107 paths; 92 safe text files read completely; 14 generated HTTP-result JSON files classified without reading; one actively written core manifest excluded from acceptance**. `A08.json` records every path and its effective classification, dependency, target, preservation action and blocker. Ignored `.turbo`, `node_modules` and external symlink targets are excluded. No runtime imports, tests, builds, installs, SQL, providers, credentials, product mutations or nested agents were used. Public documentation reads only. This is inventory and a proposed cut, not implementation acceptance or a renewed state/history/security review.

Generic cache TTL compatibility also includes **clearing a previous expiration when overwritten without TTL**, `ttlMs` precedence over `ttlSeconds`, and deleting for nonpositive TTL. Cleanup must not delete a replacement written after an older expiry. A timeout race only bounds the caller's wait; it does not prove the backing write was cancelled. Driver expiry/deletion/abort guarantees therefore need a real adapter contract, not an `AtomicStateBacking` label.

## Core framework and backend direction

- `core/src/infrastructure/env/index.ts` directly imports `@t3-oss/env-nextjs`; every DB/DNS/log/Redis env factory reaches it. Keep empty-string-as-undefined, CI/SKIP_ENV_VALIDATION/lint skip conditions, prefix stripping, case-insensitive boolean vocabulary and the exact duration schema behavior. Replace only framework-specific env construction with a declared server validation port after the **active core-manifest writer** supplies reviewed declarations. No manifest state is accepted here, and no credentials were read.
- No `next/*`, React `cache`, `unstable_cache`, `headers()` or `cookies()` appears in inspected core/Redis source. Request headers are explicitly Axios/Undici inputs, image-proxy encrypted headers and external proxy configuration, not ambient Next request headers. Retain ALS abort propagation in `http/request-signal.ts`; the backend composition must pass the actual request signal/headers explicitly. Never globally cache per-user request authority.
- Core DB drivers own Drizzle, explicit PostgreSQL pool configuration and Bun SQLite synchronous transaction scopes; default schema mapping is SQLite until explicit dialect is supplied. These remain native SQL, not KV. A Node-only backend cannot assume Bun SQLite works unchanged.
- Certificates keep filesystem roots and SQL hostname grants. DNS remains opt-in native lookup caching (1,000 entries, minimum five-minute TTL), not a Nitro KV DNS resolver. TLS contexts remain live native objects (four contexts); HTTP fetch dispatchers remain owned native resources (eight cached configurations, default retirement grace 1,000 ms). These are not serializable KV payloads; preserve invalidation/drain and existing unsupported native-transport holds/Q17.
- Dependency direction is consumers → Redis/cache ports → core infrastructure; core contains no imports of API/auth/db/request-handler/integrations/widgets/UI server runtimes. Core logging lazily opens Redis on first log; importing legacy Redis channels opens multiple clients, and legacy HTTP agent imports DNS initialization. These side effects must not reach frontend shared contracts. Browser use observed in Nitro is only `logs/constants.ts`, not logger/transport runtime.
- `apps/nitro/src/server/compose.ts` currently composes public foundation health/RPC, not a KV/cache/SQL/logger/task producer. No `useKV`, `useStorage`, `unstorage` or state/history backing join was found in its source tree. `packages/db/runtime-state.ts` and `runtime-history.ts` were located by filenames only, not accepted/re-reviewed. Candidate backend binding belongs under `apps/backend`; frontend stays `apps/nitro`. No relocation is authorized by this audit.

## Minimal honest implementation cut

1. Add a **cache-only injected port** (planned `packages/redis/src/cache/{contracts,index}.ts`) with serialized get/set/remove, exact logical key, optional TTL ms/seconds semantics and owned lifetime. **Do not implement `AtomicStateBacking`, locks, epochs, pub/sub or security through this port.** Preserve `ttlMs` precedence; nonpositive TTL deletes; missing is distinct from a serialized null; no-TTL remains persistent where required.
2. Implement Nitro binding (planned `apps/backend/src/infrastructure/cache.ts`) against real `useKV` from `nitro/kv`, on a reviewed private mount. Keep SuperJSON at the application boundary rather than passing Date-bearing objects into ordinary JSON serialization. Driver TTL is seconds and driver-specific: never silently round millisecond deadlines or assume metadata TTL expires values. Retain an absolute expiry check for exact visibility and require bounded physical cleanup for the selected driver. Keep logical namespaces and avoid key-normalization collisions. Use private mounts, not assets or root-wide clear.
3. First wire ordinary board snapshot persistence through a real producer-owned port; preserve its authorization/generation/query-key rules. Then split shared response and update freshness payload ports from native SQL coordination. Conditional publication remains held until a real producer contract preserves cross-store failure/invalidation behavior; no post-check write claim of CAS, and no `setItems` transaction claim. Persistent stale/security/history rows remain native/durable. No fallback may advertise shared state when only local memory exists.
4. Wire actual log/status/ping/scheduler producers to the same owned listener/SSE owner and reuse their existing SQL/history ports. Stop subscriptions/timers, abort pending work and await owned cleanup at shutdown. A second process/listener needs an explicit delivery mechanism; local callbacks are not cross-process pub/sub. Keep current 32-agent cap and existing exclusive producer/declaration leases.

Official references: [Nitro v3 KV storage](https://v3.nitro.build/docs/storage), [unstorage API](https://unstorage.unjs.io/guide), [memory driver](https://unstorage.unjs.io/drivers/memory). Nitro v3 uses `useKV`/`kv`; `useStorage`/`storage` are deprecated aliases. Default KV is process memory; TTL/watch/batch APIs do not establish CAS, SQL transactions, distributed delivery or restart durability. No provider connection was made.
