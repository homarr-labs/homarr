## Proposed backend move, not authorized implementation

All 14 `src/server/**` files and both `server/**` lifecycle files are backend/SSR runtime candidates under the same relative paths in `apps/backend`; `nitro.config.ts` is backend host configuration. JSON gives every proposed destination. Shared `request`/`contribution` contracts should become dependency-light package contracts; browser render/provider/refresh contracts stay frontend-owned or shared, never backend-private browser dependencies. SSR `render.tsx` intentionally consumes frontend Router/routes/providers on the server: design an explicit frontend SSR artifact boundary, not a browser import of a backend server.

`entry-server.tsx` needs a backend same-listener entry/asset bridge; `entry-client.tsx` stays frontend. Split Vite/Nitro build integration only after reviewing asset serving, externalization (`/nitro/src/server/`), paths, declaration ownership, static assets and deployment. Update lifecycle imports as one exclusive cut: HTTP, oRPC/SSE, assets and SSR must share the same application lifetime and disposal owner. `application.ts` has ordered contribution startup, request memo/effects/disposers, HEAD/body cancellation, active-body retention and reverse shutdown; relocation must preserve those mechanics. Public preparation's SQL readiness/admission, same-schema injection, serialization-before-admission-release, anonymous-only policy and bounded/origin-checked locale mutation stay guarded. Prepared join slots explicitly hold authenticated principal, compatible writers, integrations, widgets, state/history/jobs SQL, copied catalog, render hydration and production listener. Q16/Q17/Q18 remain unresolved.

Redis removal is not demonstrated by the absence of imports here. No Nitro KV adapter is installed in this scope. Appropriate cache replacement belongs with A08's concrete cache graph; sessions/authority/transactional state stay SQL, and real pub/sub delivery needs owned same-listener SSE—not fake KV subscriptions or guessed CAS.
