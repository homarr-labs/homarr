## Transport and lifecycle invariants

- **One Homarr listener:** old app-local evidence is port 3001 for WS and no tasks port. The architecture reference records production Next instrumentation starting both runtimes and nginx `/websockets` forwarding to 3001; actual instrumentation/nginx belongs to A01/A16 and was not read here. Replace that wiring jointly. Decoupled frontend/backend directories do not imply separate Homarr hosts or ports. Workshop's independent 8090 listener is not a second Homarr subscription listener and is retained.
- **Origin is a gap to close deliberately:** `apps/websocket/src/main.ts` itself has no Origin allowlist/check. That does not establish downstream router/proxy behavior. New cookie-authenticated HTTP/SSE must apply the approved origin/host/CSRF policy at real ingress, preserve reverse-proxy deployment semantics, and reject unauthorized cross-origin subscriptions. Do not reuse Workshop's public `PB_ALLOWED_ORIGINS=*` for Homarr privileged streams.
- **Real authority:** old WS normalizes incoming headers, parses the configured session cookie and calls `getSessionFromToken(db, token)` before `createTRPCContext`. Errors log and produce null session/empty headers, not an invented user. Preserve actual resolved identity, anonymous/public access distinctions and per-operation/resource permissions. Never trust client principal IDs, fake admin/service principals, or connection success as authorization. Session revocation/expiry during long streams needs an explicit A04/A03 contract.
- **Subscription truth:** the app imports `@homarr/api/websocket`; it does not define a local topic catalog. A03 must enumerate each router subscription and its inputs/payload/error/access semantics; A08 must provide its actual producer channel, initial snapshot/order/reconnect/unsubscribe rules. A10 supplies job/status producers. Reuse the single approved publisher/subscriber owner; no parallel topic registry, KV-shaped fake subscribe, ACK-only streams or synthetic data. Define buffering/backpressure/gap behavior; do not claim durable replay unless the actual producer supports it.
- **Startup readiness:** retain dispatcher → session cleanup → initialize → start ordering, then report real readiness/failure. Old WS readiness resolves on actual listening/error. SSE readiness must likewise reflect real registered transport and producers, not an unconditional resolved promise. Import/build/SSR/HMR must not start an extra scheduler/listener.
- **Drain:** old task files provide no explicit stop/drain; old WS handles SIGTERM only and does not demonstrate an awaited active-client drain. The owned backend must stop admitting work, stop cron scheduling, bound/await active jobs and producer work, signal/close SSE streams, unsubscribe/dispose shared resources, close the same listener and finish within deployment grace. HMR/restart must clean owners. Specify SIGTERM/SIGINT and failure handling; do not advertise old WS reconnection frames as SSE replay guarantees.

## Workshop preservation boundary

`main.go` registers PocketBase JS hooks/migrations, Homarr provider routes and static docs serving. It preserves query-bearing canonical redirects, separate missing-API errors versus custom `404.html`, cache behavior (including Next static assets), compression quality and video-range exceptions. Those `_next` paths are part of **excluded docs architecture**, not permission to migrate docs to Nitro.

`homarr_provider.go` exposes `/api/ai/v1/models`, authenticated `/api/ai/usage` and `/api/ai/v1/chat/completions`, with PocketBase user authority distinct from Homarr local authority. It enforces bounded input/output, model aliasing, sanitized tools/routing/cost parameters, per-user/global in-flight limits, transactional daily quotas, redacted bounded upstream errors, cancellation-aware outbound HTTP and real JSON/SSE responses. Retain PocketBase transactions and quota history; Nitro KV cannot replace them. Provider keys remain Workshop-server-only. Read the provider source only; no requests were sent.

JS migrations own users, submissions, votes, comments, private reports/author summaries, listing aggregates, atomic submission revision CAS, migration rollback snapshots and private daily/global assistant quotas. Hooks synchronize optional GitHub OAuth, render escaped social metadata (local/remote listings), initialize submission metadata/author votes, reopen reports and notify authors/moderators. HTML templates preserve their existing content and placeholder escaping. Keep all data/ACL/migration contracts unchanged; do not run down migrations or reset volumes.

Deployment text pins Go/PocketBase versions/image integrity and builds `apps/docs/out` into the independent PocketBase production image, retaining `/pb_data`. Entry point drops privileges and writes public URL-only runtime config before exec. Preserve public API/web/website URLs, OAuth redirect contract, allowed origins, nonroot behavior, health checks, immutable-image promotion and backup/restore contracts. Staging defaults to a mutable image tag even though README advises immutable digest promotion; this is existing operator guidance, not a stack-cutover edit authorization.

**Homarr-facing seams do need the new stack:** `packages/workshop` (A12), API Workshop/auth/provider operations (A03/A04), Custom Widget validation/runtime (A13), and browser Workshop/provider consumers (A02/A05/A06) must call the existing independent PocketBase REST/file/OAuth/OpenAI-compatible contracts via actual authorized Nitro services and oRPC Query consumers.
