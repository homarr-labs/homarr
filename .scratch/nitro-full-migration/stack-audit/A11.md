# A11 — database stack boundary inventory

## Outcome and scope

Read-only inventory, not implementation or renewed persistence acceptance. Scope is `packages/db`; only this report and `A11.json` are written. `STACK-CUTOVER.md` is steering, not an edit target. Filename inventory includes tracked and nonignored untracked source. Frozen source basis: Git HEAD `c009cba62d8ffab1d19186e4df62674b616979fd`. Modified tracked files use that baseline for static edges; their current implementations remain held. Initial manifest orientation is not acceptance of its mutable source.

**216 individual paths classified:** 119 safe frozen text files scanned (53 source/config/test files and 66 historical SQL files; 10,144 lines), 70 generated migration metadata files classified without body interpretation, and 27 untracked source files held without content interpretation. Twenty unchanged small files additionally received complete manual reads; the JSON distinguishes manual reads from static scans. Reading text does not certify behavior. Migration SQL was scanned as text, never executed. Generated snapshots/journals are not product source or disposable files.

Excluded trees: `packages/db/node_modules/` (vendor/cache and possible symlink targets) and `packages/db/.turbo/` (generated running output); no traversal or external-target reads. Generated `migrate.cjs` bundles are named build outputs, not additional inventoried Git-owned source. No binary/static asset occurs in the 216-path filename set. No credentials, environment values, appdata, current DB contents, providers, browser, application imports, tests, builds, installs, SQL execution, or Git mutation were used.

## Import and browser graph findings

- No direct Next, `server-only`, or `client-only` import was found in frozen `packages/db` text. No tRPC/Redis value import was found there. The Next cut is in callers, not removal of DB domain behavior.
- `index.ts:1,5,11–16` exposes Node async-local admission, core DB scope, runtime/copy/store and transaction modules. `schema/index.ts:5,7–19` imports core `createSchema` and both engine schemas. Consequently **DB value exports are backend-only even without a `server-only` sentinel**.
- `validationSchemas.ts:1,5` → `drizzle-zod` + `./schema` → core driver infrastructure. It is not a browser-safe value boundary. `driver.ts` imports Bun SQLite, Drizzle SQLite/PG and both engine schemas **only as types**; distinguish erased types from value reachability.
- Core driver/factory/scope dependencies occur in root, schema, runtime, copy and transaction gate; certificate-schema re-exports occur in both engine schemas. Their downstream implementation/ambient environment evaluation is A08's boundary, not certified here. `queries/item.ts:5` deep-imports widgets **only as a type**; preserve intent while decoupling shared contract ownership.
- Direct ambient config edges: `configs/postgresql.config.ts:4,11–18` and `configs/sqlite.config.ts:4,10` import/use `dbEnv`. Their _names_, not values, were read. No frozen production persistence source directly references `process.env`. Test-only ambient edges are `runtime.spec.ts:33,35,1052,1265` (`PERSISTENCE_G_CONFIG`, `PATH`, `HOME`) and `test/sqlite-migration.spec.ts:50–51,255–256` (`DEMO_MODE`). Package `with-env` is operational dotenv glue; it was not invoked.
- Native/Node import edges and type/value distinctions are recorded in `A11.json`. Existing test files retain `better-sqlite3`, Bun SQLite, `pg` and Testcontainers imports as offline source evidence only.
- A frozen static traversal from **511 `"use client"` roots**, visiting **1,164 source paths**, found **zero reachable DB entries via resolved static value imports/re-exports**. Type-only declarations were excluded. This is bounded evidence, **not a browser bundle proof**: dynamic imports, package wildcard/unsupported conditional exports, unresolved aliases, other entrypoints and current mutable `apps/nitro` code were not certified. No clean-current-graph claim is made.
- Frozen Next callers include invite/init/user-create/board-settings/not-found server pages, SEO server component, API HTTP handlers, backup import, live health, onboarding claim, media and MCP authority routes. `apps/nextjs/src/proxy.ts` uses the reader export; tasks session cleanup and websocket main use SQL. Package server consumers include API/auth/CLI/cron/analytics/icons/request-handler. `packages/settings/src/creator.ts` uses `User` only as a type. Widget app/bookmarks prefetch uses SQL values: keep server prefetch behind backend transport rather than importing it into a browser module registry. Caller bodies and other audit scopes are not re-reviewed.

## Durable values and minimal startup/deployment join

Retain both legacy driver identifiers (`better-sqlite3`, `node-postgres`), schema casing, SQLite/PG timestamp/binary distinctions, SuperJSON settings/options and SQL constraints. Preserve account/session/verification/API-key/invite authority; groups and permission links; all board/layout/item data; media/icon references; onboarding, cron and settings rows. Preserve encrypted integration-secret and widget-secret `value` encodings, legacy/v2 custom-widget encrypted values, and assistant encrypted API key/headers; no decrypt/re-encrypt/reset is authorized by this stack change.

Keep all **49 SQLite + 17 PostgreSQL historical SQL files** and generated snapshot/journal identities unchanged. Preserve the hash/timestamp comparison in `migrations/compatibility.ts:6–17`; do not rewrite historical SQL, discard snapshots, renumber journals, or reset data to fit a new framework. New `0049`/`0017` files and changed journals remain held, not accepted updates to the historical baseline. No migration hashes or generated catalogs are reproduced here.

Bounded proposed cut: backend composition resolves explicit configuration once, creates the owned persistence runtime, performs the existing validated schema/content migration sequence before readiness, wires admitted DB and proxy/trust capabilities into same-listener backend handlers, and owns draining/close. Move only caller/startup glue; preserve package paths and operation boundaries. `runtime.ts` resolves `./migrations/<engine>/` relative to `import.meta.url`; copy engine resolves `./migrations/sqlite/`. Preserve that layout or supply an explicit verified folder in deployment. Existing build metadata names both `migrate.cjs` bundles. No backend build/asset relocation is accepted without the deployment join review.

Nitro KV may serve separately reviewed disposable caches; it does **not** replace SQL authority, migration ledgers, transactions, durable runtime values, recovery or native pub/sub semantics. KV availability is not evidence of CAS, commit or rollback guarantees. Keep Q16/Q17/Q18 affected joins held.
