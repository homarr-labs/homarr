## Findings and narrow cutover targets

### F01 — Common public boundaries need a declaration gate

`packages/common/src/index.ts:1-16` re-exports object, string, cookie, array, date, stopwatch, hooks, id, URL, number, error, theme, function, grid and resize helpers. It does **not** re-export `server`, `client`, `env`, or `types`. Preserve that separation. The root is not a dependency-light browser contract: React/Mantine hooks/theme are included; `object.ts:16-17` uses Node `Buffer` when hashing; `date.ts`, `hooks.ts`, and `stopwatch.ts` register Day.js plugins, and `stopwatch.ts:10-27` globally changes English relative-time strings.

Source consumers now spell `@homarr/common/object`, `/url`, `/number`, and `/date`. Corresponding implementation files exist and were inspected. **Their current public export declarations are not accepted by this audit**: `packages/common/package.json` is excluded as an active writer. Coordinate exact declarations with its owner; do not deep-import `src` as a bypass, add new utility copies, or replace the root wholesale. Common skill reference metadata predates this declaration work and is not proof of the mutable exports.

Browser candidates once the declaration gate is reviewed: `/number` for bytes/rates/conversion; `/date` for validated dates/duration; `/url` for safe app links; `/object` for typed keys/entries/record guards. `/object` still needs a separate decision for `hashObjectBase64`: preserve TanStack `hashKey([obj])` serialization and UTF-8/base64 output, not a guessed JSON.stringify/btoa substitution. `/url` has a **type-only** Next internal `ReadonlyHeaders` import; no runtime Next import, but declaration closure still depends on Next. Use a reviewed standard/structural header-reader contract in this same canonical file while preserving header/protocol behavior. These are proposed cuts, not implementations.

### F02 — Server helpers are not browser imports

`packages/common/src/server.ts` eagerly exports security, encryption, requests, errors and bounded response parsing. `request.ts:1-8` imports `next/server` user-agent parsing. Replace that adapter with a verified dependency/contract preserving device classifications and existing return shape; do not invent a UA parser or assume Nitro/H3 supplies an identical result. `ipAddressFromHeaders` currently returns the raw `x-forwarded-for` value: no trust/proxy reinterpretation is authorized here.

`encryption.ts:3-10` imports validated environment at module load and derives AES/HMAC keys; `env.ts` imports Node crypto and core environment infrastructure. Keep these and `security.ts` backend-only, preserve persisted AES-CBC ciphertext/IV format, keyed fingerprint derivation and timing-safe comparison. The existing skipped-validation zero-key fallback is **not permission** to supply fake/default keys in a production cutover. Do not expose environment objects, secrets, or token helpers through browser barrels. No `server-only` sentinel was observed in these files; the actual import graph, not the suffix, enforces the restriction.

HTTP/parse error handlers import core logging and several HTTP SDK error classes. Keep reusable error normalization rather than reimplementing fetch/provider parsing. Standalone `/errors/http/request-error.ts` and `response-error.ts` contain dependency-light classes/types; importing their aggregate server/error barrel also imports logging/provider code. `NodeFetchHttpErrorHandler` exists but is not re-exported by the handlers barrel. `readBoundedJsonResponseAsync` is an existing structural stream parser with declared and streamed byte limits; reuse it where required instead of an unbounded or fake parser. Runtime reachability of logging/core is A08 coordination, not proved here.

### F03 — Revalidation is not a promise-shaped no-op

`packages/common/src/client.ts:1` exports a Next server action. `revalidate-path-action.ts:1-6` uses `"use server"` and `revalidatePath(path, "page")`. This is not an ordinary browser helper. Target the owning consumers' actual oRPC Query invalidation **and** TanStack Router invalidation/reload/navigation contracts, preserving post-mutation completion and path-specific data refresh. Do not map a page path blindly to an arbitrary query key, replace it with `Promise.resolve()`, or retain a hidden server action bridge. Relevant source consumers surfaced in forms-collection board/app create and onboarding account/welcome/setup-studio; A06 owns their full coverage. `apps/nitro/src/app/router.tsx` is a discovered host location, not reviewed or accepted implementation.

Keep compatibility during a narrow convergence onto `src/standalone/types.ts`; do not leave a declaration-only Next dependency hidden after runtime migration. `standalone/compatibility-types.ts` is a deliberate cross-facade type witness, not product runtime, and will require a deliberate disposition when legacy types retire.

Legacy mapping uses a variable JSON import; accepted standalone `catalogs.ts:9-46` provides explicit lazy loaders for all 36 canonical files. Reuse it for Vite closure; do not make a second catalog. Preserve recursive removal of blank translations, English merge fallback, strings/whitespace/malformed entries as stored, immutable per-request messages, error/fallback callbacks, namespaces, `.has`, `.raw`, rich React substitutions, and ICU zero/one/other behavior. Existing check/test source covers subsets and error-mode distinctions; it was **read, not run**, so this audit does not claim these checks pass today.

**Semantic risk to reconcile, not permission to rewrite the accepted facade:** `getIntlLocale` maps `cn→zh-CN`, `zh→zh-TW`, `cr→en`, and the culture formatter uses `resolved.intlLocale`. Standalone `loadRequestI18n` instead keeps `snapshot.locale` as the catalog key and forwards that unchanged to `createTranslator`/`createFormatter`/`IntlProvider`. Its all-locale check loads messages, while the visible formatting examples exercise English/French and provider examples English/Hebrew. This text evidence does not prove Intl formatting/plural behavior for `cn`/`cr`. Retain catalog identity and the accepted mapping, and require an explicit reviewed facade decision for Intl aliases; do not rename locale keys or assert behavior from catalog-loading coverage.

`now`, `timeZone`, named `formats`, hour12/seconds preferences and request clocks must remain explicit where supplied. The facade intentionally permits omitted `now`/`timeZone`; avoid blanket UTC/default insertion. Existing `runtime/date.ts` distinguishes date-only UTC values from explicitly zoned timestamps. `runtime/culture.ts` attaches Day.js locale per instance; `runtime/resources.ts` loads Day.js/table assets with revision fences and immutable ownership. `src/dayjs.ts` is old global-locale/Suspense/Next-params glue, not a replacement resource owner. Locale changes require the host callback: standalone `useChangeLocale` throws if missing. Keep the locale cookie key, one-year lifetime, base path, no-prefix URL semantics, source precedence and failure behavior; do not emulate locale changes by changing only strings or by silently adding URL prefixes. Browser host glue and current public-culture composition remain A02/production-join gates.

### F05 — Definitions, validation, and settings remain canonical contracts

No direct tRPC, API, auth, SQL/DB import was found in the inspected assigned source. No request providers are implemented here. `definitions` is stable business metadata, not an API-result-derived frontend type layer. Keep integration/secret kinds and public-vs-private metadata, authentication mode alternatives, widget capability/reverse mappings and maximum integrations, default option values/sizes, Docker candidate browser/server scopes, release-provider normalization, auth choices, permission inheritance/matrix and navigation-access rules. A registry entry such as `httpAuth: {type: "adapter"}` requires its real integration-owned adapter, never a fabricated generic credential bridge. Catalog `mock` remains the existing hidden/development metadata, not production cutover fallback behavior.

`@homarr/definitions` root and declared `/integration`, `/cookie`, `/docs/*` sources are reusable. The root pulls `docs/index.ts` and derived catalogs; `docs/index.ts:5-11` reads a **public website URL** from DOM meta or guarded process environment. Preserve the backend-provided browser metadata when replacing Next layout, and avoid leaking general server environment. `widget-integration-map.ts` computes bookmark links at module initialization, so changing public metadata after import cannot be assumed to refresh those stored links. Metadata/codegen are different exports from the runtime docs-link helper: never import `docs/codegen` into a browser/API barrel; its top-level main writes files and its refresh branch fetches a sitemap.

Validation declares only wildcard subpaths (`@homarr/validation/<module>`), **no root export**. Reuse these same Zod schemas at browser forms and oRPC/backend trust boundaries. Keep refinements, coercion/transforms, null-vs-omitted behavior, strict/strip policies, legacy-header and dynamic-section migrations, input bounds and error parameters. `enums.ts` assumes nonempty enum/union inputs: do not replace registries with empty or truncated arrays. `form/i18n.ts` and `user.ts` import translation types only, so there is no runtime Next hook import there; declaration closure still reaches legacy `next-intl` types. Retarget type-only imports to canonical standalone types when the facade contract is reviewed, not to server/router types.

Security-sensitive preservation examples: reserved group names and permission literals; lowercased/trimmed username vs existing minimum-password rule (suggestions are not additional enforcement); LDAP special-character rejection; profile null/email transforms; exact responsive Mobile/Base/gutter/ID constraints; source-owned header account-access requirement; distinct empty app href, restricted ping URL, integration-create URL, and onboarding service-address policies. These schemas validate **shape**, not principal authorization. Browser-visible permission metadata, schema defaults and legacy preference parse fallbacks never grant privileges; server per-request SQL authority remains owned by A03/A04/A11.

`media.ts` uses real `zod-form-data` repeatable File decoding, supported MIME types and 32 MiB per-file limits; `certificates.ts` uses File checks/extension and 1 MiB limits. Preserve multipart/body-limit/transport parity with backend owners, not a JSON surrogate or fake File parser. Do not infer aggregate upload limits or PEM/CA trust verification from filename checks.

`@homarr/server-settings` is a browser-safe **schema/default/type** package despite its name; it imports no database or API. Keep canonical branding bounds, legacy login-setting interpretation, defaults, color-override behavior and setting keys in `src/index.ts`. `SupportedLanguage` is currently a type-only root-translation import; prefer the declared `/languages` type entrypoint to narrow dependency closure. Persistence, effective settings, privileges and runtime public responses are backend-owned; do not import an API router/DB row to infer browser settings types or mistake `parseBrandingSettings` fallback for authorization.

## Dependency/type-cycle assessment

Observed source direction is validation → definitions + translation types; translation/runtime → definitions cookie + common date/number; definitions → common object/url/type helpers; server-settings → definitions + translation types. No direct API/SQL/type cycle was found in these files. However, aggregate common server/error helpers pull core logger/environment infrastructure, and mutable common declaration/package dependencies are intentionally not accepted here. A08 must review those downstream graphs; this audit cannot certify transitive cycle freedom. Keep pure client schemas/domain vocabulary directed inward, and server implementations directed toward those contracts, not vice versa. Do not replace types with `RouterOutputs`, server context, request-bound resources, or SQL schema inference.
