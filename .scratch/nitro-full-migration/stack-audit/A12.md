# A12 — infrastructure packages stack cutover audit

## Outcome and evidence boundary

Read-only source audit, 2026-10-11, governed by `../STACK-CUTOVER.md`. **75/75 safe repository-owned files, 5,352 lines, fully content-read** across icons19, image-proxy3, ping4, docker17, analytics8, workshop8 and cli16. This includes all seven existing spec files; none was executed. Git's cached/untracked, exclude-standard inventory matches the safe-file set. An additional21 ignored generated files received filename/classification only:14 `.turbo` logs and seven TypeScript build-info files. No binary assets exist in the owned safe set; installed/vendor/symlink targets are excluded, not recursively audited.

The accompanying `A12.json` contains a row for every file, including exclusions, with dependency split, exact target/preservation and blocker references. Full text reads were performed through dedicated reads and bounded Python text dumps; truncated dump prefixes were subsequently read. Searches classify edges, not a bundler/type/runtime proof. No application imports/evaluation, check/test/build/install, live network/provider/SQL/browser, environment/credential/current-data read, Git mutation or nested agent occurred. Only these two reports are written. Historical tests/reviews below are cited, not repeated or newly certified. Active peer source observations do not constitute dependency acceptance.

No assigned package directly imports Next or tRPC. That does **not** make its public root safe: CLI hashing imports `@homarr/auth` → `next/headers`/configuration; Icons search imports Common's mixed browser barrel; Docker root reaches env/singleton/discovery; analytics reaches ambient DB/auth/env; image-proxy reaches Redis/crypto/env/trusted HTTP. Workshop's advertised backend imports React Query hooks. No source or selected URL is relocated, rewritten or deleted by this audit.

## Concrete cuts and targets

Targets below are **proposed allocations**, not authorization to move files. `apps/backend` is the plan's candidate composition root; package-owned domain logic remains package-owned. One listener may still serve frontend assets, RPC and binary/SSE routes. Browser clients import contracts/query adapters only, never backend construction. Use the oRPC TanStack Query adapter for Homarr-native queries and TanStack Router for navigation/loading/prefetch; neither replaces binary HTTP, Workshop's external PocketBase protocol or local CLI execution.

### I — Icons

Keep injected `createIconSynchronizationService`, `IconReadScope`, parsers and `planIconSynchronization` as the single domain implementation. Proposed `apps/backend/src/services/icons.ts` supplies migrated request/job SQL scopes, real reference codec, clocks/bounds, current owner checks and owned trusted HTTP. Proposed `packages/icons/src/browser.ts` exports only picker contracts/arrangement/URL predicates/metadata; extracting pure helpers must not import `search.ts`'s SQL/fetcher chain or Node path/crypto. Proposed `packages/icons/src/url.ts` owns the exact `/api/user-medias/<id>` helper, reused by existing mapping and browser consumers. These subpaths are missing today. Common's actual `string.ts` contains normalization/ranking but has no `./string` package export; use a separately approved pure export, not the Common root as a browser/backend compatibility shim.

SQL remains authoritative for repository/icon/media existence, IDs, exact selected URL strings, original byte-derived local MD5 and replacement snapshots. Transaction-time checks must cover expected catalog, current selected references, missing local media, current authority/external disable and every compatible writer. Failed sources preserve old rows; all-source failure cannot become empty catalog or successful job. No same-MD5 local-file rebinding. Preserve all five remote catalogs, slugs, templates, case-sensitive extensions, checksums, licenses, ordering/ranking/group limits/count semantics. Public icon projection remains public, with no media-byte/creator exposure.

### P — Image proxy/private images/media

Proposed `packages/image-proxy/src/{contracts,service,response}.ts`: extract the existing `ForwardImageResult` and create/createMany/forward algorithms into an injected `ImageRegistrationService`; proposed backend `services/image-proxy.ts` owns store, CBC codec/HKDF/HMAC, key generation, trusted transport, grant/revision policy, clock and safe logger. Providers Plex/Immich/Tracearr/Gotify consume a narrow registration port preserving their URL/header inputs and opaque string outputs; no ambient `new ImageProxy()`, credential-bearing public URL or pass-through implementation.

The existing `image-proxy:url:<id>` encrypted URL/header and `image-proxy:hmac:<urlHmac>.<headerHmac>` identities have86400-second TTL and **are registrations, not image-body caches**. Under STACK-CUTOVER security state is SQL-backed: an accepted atomic-state adapter can back paired registration/dedup/expiry; it is not presently an accepted image-specific producer. Preserve null versus headers JSON/HMAC serialization, HKDF `sha256`/empty salt/`image-proxy`/32-byte key, issued IDs/paths, no TTL renewal merely on dedup hits, and128-item registration batching/yield. The current static key lives for the process, not per request; explicit secret/key-generation ownership must prevent accidental cross-key sharing. Dedup misses can race today and records are written separately; a stronger atomic pair is a proposed reviewed cut, not source-equivalence evidence.

Native binary `/api/image-proxy/:id` preserves upstream status,502 fetch failure,404 missing, null error body and `X-Homarr-Image-Proxy-Error`; success preserves buffered ArrayBuffer bytes and upstream Content-Type, not rasterization/base64 or streaming conversion. Source one-hour **public immutable** caching and lack of retrieval session check must be recorded, not automatically approved for private artwork. Registration/current retrieval/revocation and already-rendered lifetime/cache policy require explicit authority-owner disposition; do not invent a grant, casually require login, or widen anonymous access. Q18 affects upstream grant admission; TTL/opaque handle/type safety are not permission. Native media `/api/user-medias/:id` remains a separate public-read contract with `private, no-cache`, exact non-SVG bytes, actual SVG profile, sanitized-byte SHA256/base64url ETag, weak/list/`*` validators/304 without Content-Length, original MIME, sandbox CSP and nosniff. Stored upload bytes/MD5 are not sanitized serving bytes.

### N — Ping/network

Proposed `packages/ping/src/{contracts,service}.ts` and backend `services/ping.ts` supply `sendPingRequestAsync(url, signal?)` through a typed owned reachability transport. Preserve status/duration versus error union, monotonic duration,10-second header-fetch timeout and ping-specific untrusted-certificate behavior; never transfer its `rejectUnauthorized:false` into image/icon/integration trust. Existing source constructs a new dispatcher per request and neither consumes/cancels the response body nor closes the dispatcher; timeout ends when headers return. Add real request/body/dispatcher ownership and drain as an explicit reviewed lifecycle repair, not a fabricated full-transfer timing guarantee. Parent cancellation currently has no parameter. Direct `undici` import is undeclared in Ping's manifest; declare only if the new implementation directly retains it, otherwise use the admitted Core transport port. Runtime fetch implementation/shim choice stays with the transport owner.

### D — Docker

Preserve Dockerode, descriptors/parser/labels and pure color helpers. Proposed `packages/docker/src/{contracts,service}.ts` exposes explicit endpoint configuration, typed inventory/action/log primitives and async reset/disposal; backend `services/docker.ts` owns client/agent/TLS file resources and fan-outs. Root value exports must no longer acquire ambient env or singleton construction when a browser wants `ContainerState`/target/status. New pure `./contracts`, `./endpoint-descriptor`, `./labels`/discovery parser subpaths are absent; `./shared` exists and its Mantine/state imports are type-only, but colors are not a service contract.

Preserve endpoint id/name/kind/scope/source/capabilities, socket/tcp/tls union, socket paths, host/port, explicit plaintext `allowInsecure:true`, required TLS `caPath` and paired `certPath`/`keyPath`, initialization-failure isolation and legacy/default precedence. Do not include private cert/key file contents in DTOs/KV. `ENABLE_DOCKER` is a procedure-level gate today, not enforced by `getInstances`; preserve correct admin/demo/enable ordering. Reset currently drops arrays, not physical clients/streams. Replacement reset must fence/retire old generations, settle all late acquisitions and then invalidate inventory; no daemon restart follows. Preserve hidden-label semantics, Homarr/Homepage fallback, escaped source IDs, inventory filtering, per-target capability actions and log frame/1MiB/cleanup/error behavior. Native oRPC iterator/SSE delivery must own backpressure, cancellation and disconnect separately from cached inventory.

### A — Analytics

Use existing source snapshot service, not analytics root import. Proposed backend `services/analytics.ts` binds real SQL/schema/operators/SuperJSON CAS, source version/platform/uptime/provider/consent configuration and source-equivalent PostHog client; no SDK/provider work in this audit. Package `./contracts`, `./snapshot-properties` and narrow provider factory export remain absent. Source client factory has no module-load send but still belongs on server; report omits its baked-in ingest-key literal.

Consent, instance ID and `lastSuccessfulSnapshotAt` are durable SQL settings, not KV expiry flags. Preserve seven-full-day due behavior, period UUID, count/group/distinct/join/bucket fields, consent/external recheck, synchronous capture → awaited flush → settings CAS → sent. Source counts are parallel reads, not an atomic consistent snapshot; do not label them one without a reviewed SQL snapshot cut. Settings persistence failure after successful provider flush can return `failed` despite an external effect; no automatic retry or false rollback. One service's pending promise is database-authority-owned; dispose/drain before provider/SQL closure. Manual admin/guarded mutation and weekly hidden run-on-start/no-manual cron use the same service; neither public frontend SDK nor a fresh per-request service is parity.

### W — Workshop Homarr client only

Keep `packages/workshop/src/schema.ts` public schema/portable validation/URL contracts and the existing PocketBase wire algorithms. Proposed `src/transport.ts` owns the non-React `WorkshopBackend`; `src/query.ts` owns Query options/hooks/invalidation; `./client` should expose browser glue and `./backend` server-safe transport only after reviewed extraction. Today both `client.ts` and `index.ts` reexport the901-line mixed backend module. `baseUrl`/list/screenshot/record contracts must remain typed; no replacement Go service, collection/schema migration or fabricated authentication.

Preserve normalized public URL config versus separately configurable API/web URLs; screenshot filename/thumb encoding, multipart original File bytes/additions/removals and count/MIME/size bounds; expectedRevision and server-owned initial revision; listing400/404 fallback only, author/type/search/sort/pagination, comments/votes/report summary/admin moderation and hosted usage. PocketBase's GitHub popup/session store is **Workshop identity**, not Homarr admin/session authority. SSR/backend clients need request-isolated nonpersistent auth stores; never share the browser-default auth store/token across users. Frontend Query caches require base URL plus authority/account generation, cache clearing/abort on signout and current owner before callbacks; existing list/detail/report keys do not all include identity. Retain subscribeToAuth unsubscribe and8-second composed signal timeout where implemented; create/update and several account/mutation methods lack signal parameters, so ignored UI completion cannot undo a dispatched write. Preserve the frontend handoff's revision limitations and unavailable flows. Go/PocketBase `apps/workshop` is outside A12 and expressly unaltered.

### C — CLI/startup/build

Keep local CLI standalone, not a browser/oRPC command bridge. Proposed `packages/cli/src/{runtime,services}.ts` injects actual DB/auth-security/crypto/validation/config/output and closes native handles; `src/index.ts` remains executable bootstrap only. Existing public `index.ts` reexports a module invoking `void main()`: never import that barrel for a contract. Use existing `@homarr/auth/security` instead of the Next-bound auth root only after its transitive graph is admitted. Preserve user/integration flags, mutually exclusive selectors, empty/not-found messages, original local SQL selection/output/exit behavior, credentials-provider gates, bcrypt policy and session invalidation. Password writes/session deletes and recreate-admin multiwrites need same-authority atomic/compatible-writer disposition; source operations are separate writes, not already transactional. Usernames lowercase collisions and recovery concurrent-admin race need explicit outcome policy, not silent repair. Printed generated passwords/argument plaintext stay authorized local CLI behavior, never report/telemetry/browser output.

Harness-only argv path deliberately avoids loading DB/Auth; retain it. Preserve exact Docker image/container/volume naming, stable owner-only encryption-key file generation/exclusive create/race handling, repeated env flags, demo mode,7575→host port and `/appdata`, and stop-keeps-volume behavior. The source can force-remove a named existing container during run; reading it does not authorize running it. Harness child-process/stdout/secret boundaries are local CLI ownership, not Nitro KV.

Shipping cut is not complete: CLI esbuild Node CJS outputs `cli.cjs`, external bcrypt/cpu-features and native bindings; Docker still builds Next plus CLI, copies Next traced standalone, native SQLite/migrations and `/usr/bin/homarr`, and runs Node24.18.0. Existing run.sh migrates before startup, supervises/restarts Next, and owns nginx/internal-or-external Redis/shutdown; Next instrumentation starts jobs/WebSocket. Backend cutover must explicitly replace listener/task/stream initialization and supervision while retaining migration/restore/readiness/signal semantics. Root package version used by analytics and hard-coded CLI1.0.0 are distinct source contracts; supply built version metadata deliberately. No Nitro output/build/resource/native ABI compatibility was checked.
