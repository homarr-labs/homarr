## 1. Source-derived trust and routing, not invented configuration

Static source reads establish:

- `packages/core/src/infrastructure/certificates/files/index.ts:17–39`: the trusted CA bundle is `node:tls.rootCertificates` plus loaded custom `.crt`/`.pem` contents. `certificates/runtime.ts:7–11,28–40` supplies **one** `ca` array, separate hostname/fingerprint records and a material version. Custom anchors are not tagged proxy-only or target-only. No second store, permission or trust-role setting exists in these contracts.
- Legacy `http/request.ts:34–57` supplies this bundle (or the existing server-controlled CA override) to Undici `connect` and native HTTPS endpoint TLS. Native `proxyEnv` comes from ambient configuration in that legacy source; it is not read here. Installed `undici/lib/dispatcher/proxy-agent.js:114–131,194–220` builds outer TLS from `proxyTls` and inner TLS from `requestTls`, not merely `connect`. Legacy Fetch therefore does **not** establish explicit custom-CA propagation to both proxy stages. Retained pinned native source evidence in `implementation/trust.md:287–293` establishes endpoint CA does not reach initial native HTTPS-proxy TLS either. These are limitations, not an independent proxy trust policy.
- Frozen managed `http/runtime.ts:160–183` explicitly applies the **same effective CA** (`override.ca ?? material.ca`) to direct `connect`, `requestTls` and `proxyTls`. The default server anchor policy is therefore **SAMECA**: all approved roots may authenticate either peer, with each peer's own chain/identity verification. A target signed by an approved custom root is allowed even if that root also signs the proxy. Do not prune it to manufacture a “proxy root cannot sign target” policy.
- TLS identity is a different question. `http/tls.ts:33–42` grants only an exact hostname plus peer leaf fingerprint, after chain verification. Current managed Fetch also passes its custom identity callback to `proxyTls`; this is a real source difference from the required strict proxy boundary, **not** evidence that proxy exceptions are approved. The proposed native join must use ordinary `checkServerIdentity` against the configured proxy URL hostname/IP; target alone retains its accepted exact grants. Do not silently change the existing Fetch path in this allocation or claim its broader trust behavior accepted.
- Managed proxy settings are explicit `{ httpProxy, httpsProxy, noProxy }` strings (`runtime.ts:18–22,79–85`), not newly discovered DB/UI settings. No proxy certificate role setting was found in the inspected Server Settings/static environment-schema source. Managed construction copies these settings; no ambient environment read, injected global CA or new credential policy is proposed. Preserve injected lookup (`runtime.ts:171,215`), target DNS/SSRF caller gates and hostname-vs-address verification; do not import legacy `dns/init.ts` side effects into a resource leaf.
- Installed `undici/lib/dispatcher/env-http-proxy-agent.js:22–40,65–143` resolves HTTPS proxy with HTTP-proxy fallback and explicit noProxy matching (wildcard, case-normalized exact/suffix host, optional port, comma/whitespace entries). Explicit empty strings do not consult ambient values. That is **Undici's resolver**, not proof of native equivalence. Native `proxyEnv` types (`@types/node/http.d.ts:1485–1539`) do not specify a public resolver or proxy-TLS hook. Retained managed native checks cover only empty/wildcard/exact IP/host:port patterns, not the complete native resolver. No native private symbol, guessed option or new resolver policy is permitted.

**Consequences:** the feasibility fixture's distinct proxy/target CAs proved primitive separation, not server policy. Future production-default evidence must use the SAMECA bundle at both stages, including a valid cross-role signer positive, and reject a target whose signer is absent from that bundle despite an exact hostname grant. Separate-CA fixture negatives may remain seam evidence but cannot be called production policy. A normal replacement proxy leaf under an approved root and valid hostname must remain valid; no proxy pinning is introduced.

**D1 — smallest remaining trust question for the coordinator/user:** does an existing server-controlled _native HTTPS CA override_ replace anchors for both proxy and target (matching managed Fetch's effective-CA mapping), or remain target-only while the proxy uses unmodified `material.ca`? Legacy native proxy TLS never received this override, so successful legacy behavior cannot answer it. Do not choose here or add a field. Default SAMECA and lifecycle planning continue; override implementation/acceptance waits for a recorded answer. A custom target identity override never authorizes a proxy identity exception.

## 2. Minimal future join and mandatory ownership handshake

Conditional design only: preserve the existing native `ResourceHttpsAgent`, native request/response stack and actual Axios HTTP adapter. Delegate CONNECT parsing/status/socket delivery to declared installed Undici `Client.connect`; do not replace Axios with Fetch/Undici dispatch or select a production transport now. Ordinary no-proxy construction and source TLS/lookup/options continue through the accepted r3 native branch, unchanged. A new proxy branch is eligible only after routing/source and lease gates below.

1. **Request admission before asynchronous creation.** Extend the Agent's native request admission bridge to keep one lease per actual `ClientRequest`, including queued requests. Capture the request synchronously at admission/`createSocket` and pass that identity into the connection transaction before any await; the r3 `connectingRequest` field is only a synchronous association, not asynchronous shared state. Native `request(..., { signal })` and Axios's real per-request abort/destroy/close path cancel that lease. `request-signal.ts` remains operation-scoped; never copy the prototype's one AbortSignal per Agent or cancel unrelated requests on a shared client.
2. **Native queues/concurrency remain native.** Do not mutate queue arrays or serialize all callers in a new scheduler. Track admission through actual queued abort, free-socket reuse and new creation, respecting native maxSockets/maxTotalSockets, reuse and scheduling. Pending native creation and its Client transaction must count as occupied capacity until terminal settlement; cancellation of request A cannot close B's tunnel or free a slot while A can still deliver. Queue admission must reject after retirement even if a native queue would otherwise restart creation. Missing request association is a HOLD, not an unowned connection fallback.
3. **Register transaction before I/O.** Agent owns request/generation, cancellation lease, pending Client, connector invocation and physical-stream joins before dispatch. Smallest candidate is one owned Client per new tunnel, native Agent pooling target sockets; no new shared proxy-client cache. Check ownership/currentness before Client creation, dispatch and each continuation. All returned/callback/late streams enter the registry before inspection, destruction or delivery.
4. **Pinned initial-socket handshake or HOLD.** Installed Undici 7.29.1 `lib/core/connect.js:86–96,126–149` returns the initial native socket, while `types/connector.d.ts:33–34` declares `void`. Accepted feasibility observed this return; it is a source-version dependency, not a portable API guarantee. A future connector wrapper must establish transaction ownership before invoking buildConnector, capture its returned value as `unknown`, require the real native stream, attach physical-close ownership immediately, and reconcile any synchronous callback/reentrant cancellation with a single pending outcome. If callback, construction throw, end/close or retirement can escape the pre-registration handshake, **HOLD**; do not cast away the gap, patch library/native globals or replace the connector with a new stack. COMPOSITION/reviewer must accept exact installed source/version provenance before reliance.
5. **CONNECT handoff without cancellation gap.** Outer proxy TLS uses approved SAMECA anchors and ordinary URL hostname/IP verification before credentials/CONNECT. `api/api-connect.js:51–83` removes Undici's signal listener at handoff; `dispatcher/client-h1.js:530–564` detaches the socket from Client/parser ownership. The transaction's independent cancellation/stream-close lease must survive this interval and cover late deliveries. Require actual 2xx status before target TLS; 407/rejection/error never reaches the target. Capture detached ownership before releasing dispatcher ownership. Then register target TLS over that socket with accepted target anchors, identity grants/overrides and options; omit IP SNI without omitting IP identity checking. No parser, HTTP upgrade implementation or trust relaxation is added.
6. **Exactly-once native callback and physical release.** One terminal callback owner handles secure target delivery, abort, pre-delivery end/error/close, synchronous throw and late completion. Mark terminal before invoking the native callback. A throwing callback is retained as failure, not retried; any delivered/late stream remains owned and is destroyed when cancelled/retired. Request handoff releases only its pending-creation lease, not Agent ownership of raw/detached/TLS streams. Remove request listeners/wrappers on every terminal path without removing physical-close ownership or restoring over another owner's replacement handler.
7. **Invalidate/drain/quarantine.** Retire admission synchronously before aborting queued and pending requests; preserve material-generation fences and reject all old continuations. Join pending connector completion, cached Client destruction, raw/detached/target close events and native pool closure, including reentrant late registrations. `ownership.ts:107–152` already joins independent r3 streams beyond pool snapshots, but its destroy-throw catch currently rejects immediately: a future minimal correction must still start/join all available physical cleanup and retain the failure, never call `onReleased` on failure. A genuinely throwing/rejected destroy or uncertain close keeps a strongly owned quarantined record and failed retirement; elapsed timeout/`destroyed` flag is not physical settlement. Repeated disposal returns the same Promise, including rejection. Invalidate/dispose aggregation stays all-settled, while new material cannot resurrect a retired Agent. Preserve strict-eight Fetch cache, TLS context cache, coalescing/material-abort contracts, bounded dispatcher retirement and caller-owned dispatchers; no unrelated refactor.

The probe's release fault was injected **after** physical close. It does not prove genuinely failing destroy, callback throw, early end, multi-request isolation, queue reuse or managed invalidation. These remain evidence gates, not accepted guarantees.

## 3. Routing, Axios and whole-guard stop line

Before implementing a proxy branch, return source-backed exact native proxy selection/noProxy rules for the pinned Bun and relevant Node versions, including precedence, empty settings, HTTPS fallback or its absence, suffix/port/IPv6/IP handling and bypass cases. Preserve each existing client's source behavior; do not copy Undici rules into native routing by assumption or unify differences by policy. Without a usable public selection seam or an explicitly reviewed source-preserving local seam, keep the join **HELD**. A configured bypass is routing, not retry-direct fallback; TLS/auth/CONNECT failure never retries directly.

`runtime.ts:231–248` currently binds native Agents with `proxy: false` and refreshes them by material version/liveness. Installed Axios `lib/adapters/http.js:258–295,962–1139,1322–1335` retains HTTP-adapter native/follow-redirects selection and native request destruction on abort. Verify actual default managed clients select that adapter without supplying a test factory, replacing a transport or activating Axios's transitive tunnel-agent cache. Keep existing request transforms, headers/auth separation, errors, upload/download streaming/backpressure, size/compression limits, timeouts and caller overrides. Redirects require per-hop routing/noProxy and fresh request association, origin credential stripping, current trust checks and HTTP↔HTTPS Agent switching, including maxRedirects=0. Caller-supplied adapter/transport behavior is not silently claimed runtime-owned or broadened.

**Native plaintext HTTP through an HTTPS proxy remains an independent gap.** Default managed Axios uses the `node:http.Agent` created at `runtime.ts:85`, owned through pool snapshots without r3's independent connection tracker. Custom CA propagation to its initial proxy TLS and pre-pool cancellation/close ownership are unproved. Neither the HTTPS connector nor HTTP-proxy positives settle it. If pending creation escapes tracking or native HTTP lacks a bounded public CA/ownership seam, stop and return that limitation; no second agent architecture is authorized. **The entire Bun native HTTPS/Axios guard stays held**, not a per-path/protocol whitelist. Existing no-proxy behavior, including the guard's existing `noProxy === "*"` treatment, is not broadened.
