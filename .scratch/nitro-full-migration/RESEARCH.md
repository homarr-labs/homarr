# Full-feature Nitro migration research

## Destination

Prepare a capability-preserving migration specification and parallel implementation graph for the entire Homarr application on Nitro v3, Vite/React, TanStack Router and direct oRPC. The playable fixture proves a bounded seam, not full-product parity.

Canonical map: [Find the route to a lightweight Nitro Homarr](https://linear.app/ajnart/issue/AJN-482/find-the-route-to-a-lightweight-nitro-homarr). The user's latest direction authorizes comprehensive research and preparation. Implementation follows reconciled decisions and an approved full migration spec, not this inventory alone.

## Shared research contract

1. Load `research` and `codebase-context`. Read the live map and the assigned ticket or local question. Consume relevant existing research rather than repeating settled stack investigations.
2. Inventory the current source exhaustively within the assigned area. Cite source paths/symbols and first-party documentation URLs. Record actual checkout provenance and distinguish current code from earlier reports and the uncommitted experiment.
3. Classify each capability as reusable, adapter needed, or replacement needed. Preserve behavior and durable data, not necessarily implementation libraries. Every existing capability gets a target seam and acceptance obligation; missing evidence is an explicit unknown.
4. Propose independently demonstrable implementation batches, shared interfaces, exclusive ownership and genuine blocking edges. Specify what a worker can port before another worker finishes and which central registrations remain single-writer. Avoid assuming that all endpoints require a full service rewrite.
5. Write one Markdown note in `research_notes/Homarr full Nitro migration/` at the assigned filename. Include coverage reconciliation, recommended seams, primary-source library evidence, human decisions still needed and any unassigned capability discovered. Recommendations are not human decisions or proof of compatibility.

Use installed declarations/source and official versioned docs. Context7's quota failure is already recorded; repeated calls are not a new evidence source. All libraries may change, including i18n, when necessary; retain current catalogs, formatting, locale semantics and all application features. Keep server secrets and policy out of browser graphs.

Research is read-only except each worker's own note. Keep the existing branch/worktree and leave manifests, application code, real appdata/environment/credentials and Git history untouched. Run no builds, installs, application probes, tests, lint or typecheck. Keep the published fixture container and human browser session running unchanged at `http://127.0.0.1:3100/boards/public`.

## Synthesis gate

Coordinator reconciles these notes into a feature/endpoint parity ledger, library and package-boundary decisions, and a contract-first parallel task graph. Open wayfinder decisions remain open until evidence and the human's required tradeoffs are recorded. Full acceptance requires observed behavior per feature; inventories and the current fixture never establish that every feature already works.
