## Owned files and candidate interfaces

- `base/creator.ts`: same explicit lazy creation entries, generic kind-specific return types and HTTP-auth dispatch. Factory logs now use the operation's injected sink, without importing the environment/filesystem-initializing global logger or logging an upstream failure cause.
- `base/integration.ts`: existing secret helpers, native/declared HTTP-auth behavior, URL-prefix/external-link/WebSocket behavior and abstract testing API retained. Connection testing now delegates to explicitly scoped `transport.testConnectionAsync`; no default certificate store/DB/agents are created from globals. Missing runtime resources fail closed rather than restoring Redis/legacy initialization.
- `base/errors/decorator.ts`: original prototype wrapping and provider-specific handler ordering retained; default Zod/JSON/Fetch handlers and logging are injected through runtime resources. Candidate v2 also recognizes sanitized shared-transport errors before those handlers and creates the existing `IntegrationRequestError`, `IntegrationResponseError` and `IntegrationParseError` classes with credential-free native-compatible cause fields. Unknown error causes are replaced with safe messages and new stacks. Normalized errors remain internal server domain objects; exported executor failures never retain raw causes/stacks. Host must supply the existing ordered defaults for other provider/SDK errors before claiming complete diagnostic normalization.
- `base/session-store.ts`: existing `createSessionStore<T>(integration)` provider call shape survives through request-local resource lookup, with an optional explicit second resources argument. Same envelope type/version and keyed ID/URL/sorted-kind/value configuration fingerprint. Codec/crypto are injected; unsupported, corrupt and mismatched envelopes remain null. Provider TTL is passed unchanged; writes remain best effort and failures are reported without raw errors. `SessionStoreBacking` requires `setIfCurrentAsync`/`removeIfCurrentAsync` so stale operation/session clears cannot overwrite a newer configuration; backing owner must actually implement atomic fencing, expiry and lifecycle. No Redis import/creation remains here.
- `base/test-connection/test-connection-service.ts`: existing rich error-category handling retained, with explicit `TestConnectionResources` for TLS options and authorized certificate diagnostics. Unmanaged `tls.connect`/global certificate lookup were removed. Trust owner must implement bounded, abort-aware certificate inspection and resource cleanup, not a new general TLS bypass.
- `runtime/contracts.ts`: `IntegrationConfiguration`, `IntegrationExecutionContext`, `IntegrationRuntimePolicy`, resource/log interfaces and discriminated shared/owned testing leases. Configuration/trust identities are opaque producer-issued revisions, not fabricated hashes or DB schema changes.
- `runtime/context.ts`: request-local AsyncLocalStorage binds explicitly injected resources around the actual transport scope. No global mutable default, no fallback key, no app/environment/DB initialization. This is not an authentication helper: low-level callers still need authorized secret resolution.
- `runtime/executor.ts`: `createIntegrationRuntime` composes real lazy factory calls with injected policy/resources. Native operations require explicit query/interact authority; Stats uses query; arbitrary HTTP authentication and native tests always use full. Policy executes before secret resolution and before client construction; snapshot/current checks surround secret resolution and results. Candidate v2 repeats live authority, configuration/trust/current and signal checks after resource preparation, after transport-scope entry and after native factory settlement, before admitting provider/native/HTTP-auth/test work. Signal is also checked synchronously at invocation; final result fencing is not used as a substitute for admission. Request abort/deadline returns promptly, while pending work and shutdown ownership remain until physical settlement. `closeAsync` denies new work, aborts operation scopes, then drains existing work without pretending uncancellable SDK work finished. Native callbacks are trusted server-owned code, never an exposed user-selected method dispatcher. Generic operations are not cached/retried and no new coalescing policy is inferred. These gates do not roll back already-admitted upstream mutations or replace the real producers' per-request/config/trust/session fences.
- `runtime/executor.ts` also provides safe `IntegrationRuntimeError` and `IntegrationConnectionResult`: connection category/status/request-code plus authorized public certificate PEM/fingerprint where present, never raw URL/cause/request body/cookies. `getHttpAuthenticationAsync` deliberately returns server-only derived credentials; API/Custom JSX must consume privately and apply their existing response redaction rather than expose this object.
- `runtime/stats-transport.ts`: candidate extraction of existing native Stats Fetch/Axios transport/context behavior, usable with unchanged real provider modules. Preserves compiled relative provider paths/base prefixes, stored header/query precedence, no redirects, Axios selection, 16-KiB authentication-header bound and discarded auth bodies; adds scoped cancellation checks and sanitized transport failures. It is not a second Stats registry or provider implementation. Axios transport cannot silently fall back to Fetch. Native parsers remain source-owned.

## Consumption evidence and limits

The unchanged real `minifluxStatsProvider` runs through the new transport context and authorized executor's injected Stats hook, using synthetic injected Undici responses. It observes `/prefix/v1/feeds/counters`, saved `X-Auth-Token`, scoped signal and redirect rejection; `read=9`, `unread=4` are actual source parser sums. Negative counters are rejected by the existing parser. This proves a real provider module can consume the candidate boundary, not that the unchanged `StatsIntegration` wrapper or native factory's Miniflux constructor has been mounted into Nitro.

The real factory is the executor's default/native constructor, not an injected 89-kind mock. Existing Stats dispatch is deliberately a dependency hook so the accepted source-owned Stats service can bind the trust scope without eager all-provider/global imports. The helper is candidate extraction: the Stats wrapper owner must switch its shared request methods to consume it and remove the old duplicate transport glue after acceptance. Mock class/data/widget fixtures remain entirely unchanged/read-only; no new Mock implementation was added and its full stateful methods were not executed here.

Synthetic session checks use explicit disposable AES-256-CBC/HMAC resources and a simple JSON codec for a string token only. They prove envelope/config/TTL forwarding/fencing behavior, not actual production SuperJSON Date preservation, durable backing expiry, key continuity, restart or SQLite restore. Production adapter must inject existing SuperJSON 2.2.6 and accepted secret codecs, preserving their byte/envelope representations. Migration-time private sessions must not regain authority from archived state.
