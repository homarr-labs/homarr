## Persistent SQL backing boundary

The STATE review accepted the necessary `AtomicStateBacking` conditions; this contract is unchanged by v2. Concrete implementation and both-engine acceptance remain DB-owned and are required before production mounting. This lane supplies no SQL adapter, memory production implementation or generic Nitro KV adapter claiming CAS/security guarantees.

- `readAsync(keys, operation)` returns `{ now, values }`: one consistent observation, explicit null for missing/expired keys, Unix milliseconds, authoritative backing clock. Expired values are logically absent even if physical cleanup has not run.
- `mutateAsync({ conditions, writes, readKeys }, operation)` returns `{ applied, now, values }`. Test all conditions against the effective unexpired values, then apply all writes or none, and obtain requested post-mutation reads in the **same atomic transaction**. On condition failure make no writes and return the current requested reads. Raw string equality is intentional: lease tokens are raw strings; payloads are SuperJSON strings.
- Writes are discriminated `set` with TTL milliseconds or null for non-expiring state, `delete`, and Redis-compatible signed integer `increment` with refreshed TTL. Missing/expired increment begins at one; invalid/overflowing counters must fail without partial mutation. Conditions can contain an owner token, a revision/CAS value or null for NX, plus both observed global/scoped generation values.
- TTL is calculated at the atomic observation/commit boundary using the backing clock, not a delayed client scheduling timestamp. Expired owners cannot renew, delete a replacement, or write payloads. Fenced multi-write checks cannot be split into independent SQL/KV operations.
- All methods receive an abort signal and absolute deadline. Operations are guarded at 500 ms; the source response guard remains 750 ms above that. Do not queue/replay writes after outage. Check abort/deadline after waiting for transaction ownership and before commit; roll back on cancellation/error and settle promptly. A commit that occurred before the deadline but whose response is lost is still ambiguous, not proof of rollback; lease acquisition uses token-fenced best-effort cleanup.
- SQLite must use the persistence owner's explicit direct driver and a synchronous atomic callback, with no network awaits inside its transaction. PostgreSQL must hold one checked-out client for its transaction. Parameterize keys/values. No async SQLite transaction callback, shared-session BEGIN interleaving, new default PRAGMA, or physical state table is prescribed/created here.
- One active backend owns these factories. Stop/maintenance must abort the supplied channel lifetime signal, stop generations/fanout/statistics/handlers, drain their bounded work, then close the backing. `createStateGenerations.stop()` aborts its own operations. The factories never close an injected DB resource or start a new polling fleet.
- Restart recreates only volatile listeners, read-coalescing maps, local cache and pending local repair metadata. Persistent payloads, last-good snapshots, generation rows and remaining expiry require the SQL owner. Leases are not imported as valid active owners. Restore must reconcile/invalidate private state and epochs before readiness; that is not implemented here.

Full integration invalidation now asks the backing to advance generation, expire that counter, delete the encrypted integration session and delete the stable statistics snapshot together. This strengthens the legacy two-step snapshot deletion and needs owner review. Response-only invalidation does not delete credentials or statistics. Overflow repair advances the family's global generation; it does not pretend to recover untracked per-integration secret deletions. A full invalidation failure is surfaced, and domain policy must remain fail-closed where it relies on that deletion.

## Failure and capability coverage

- Response-store failure disables that request's shared adapter and falls back to the existing bounded L1/upstream behavior. It never queues payload writes. This is cache outage behavior, not permission authorization.
- Statistics-store/generation unavailability remains an explicit error, as in source; no manufactured local durable last-good value or zero/error-free snapshot is returned. Provider failure with a usable store retains real prior values/timestamp and records retry/error/stale state.
- Generation repair is source-owned bounded invalidation repair, not a delayed queue of provider/security payload writes. A process restart loses pending local repair metadata, exactly the remaining source weakness; durable outage/restore reconciliation must be accepted separately before production.
- L1 preserves the source behavior in which an already-running pre-invalidation caller can receive its old result, while that result cannot repopulate newer cache state. The existing regression explicitly asserts this. Current authorization/configuration checks and final response cancellation/revalidation belong to the consuming protected provider flow; do not claim that cache primitives alone deny private responses.
- Latest fanout is not log replay/history and does not invent delivery/exactly-once guarantees. Logs and SampleHistoryStore remain #19-owned. Lists/ping registry/history are not retired; original channel capabilities remain untouched but are not yet Redis-free.
- Preview/configuration/limiter/session/image policies remain domain-owned. The conditional multi-key backing supplies a possible primitive, not a duplicate implementation of those policies.
- The unused generic queue remains a legacy export with JSON-array read/modify/write semantics; no discovered caller, atomic dequeue, durable retries or exactly-once guarantee is claimed. No retirement or replacement scheduler was introduced.
