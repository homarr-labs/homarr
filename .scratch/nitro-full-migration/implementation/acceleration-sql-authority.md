## Frozen candidate API

`createSqlAuthorityReader(configuration)` owns admission bookkeeping, private credential witnesses and read leases over the supplied existing main `PersistenceRuntime`. It does not construct/open/close another SQL resource. The returned API is:

- `admitOpaqueSessionAsync(token, operation)` and `admitApiKeyAsync(header, operation)` return anonymous or an authenticated **read snapshot** with an immutable `PolicyIdentity` lease.
- `lease.assertCurrentAsync(operation)` performs a genuine new credential/membership/grant SELECT, compares the exact credential/provider and canonical membership/expanded permission sets, and rejects stale evidence. It is not a COMMIT permit, lock, revision or revocation subscription.
- `lease.releaseAsync()` aborts that lease's admission and awaits its started native reads/revocations. `reader.closeAsync()` aborts new admissions and drains admitted SQL, bcrypt work and lease reads/revocations. The runtime owner must then separately drain/close its DB resource. Never close the reader from inside its own admitted operation.
- `revokeCredentialAsync(lease, operation)` accepts only a live lease privately issued by this reader. For an opaque-session lease it conditionally deletes **that exact authenticating session**, not another credential or all user sessions. SQLite uses G3's synchronous bounded immediate transaction and native `changes`; PostgreSQL takes the actor parent `FOR UPDATE` before the bound conditional DELETE and consumes native `rowCount`. Witness user/provider plus original session expiry are matched. Zero rows reports not-current. Confirmed deletion invalidates matching local leases and awaits their in-progress reads/revocations. Already-dispatched ambiguity invalidates/drains local matching leases and returns sanitized `REVOCATION_COMMIT_AMBIGUOUS`; there is no automatic retry or false rollback claim. API-key leases instead fail closed with `COMMIT_AUTHORITY_JOIN_REQUIRED` before SQL: legacy API-key deletion requires current admin permission, and the all-writer COMMIT protocol is absent. The exact hash/user/provider-bound API-key DELETE is implemented as an unmounted physical SQL candidate, not an executable admin bypass or new self-revocation policy.
- `commitAuthority` is explicitly unsupported, with exact join `same-native-transaction-credential-principal-grant-locks-and-validity-through-G3-dispatch`. `requireCommitAuthority()` always throws `COMMIT_AUTHORITY_JOIN_REQUIRED`. No permissive callback or no-op assertion fills this join.

All operations take the caller's real `signal` and finite absolute `deadlineAt`. Lease reads/revocation cannot extend the original admission deadline or the verified session host validity bound; another request requires fresh admission. Root and lease lifetimes are joined into G3 native execution; there is no timer race standing in for acquisition/statement/rollback/release settlement. Ordinary runtime defaults and G3 are unchanged. Single-SELECT read snapshots run inside bounded native transactions: SQLite consequently acquires its immediate writer admission even for this read candidate; PostgreSQL does not infer repeatable-read/READ COMMITTED or claim locks protecting later work. Neither read transaction contains domain writes. Invalid rows/unknown stored permission keys/oversized joined snapshots fail closed rather than return a partial principal.

## Source semantics and explicit configuration

The reader preserves existing `session.session_token` opaque lookup, exact `session.user_id` mapping and engine-specific stored expiry (SQLite timestamp milliseconds; PostgreSQL timestamp). It reads current actor provider, complete `groupMember` membership and joined `groupPermission` values in one native statement snapshot with one materialized SQL clock observation. Distinct global permissions are expanded with the actual `getPermissionsWithChildren` algorithm used by legacy callbacks; no implicit everyone/admin membership is manufactured. Profiles, password hashes, emails, names and provider tokens are not returned.

The API-key branch preserves the legacy exactly-two-part `id.token` format, queries the existing `apiKey` row, and calls the same `comparePasswordsAsync` bcrypt implementation outside the SQL transaction. A second SQL snapshot after bcrypt must still match the exact stored hash/user/provider before it returns current membership/grants. API keys have **no stored expiry**; the legacy display-session one-day timestamp is not an authorization expiry and is not copied here. Legacy `apiKeysRouter` create/delete are admin-only; this candidate never downgrades deletion to possession-only authorization. No key issuance/rotation, password verification replacement, AuthJS login, JWT, provider callback or new table is implemented.

There are no fabricated defaults. Constructor configuration requires explicit branch selection, snapshot row bound, resource lifetime and `credentialSqlLogging: disabled-by-resource-owner`. The latter is a required resource-owner obligation: frozen runtime does not expose logger inspection, so this declaration is not independent proof that its logger is disabled. Before any disposable SQL/host consumption, the owner must prove it supplied the actual runtime configured with credential-query logging disabled; otherwise do not construct this candidate. This source adds no logging and removes native SQL error/cause text from outward errors.

Opaque sessions additionally require explicit `approved-stored-expiry-reader` configuration with a finite nonnegative accepted maximum absolute DB/host clock skew. The candidate rejects missing/expired sessions and unsupported clock observations, and exposes a conservative host validity bound `storedExpiry - acceptedSkew` alongside stored expiry. There is no issuance duration, renewal policy, accepted skew default, authority epoch, counter or production Q16 choice. This is a configurable candidate only; Q16's owner must accept clock/expiry/transport semantics before enabling this branch. Its signal is not an automatic wall-clock-expiry timer or cross-process revocation feed: each private read/delivery requires a fresh awaited assertion and lifetime check; no assertion may be treated as authorization for a subsequent mutation.

Caller request transport/header-cookie precedence, origin/CSRF enforcement, approved branch/config provenance, demo/config pinning, HTTP private-output cancellation and logout response remain host/authority joins. Credential values and hashes stay closure-private and are absent from lease DTOs, errors and this handoff. Leases are server-private resources, not RPC DTOs.

## Exact missing COMMIT/writer join

No all-enabled-writer protocol exists in the frozen sources, so media, Group2, restore and other protected mutations cannot use these snapshots as COMMIT authority. Future allocated DB work must reacquire the credential and actor facts on the **same** native transaction as its domain writes and retain them through G3 dispatch. SQLite must reread synchronously under immediate admission. PostgreSQL must establish suitable fresh-read isolation, lock canonical user parents before credential/membership changes, lock exact credential evidence, lock group parents in canonical order and then reread the complete grant set. Empty/new membership/grant sets require the parent-writer protocol, not locks only on rows already present. Actual verified session validity must bound G3's deadline before entry; API keys acquire no invented expiry.

Every enabled session create/renew/revoke/cleanup, API-key create/replace/delete, actor/provider/account mutation, user deletion/cascade, membership update, group-grant save/delete, group deletion, local/everyone/LDAP/OIDC reconciliation, setup/registration, background and restore writer must join or remain unmounted. This lane's exact credential revocation is a source candidate for its one conditional deletion, not proof that those other writers comply. Maintenance/resource replacement requires actual host abort/drain rather than relying on row locks against a replaced DB. No generic currentness callback, claimed revision or optional permissive writer setting is provided.
