### Named-section mapping fact, then our stricter fence

Retained B's Mach-O DataStart chooses the first section named `__go_buildinfo` and returns its virtual Addr/Size; otherwise it falls back to a writable segment. DataReader instead finds the first non-`__PAGEZERO` segment containing the address in its **file-backed** Addr..Addr+Filesz range and reads via segment offset. F creates segment readers at `(Offset, Filesz)` and section readers at `(Offset, Size)`. Thus B does not simply read section.Offset and trust it; its virtual-to-file path must be reconciled. [B]522–554; [F]459–468,525–528.

**Proposed narrower policy, not upstream behavior:**

- Thin64 only, with byte order chosen by exact magic, never guessed. Optional further arm64/TypeExec restriction is source-defined but requires explicit M selection; package name alone does not establish the observed CPU/type. Reject32/fat/ELF/PE/XCOFF/Plan9 or unsupported magic; no first-fat-arch selection or generic container library. [H][B]124–162.
- Bound full32-byte header and command extent within the future exact-size input. Bound Ncmd by available command bytes/minimum8 before looping or allocating. Require exactly Ncmd envelope advances to consume Cmdsz; reject truncation, zero/undersized command lengths and arithmetic overflow. For Segment64, after helper acceptance require size exactly72+80*Nsect; this equality/absence of trailing command payload is our stricter policy, not a check F performs.
- Inspect only load envelopes and Segment64/section records; no dylib/symbol/relocation/DWARF payload reads, decompression or resolution. Nonmapping command bodies can be retained as bounded opaque bytes under an explicitly reviewed structural-subset contract, not certified semantically valid Mach-O. Unsupported command interpretation HOLD, no expansion. A32-bit segment command is unsupported. Do not chase arbitrary record offsets.
- Require exactly one named section, preserve all relevant raw names/record fields, and reject ambiguous names/ownership. Require target name's fixed16-byte field to be exact `__go_buildinfo` plus two zero bytes; for owner names, require reviewed printable-byte/NUL-padding rules. F's first-NUL/no-NUL acceptance does not mandate this restriction.
- For section in owner segment: nonempty Size; section name's Seg agrees with owner Name; Addr>=seg.Addr; delta=Addr-seg.Addr; delta+Size<=Filesz and<=Memsz; segment.Offset+Filesz<=inputSize; section.Offset+Size<=inputSize; section.Offset equals segment.Offset+delta. Use checked unsigned arithmetic before subtraction/addition/conversion. Exactly one non-PAGEZERO file-backed mapping must cover the entire selected interval; competing/intersecting mappings for that interval HOLD.
- File-backed Size, not zero-fill guesses. The selected Section64.Flags/segment Flag meanings are not defined by these bodies: a zero-only supported subset can honestly HOLD on nonzero values instead of importing unseen flag meanings. Known Mach header flag values are enumerated in H208–230; unknown bits HOLD if that flag field is interpreted. Preserve uninterpreted fields rather than attach invented semantics. Size/offset/VM bounds must hold even when flags are zero.

These are proposed constraints, not a promise that the unobserved frozen binary conforms. BigInt-width checks should precede any future Number conversion; no32-bit JS bitwise arithmetic on64-bit addresses/lengths. No extra pointer/offset scans or whole-file strings search. [P]84–107.

## 3. Header /inline strings /Uvarint

Retained B supplies magic14 bytes `\xff Go buildinf:`, alignment16, header32; pointer-size byte14, flags byte15; bit0 is pointer endian, bit1 selects inline. Inline mode reads version then module string immediately after header, each Uvarint byte length followed by that many bytes. In inline mode B does not validate pointer-size byte or use endian bit to decode the Uvarints; unknown flag bits are not rejected there. Version must be nonempty. [B]55–63,191–270,284–318.

U gives complete unsigned decoder semantics:7 low payload bits per byte, least significant first; high bit continuation; at most10 bytes; tenth terminal payload<=1; n>0 success, n=0 insufficient input, n<0 overflow. Exactly10 all-continuation bytes returns n=0 in Uvarint when the supplied buffer ends there; an eleventh supplied byte returns overflow before using it. Both outcomes HOLD. Signed zig-zag Varint is not the inline string-length decoder. [U]7–25,32–37,62–87.

**Proposed narrow policy:** require section.Addr itself16-aligned and header/magic exactly at section.Offset, with no rounding or search within the section. Do not implement B's first-aligned-match searchMagic, writable-segment fallback or arbitrary strings scanning. Misalignment/displaced header produces LOCATION_UNSUPPORTED_HOLD, not a search retry. For inline require flags bit1 and no bits outside0/1; preserve bit0 and byte14 as raw header data. Do not assume byte14 is8, or bits0/1 agree with container endian: inline decoding ignores those fields in B. Reject pointer mode before attempting pointer dereferences. Header remainder is retained, not defaulted or interpreted as pointers. [B]191–258,337–411.

Bound both prefixes and strings to the reconciled named section, not just the containing segment. Use at most10 available prefix bytes; require terminal success and unsigned64 range; no truncation/wrap/clamped lengths. Reject length exceeding remaining section bytes or a reviewed evidence budget before allocation. Require canonical/minimal prefix if M chooses that additional restriction: Uvarint accepts overlong encodings, while PutUvarint supplies the minimal encoder form. Preserve raw prefix/value/positions. Leave trailing section bytes uninterpreted unless a separately accepted padding rule is supplied; no trailing-zero assumption. [U]49–87; [B]284–318.
