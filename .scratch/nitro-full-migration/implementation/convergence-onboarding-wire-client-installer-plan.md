## Token/cache gate across async SDK headers → fetch

The missing temporal seam cannot be closed by caching a token in headers and incrementing pending only in fetch. Installed `@orpc/client` `dist/shared/client.Bstqyaro.mjs:44–80,102–134` awaits headers, then finishes encoding/transport, then awaits SDK response decoding. Public `dist/shared/client.BjbdW5Rj.d.mts:60–81` exposes a whole-call interceptor; `dist/adapters/standard/index.d.mts:41` exposes async headers; Fetch declarations `dist/adapters/fetch/index.d.mts:26` pass options/path into the actual fetch override.

Required finite sequence:

- Whole-call interceptor admits exactly one call and publishes its pending completion before invoking SDK `next` once. Use a unique **locally constructed client-context object** privately associated with its call record, preserved through SDK copies of options. Headers and fetch resolve that same context association; never identify calls by shared signal/path/token or caller-supplied authority. This is local transport accounting, not a server permission receipt. No input/secret is stored in that context.
- Async headers joins the single owner GET generation, checking caller signal, owner generation, origin and token expiry. A GET is published before fetch; its token becomes reusable only after actual status/body validation and the same generation remains current. Consumers awaiting one GET have separate abort/ref ownership; one consumer abort cannot discard another's admitted work. No automatic GET retry.
- Under the same owner gate, reserve the validated token generation **before returning headers**. Count this reserved-not-yet-sent call against refresh exclusion. Refresh cannot start while any reserved/sent write exists; no write reserves an older token while a cookie-replacing GET is in flight. Expiry/reset marks the cache unavailable immediately but waits old admitted writes before a new GET. Browser expiry is defensive UX, not HMAC validation or server deadline authority.
- Fetch resolves the same reservation, rechecks caller/root signal, generation, origin, exact POST endpoint/path and token expiry, then publishes/starts one actual fetch with SDK body/headers/signal, same-origin credentials and redirect:error. Preserve the exact GET token in `x-homarr-csrf-token`; Cookie/Host/Origin/Fetch-Site remain browser-owned. SDK packet/void/json/none serialization is unchanged.
- If encoding or a pre-fetch check fails, release the unsent reservation in whole-call finalization. If sent, retain its reservation through fetch and SDK finite body decoding, not merely Response-header fulfillment. Track the actual returned Response and any required unused-body cancellation without clone/manual RPC parse/second read. Claim uses the same reserve→POST→HTTP-body-settle rule. Drain genuine task/cancellation settlements before releasing refresh exclusion; pending call refcounts and route refs are distinct.
- Abort/reset stops admission and clears token usability, **not** a sent call's pending accounting. A rejected fetch, failed body/cancellation, locked reader or unknown outward result never proves server/socket/native settlement. Retain unknown/nonretryable classification; do not clear its gate by timeout, abandoned JS waiter or finally alone. A same-origin replacement must remain held if the required old physical settlement cannot be established. Current Fetch/Bun source proof does not supply the missing stronger observation; runtime/browser transport review must resolve it before claiming this barrier implemented end to end.

This is one narrow owner/gate and SDK interceptor, not an alternate HTTP stack. Successful local fetch/body settlement remains browser-observable transport completion, not proof of D's server physical terminal or native COMMIT. Other tabs/document replacement may rotate shared cookies; this per-router owner cannot claim cross-document cookie atomicity. Such failures remain unknown/error without automatic refresh-and-resend or implicit claim reacquisition.
