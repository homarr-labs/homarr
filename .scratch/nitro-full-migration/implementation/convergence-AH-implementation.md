## Finite work and publication boundary

Input body is bounded by the actual configured issuer body byte budget before the real RPC handler consumes its finite reconstruction. Native BackendContext still carries the original request; reconstruction preserves original URL/method/headers and real body bytes, not a rewritten host or fabricated request identity. Output is bounded by explicit `maximumResponseBytes`. Both actual readers cancel on joined signal abort and await pending reads, cancellation and closed settlement. The real handler and scoped native settlement are awaited; abort is never reported as their physical completion.

The application guard checks the real lease/main before returning the response and again before each body enqueue, including post-await cancellation checks. Cancellation publishes termination before draining pending reader/guard work and releasing the request. Initial publication failure cancels/drains owned output before returning only a new sanitized response with no accumulated effects. A failure after HTTP return terminates the retained body; it cannot replace already published headers/bytes. No atomic DB+HTTP delivery, client receipt, instant cross-process revocation or write-through-COMMIT guarantee is claimed.
