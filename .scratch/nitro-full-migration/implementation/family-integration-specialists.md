## Owned transport and common surface

`protocol.ts` uses the existing explicit `IntegrationInput` and `IntegrationRuntimeResources`. Ordinary operations enter the genuine supplied `transport.runAsync` and acquire its testing-shaped HTTP lease through the existing declared `transport.acquireTestingAsync`. The correction replaces `withIntegrationTestingAsync`'s masking `finally` with explicit callback-outcome and owned-release handling, retaining both exceptions when release also fails. Shared leases are not released. An owned lease is released only after callback and compound child work settle. Every HTTP request uses that lease's actual Undici fetch and dispatcher; no global/Core fetch, agent, Redis, environment, logger, SDK transport, or mock service is constructed.

`SpecialistHttp.responseAsync` keeps body consumption inside the lease and composes operation signal, deadline, optional source request timeout and caller signal. It awaits cancellation of untouched bodies and attempts cancellation of a locked body after callback failure. A cleanup rejection retains both callback and cleanup failures in a protected aggregate. Successful used bodies are not cancelled merely because Undici leaves its reader locked after a completed read. All requests explicitly use verified Undici `redirect: "manual"`; returned 3xx, opaque redirects or already-redirected responses are protected redirect-policy holds before consumption, with untouched-body cancellation awaited. No follow, redirect-location read or string-based redirect inference exists. Fan-outs settle siblings before propagating critical failures. Abort remains an error, not a successful fallback. These callbacks and cancellation requests do not establish physical settlement of a noncooperative provider or pool; that remains the frozen transport producer's obligation.

All protocol classes inherit source-shaped `publicIntegration`, `getHttpAuthenticationAsync`, and `testConnectionAsync`. Declared authentication reuses the original public definition resolver. Overrides are explicitly owned below. Connection testing uses the genuine supplied `transport.testConnectionAsync`; only classified ordinary callback failures enter the existing native-error bridge. A callback critical failure is retained independently and rethrown even if that service returns a result; unexplained outer testing failures remain protected ownership uncertainty. Only Ntfy and Gotify expose `testingAsync` publicly, matching their sources. Testing input and transport admission are not principal or interact authority.

Ordinary positively classified provider errors retain safe request/status/JSON-parse categories. Unknown acquisition, callback, ownership, cancellation, redirect or retirement failures are not sanitized into ordinary optional-provider failure. Protected aggregates retain actual exceptions for the ownership boundary, not for public serialization or logging; acquisition/body parse wrappers retain original failures in non-enumerable fields. Logs use the supplied runtime metadata logger and omit credentials, tokens, feed URLs, upstream bodies, raw provider errors, and user-supplied event labels. iCal's status-test result deliberately uses the public configured integration URL, never its private feed credential. Source notification text/contentType is retained for the existing downstream rendering/sanitization boundary; this lane does not declare arbitrary notification markup safe.

`interactAsync` always throws `SpecialistBranchHeldError("interact-authority")` before invoking its candidate callback. Anchor PATCH and Gotify DELETE retain source algorithms behind that refusal. No context/DTO flag can enable them. No new control is inferred from a read method.
