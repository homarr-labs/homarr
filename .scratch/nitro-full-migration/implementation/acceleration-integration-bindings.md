## Concrete source adapters

- `native.ts`: `createOwnedIntegrationBindings<TPrincipal>` constructs the actual frozen `createIntegrationRuntime`, with real source factory instantiation on native operations and the real `StatsIntegration`/`statsProviders` on Stats execution. No replacement provider classes, fabricated controllers, demo results, parallel business registry, global legacy Stats guard, or legacy client fallback. Native methods preserve query/interact/full authority selection in the frozen executor; source-owned callbacks remain private trusted server code. Testing adapters return the actual source class through an owned runtime lease; the management client is only the source test operation's safe projection, not a stand-in client implementation. Testing factory calls require the exact acquired runtime and HMAC-matching input, and transport admission rechecks the actual snapshot, host test authority, trust version and input fingerprint. Generic factory return types remain `IntegrationInstanceOfKind<TKind>`.
- `configuration.ts`: performs the genuine `snapshot.db.query.integrations.findFirst` with saved secrets and app relation using the supplied actual table and operator. Captures ID/name/kind/URL/app URL, ciphertext and producer-issued configuration revision; HMAC binds those fields without decrypting during capture/currentness checks. Secret resolution decrypts only after the frozen runtime's authorization gate, verifies the captured identity and re-reads current SQL/trust. Missing rows, changed metadata, deleted/app-changed configuration, changed credential bytes/revision or trust version fail closed. Native callers may deliberately use null external URL; a non-null external URL must equal the saved app URL, and app changes still change identity. This is not a schema migration or an invented physical revision source.
- `credentials.ts`: real AES-256-CBC and HMAC-SHA256 implementation from an explicit 32-byte producer key. Preserves native ciphertext.hex/IV.hex representation and `homarr-keyed-fingerprint-v1` domain. No environment read, zero-key fallback or alternate installation key is selected. Strict malformed-input handling and constant-time fingerprint comparison; disposal erases this adapter's copied key material only. Host retains original key/codec ownership and must arrange shutdown ordering after drain.
- `transport.ts`: actually constructs and owns Undici `EnvHttpProxyAgent`, direct HTTP/HTTPS native agents and Axios HTTP adapter. Same supplied CA, secure context and native fingerprint/hostname trust matching apply to direct TLS, upstream request TLS and proxy TLS. Explicit HTTP_PROXY/HTTPS_PROXY/NO_PROXY strings prevent Undici environment fallback; Axios uses explicitly direct agents and `proxy: false`, not ambient/global clients. Source-native Fetch/Axios choice and source Stats parsing/auth exchange remain intact. Each request is fenced against current SQL/test scope and trust material and receives scoped cancellation. The owned dispatcher cannot be replaced by a caller's Fetch option. No new CA roots, trust overrides, `rejectUnauthorized: false`, hostname wildcard or permission bypass were added.
- `node-agent.ts` and `lifetime.ts`: owned native connection creation tracks immediate and late callback delivery, rejects new creation after retirement, destroys late delivered connections, and waits for physical stream close. Binding lifetime denies new/queued work after shutdown, aborts owned scopes, waits for real pending operations, and joins idempotent releases. Abort does not remove uncancellable work from settlement ownership. Undici has graceful retirement with bounded escalation to actual destruction; Axios adapter work and native connection retirement are joined. Failed retirement is retained and reported, not counted as successful release.
- `sessions.ts`: supplies the unchanged native session-store envelope/codec API with actual `AtomicStateBacking` reads and conditional mutations on `session-store:<id>`. Writes/deletes include the host's captured physical fence plus the observed encrypted session value (CAS), preserving provider TTL in milliseconds and no-TTL behavior. Context identity and trust identity must match; empty fences fail closed. State/read/mutation work remains owned until physical settlement; no ambiguous mutation retry. Existing base session-store best-effort write behavior remains unchanged. Serialization is an explicit source SuperJSON producer, not JSON pretending to preserve native values.
- `caches.ts`: composes genuine source integration generation invalidation, media request-list local invalidation and media request-stats invalidation. All three effects settle and failures aggregate; no replacement cache, fabricated invalidation success, broad TTL changes or coalescing policy. Existing source list/stats/generation ports also remain separately available for API consumers. Cache/state producers are borrowed resources and are not stopped by integration close.
- `errors.ts` / local `index.ts`: discriminated unbound/candidate producers, typed explicit hold reasons, subsystem-local exports. The public native facade preflights absent SQL/codec/trust/authority/class joins before entering the frozen executor's safe error mapping. Inside an already executing native operation the frozen executor intentionally continues its existing safe failure mapping; this lane did not rewrite that error contract.

## Narrow P1 acquisition-signal revision

Frozen for the same independent lifecycle reviewer's rereview. Only the connection-test `acquireResourcesAsync` body in `native.ts` and this appended note changed for this revision. SQL/configuration, crypto, session, cache, native Stats, proxy and retirement implementations remain unchanged; no new legacy-kind join or policy was introduced.

The existing execution timeout now starts at the entry of the tracked acquisition, before the first snapshot or authorization wait, rather than after initial authorization. One owned signal forwards caller abort, binding shutdown, child-owner disposal and the existing execution timeout; the initial `authorizeAsync` receives that signal, and the same signal continues through trust acquisition and the testing runtime. Open/signal checks precede initial admission and follow snapshot/authorization settlement. The existing deadline timestamp moves to that same entry; no new timeout duration, separate phase deadline, Stats guard or reference-count scheme was added.

The owned timer is explicitly clearable. Abort removes all installed forwarding listeners and the cleanup listener and clears the timer; the lease's idempotent release also performs cleanup in `finally`, including failed authorization, late trust failure and failed child close. Successful acquisition transfers that cleanup ownership to the existing lease, so normal test completion/release and parent shutdown follow the same disposal path. Pre-aborted acquisition does not install a timeout. No timer or abort handler declares resource release or removes pending work merely because cancellation was requested.

Shutdown now reaches a cooperative initial authorizer even when the caller signal remains live. Real limitations remain: a producer that ignores the combined signal, a snapshot currentness wait whose frozen contract accepts no signal, or an underlying resource that has not physically settled can still hold drain open. Late trust/authorization settlement is rejected by the existing admission checks and the lease is disposed after settlement; cancellation is not a producer acknowledgement, transaction outcome or proof of physical retirement. Q17/Q18, real SQL/auth/session COMMIT producers and physical retirement remain held.

No commands, checks, tests, lint/typecheck/build, runtime evaluation, dependency install, formatter command, network/provider call, SQL, environment/key/current-data access, listener/server/container launch, Git operation or nested agent was run for this revision. Existing checked AbortController/AbortSignal and timer APIs only; no new library or external documentation request. This is a source-only lifecycle fix awaiting rereview, not execution or shutdown proof.
