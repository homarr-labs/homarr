## Required producer contracts — exact existing types, no substitutes

### A: authenticated request and browser session owner

Supply one current request projection derived from the same production session owner used by the issuer/request reader, not a session-kind flag or browser-selected identity. It must provide:

1. Actual `IdentityPrincipal` / authenticated `BackendPrincipal`: `user.id`, source name/email/image/colorScheme and current expanded `GroupPermissionKey[]`. Preserve source nullability. Do not fill missing grants with an invented empty array or turn an unknown principal into an anonymous successful projection.
2. A `SourceSessionState` authenticated branch with `SourceSession.expires` from genuine stored opaque-session expiry and the same user projection. `SqlAuthorityReadLease.validity` distinguishes stored-session expiry from API keys with **no stored expiry**; never invent an expiry to fit the browser session type. Normal private application session ownership is cookie-session ownership; API-key UI support needs a separate explicitly approved contract.
3. Non-secret opaque `authorityKey` that changes on each replacement projection, including same-user refresh and relevant permission/membership/resource changes. Separate the user-visible projection from the server lease, credential, verifier and durable session identifiers. Nothing credential-bearing enters bootstrap, Query keys, loader data or logs.
4. Real enabled and locally managed `SupportedAuthProvider[]`, and real `{ enabled, readOnly }` demo state. Locally managed OIDC membership is a source policy, not synonymous with OIDC being enabled; LDAP is not locally managed by this UI.
5. Real `SourceSessionHandlers` sign-in/sign-out and `IdentityAuthority.refreshAuthority(): Promise<void>`. Refresh must obtain a fresh authenticated projection, publish replacement keyed settings/session/authority atomically and invalidate route loads. A resolved no-op is invalid. Source expiration currently hides only session context: the host must also synchronously retire the private subtree and its Query scope.

A owns fresh session/projection endpoint selection, issuer cookies, CSRF/origin handling, logout/revocation/currentness and provider redirects. U only adapts the resulting safe projection and real handlers to existing UI types. The endpoint and projection DTO do not exist in the current public bootstrap; serialize their contract amendment before implementing consumers.

## SSR publication and lifetime decision needed before coding

Keep existing public success-only Query dehydration unchanged for public data. Genuine private first paint requires an explicitly reviewed, authority-bound **private** publication path, not `meta.visibility = public` on private reads. Recommended bounded first join:

1. The admitted request builds router, its single QueryClient, real native client and active Query scope. Guard private parent before child loaders. Await finite generated `.queryOptions(...)` reads using `createRouteQueryLoader`, current request admission and route abort ownership.
2. Render the existing source shell/forms from that request-local cache. Scope identity and generated options must be identical for loaders and components; `renderRouterToString` does not wait for component-only `useQuery` requests. No server live streams.
3. Define an allowlist of safe finite query results for the requested route, bound to the safe authority/cache snapshot and emitted only in the authenticated response. Preserve date/undefined semantics using the installed matching serializer or a specifically verified wire codec, not blind JSON conversion. Never include plaintext creation results, passwords, CSRF tokens, opaque credentials, provider tokens, error internals or mutation state. Use private/no-store response caching; retain H/A response cookie/header effects.
4. Private loader functions return no native client, owner, lease, authority handles or arbitrary private payload. TanStack automatically serializes resolved loader data independently of `shouldDehydrateQuery`; use `void` where cache ownership already carries approved data. Also inspect serialized `beforeLoad` context/match hydration rather than assuming that the Query filter seals the whole document.
5. Browser reconstruction uses the safe bootstrap for matching first paint and a real same-origin cookie-authenticated RPC transport for subsequent reads. Create the same mandatory providers before `hydrate(router)`; subsequent private admission/refresh comes from A, not a local `authorize: allow` callback. Revalidate fresh server session/current grants before resumed private interactions when validity is unknown. The projection informs UI, never authenticates RPC.
6. Retire visibility synchronously before logout/expiry/authority replacement; drain/remove the acquired scope, remount private state and obtain fresh owner identifiers before resuming. Failed refresh remains closed without repeating an acknowledged mutation. Integrate `beginSessionTransition/runSessionTransition` and real `RefreshPorts`: invalidateLoaders → awaited `router.invalidate({ sync: true })`, resolveSession → A refresh, refreshRenderSnapshot → genuine settings/culture/document read, invalidateResourcePolicy → real current grant read.
7. Register request disposal before work starts, and retain admission through finite render/serialization. Scope retirement, Router SSR cleanup and Query cancellation/removal must settle on response disposal/abort. H owns the application's operation drain/publication ordering. Browser abort or scope retirement is not proof that a server mutation did not commit.

Until this private serialization amendment is approved, a shell with real request-owned providers can be joined, but data-rich private SSR/hydration remains a deficit. Do not relabel a public skeleton as completed private SSR.
