# EXPANSION35: auth frontend

## Delivered boundary

`apps/nitro/src/features/auth/` contains the local/LDAP login form, OIDC button and guarded auto-login, CLI password-recovery disclosure, generic failure feedback, logout button, return-path handling, and an owner-signaled session-expiry notice. Nothing is registered in shared routes, providers, hosts, APIs, or manifests.

`AuthFrontendTransport` injects specific asynchronous methods for reading a server-issued CSRF token, local login, LDAP login, OIDC initiation, and logout. No method has a default success implementation. Missing methods disable their action and display unavailable feedback. Rejected requests and thrown transport errors never navigate as successful authentication. No endpoint URL is invented and no network request occurs without an injected method.

Credential methods must report `authenticated` only after the approved issuer has established a browser session, not merely after a verifier accepted credentials. OIDC initiation returns a navigation URL, not an authenticated session. Logout must invalidate the native session before reporting `signed-out`. The owner must validate method responses at the transport boundary.

Requests carry the sanitized application-relative return path. If the approved issuer requires an absolute callback as the source Auth.js client did, the owner adapter must resolve it against its approved application origin. The UI does not infer an issuer origin, authorize forwarded headers, or choose a session strategy.

## Source form and navigation semantics

- `apps/nextjs/src/app/[locale]/auth/login/_login-form.tsx`: shared username/current-password fields, distinct `credentials` and `ldap` submits, OIDC separator/button, auto-login suppressed on provider callback errors, and CLI-only recovery. Username and password reach the transport unchanged, using the source `userSignInSchema`; login does not apply registration password requirements, username lowercasing, or password hashing in the browser. Native submitter selection supports keyboard submission; the fallback is local when configured, LDAP otherwise. Pending state locks all provider actions. Password state is cleared after attempts. No credentials, tokens, or raw provider failures are logged, persisted, or rendered.
- `apps/nextjs/src/app/[locale]/auth/login/page.tsx`: source return paths are selected by the route owner (`redirect` before `callbackUrl`) and sanitized before use. The feature reuses `sanitizeRedirectionUrl` and additionally rejects backslashes/control characters and verifies same-origin path resolution. A confirmed login navigates to that path through the owner callback; the owner is responsible for session/cache refresh first. No successful notification precedes session establishment.
- `apps/nextjs/src/components/user-avatar-menu.tsx`: logout finishes before navigating to an approved provider logout URL or `/auth/login`. The owner navigation method must preserve provider navigation against cache-triggered reloads. Provider redirects require both protocol checks and owner approval for the specific sign-in/sign-out purpose.
- `apps/nextjs/src/app/[locale]/_client-providers/session.tsx`: source expiry triggers sign-in from a session supplied by its owner. This feature accepts only an explicit expired signal and presents the return-preserving login link. It does not calculate expiry, read a session, install timers/listeners, or claim an unknown session is anonymous.

Messages are injected so the host can reuse source translation keys without another translation provider: `user.field.username.label`, `user.field.password.label`, `user.action.login.label`, `user.action.login.labelWith`, `user.action.login.forgotPassword.*`, `user.action.login.notification.error.*`, and `common.userAvatar.menu.logout`. New unavailable/CSRF/expiry copy and field-required/visibility labels must be localized by the host owner. Errors use fixed message codes rather than server detail that could disclose account existence.

Use the existing pure `OnboardingAuthShell` presentation when the owner exposes a browser-safe entrypoint. This feature deliberately does not duplicate the shell, identity, invite-registration, onboarding, session-provider, or SQL-reader flows. The current `@homarr/onboarding` root also exports runtime-coupled onboarding studio code, so no import from that root is added here.

## P2 lifecycle cancellation return

The source review identified a deferred-CSRF lifecycle gap: a removed or rebound form could dispatch captured credentials/logout and later navigate over a replacement page. `attempt-lifecycle.ts` now owns one current attempt per committed component binding. React layout-effect cleanup invalidates the attempt, drops feature-owned credential references, and aborts its controller on unmount or transport/navigation/capability replacement. Individual transport/navigation method replacements also invalidate it. Changed configured providers, return path, callback-error signal, and OIDC auto-login setting invalidate login attempts. Old binding callbacks cannot start an attempt in a replacement binding. Current binding setup clears pending state and the login password field; unmount cleanup performs no React state updates. Owners should keep bindings stable while unchanged and commit binding/capability updates through React rather than mutate unseen configuration in place.

Login and logout check currentness immediately after each awaited CSRF, mutation, and navigation operation, before subsequent mutation/navigation or state updates. Catch/finally handling cannot write late errors or clear a newer attempt's pending state. Credentials reside in a releasable attempt slot rather than an asynchronous function parameter; the feature drops that slot immediately after handing a credential request to the owner and immediately when abandoning an attempt. This releases references, not a claim to erase immutable JavaScript strings or an already-dispatched owner request.

Central binding change: each specific `AuthFrontendTransport` method accepts optional `AuthFrontendRequestOptions` containing the attempt `AbortSignal`; the feature supplies it for CSRF, local/LDAP authentication, OIDC initiation, and logout. Owner adapters must forward/compose it with their existing cancellation/timeout signal only where the real transport supports cancellation. Navigation methods accept optional `AuthFrontendNavigationOptions` with the same signal and `isCurrent()` guard. An asynchronous owner navigation/cache-refresh callback must recheck these after its own awaits before actually redirecting. Old adapters that ignore these optional arguments remain structurally compatible, but their already-started work is not made cancellable by this UI change.

Abort does not roll back an already-dispatched server mutation, invalidate a server-created session by itself, or cancel a redirect already performed. Native transport implementations, credentials retained by their requests, and server mutation/session ownership remain with the auth owner. Cancelled OIDC auto-login is not automatically retried; the existing one-attempt guard remains, with manual provider actions available after a binding reset. Q16 issuer, CSRF enforcement, session, callback, and production-routing holds remain unchanged.

This revision used static source inspection only. React 19.2.7 remains an existing app dependency. Context7 remained quota-blocked, so current official [React layout-effect cleanup documentation](https://react.dev/reference/react/useLayoutEffect) supplied commit/unmount and Strict Mode semantics. No validation command, runtime repro, test, build, install, formatting, browser, live provider/SQL operation, listener registration, environment/data access, Git operation, or nested agent was run. Prior validation checks were none; final required checks and independent rereview remain outstanding. Only this feature and its own handoff note were changed; the note was moved to `scratchimplementation/expansion-auth-ui.md` without removing other root files.
