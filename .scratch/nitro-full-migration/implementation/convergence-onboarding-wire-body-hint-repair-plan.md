## Before-read / absence sequencing

1. Keep original currentness, exact method/path selection, immutable header witness, origin/CSRF/mode admission, original clock pair/budget and once-owned task/cache ownership unchanged. Hint data is an interpretation constraint, **never authority or provenance**.
2. Before the current cache return and before `ledger.run`/`readBodyBytesAsync`, validate the complete original hint and determine the compatible interpretation using the table. Reject incompatible hints/fallbacks without acquiring/reading the body. JSON interpretation also validates the existing Content-Type regex here, even for a null/zero-byte body.
3. Use the same one tracked actual bounded body read. Do not believe `none`, Content-Length `0` or missing headers as proof of absence: drain a present stream under the existing budget/physical settlement and require its actual byte length to be zero. With interpretation `none`, **any positive byte count rejects**, including whitespace, `{}`, `null` or any otherwise-valid JSON. No bytes are silently discarded or reinterpreted.
4. With interpretation `json`, apply the installed empty-text rule **after** header admission and the actual read: null/zero bytes correspond to empty text/undefined; nonempty bytes use the existing fatal UTF-8 decoder, then exactly empty decoded text yields undefined, otherwise the existing whole-text JSON.parse is required. Whitespace text must fail JSON.parse, not become absence. This also prevents a json hint from bypassing header/JSON meaning through the old unconditional byte shortcut.
5. Populate the existing private cache only after the compatible interpretation and actual read/parse succeed. A JSON value remains derived from original owned text/bytes; subsequent unknown resolution serves fresh SDK-owned parsed data, not a caller object or guessed `packet.json`. Preserve the exact-empty-text absence semantics without selecting RPC envelope fields. Keep existing request/body rejection types; no new public discriminator is needed for this narrow cut.

No new body source/getter, clone, HTTP reconstruction, custom serializer, startup callback or second read is introduced. Do not alter the owned reader's cancellation/terminal-error replay, reader.closed/release, task publication or deadline behavior. The ordinary installed codec remains responsible for real packet deserialization and the selected leaf/schema; this cut does not manufacture codec receipt provenance or claim support for arbitrary future explicit accessor-hint overrides.
