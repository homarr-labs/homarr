## Actual ports and identity

Current C signatures are concrete:

```ts
publication.claim(originalContext, returnedWireResponse): OnboardingPublicationHandle
publication.abandonAsync(originalContext, returnedWireResponse, cause): Promise<ProductionOnboardingPublicationResult>
handle.read(): OnboardingRpcRequestResult["finite"]
handle.finishAsync(): Promise<ProductionOnboardingPublicationResult>
handle.abandonAsync(cause: unknown): Promise<ProductionOnboardingPublicationResult>
```

C native `deliver` (`1190–1210`) creates the real reservation and response lookup before handler return. Claim resolves that lookup and the helper's weak original-context/exact Request/returned-Response association. Its synchronous read validates the saved **wire head** and calls A with the separately retained **source Response**. RPC's SDK source body has already been consumed by A; C's wire body was constructed from A cached bytes. They are not the same Response, and neither a DTO nor Application enrollment can create the underlying A/frame/native record.

C2 terminal forwarding already owns one published-admission-failure abandonment inside the same task. D must await its canonical result, not repeat positive finish/native dispatch or create another response/publication. C read is unavailable after terminal installation; D must not design a fictitious post-finish clock read.

## Physical Fetch boundary / async terminal sequence

Each request prepublishes its retention/terminal completion and actual read/cancel/reader-closed/release obligations before invoking them. Only the returned **wire body** is read once. A cache is accessed through `handle.read`, never by reading/cloning/re-registering the consumed SDK source Response.

| Boundary               | Concrete required sequence                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Header handoff         | Claim the real C record; obtain genuine cached bytes/head witness; perform exact approved finalization; prepublish retention; immediately before exposing the final Fetch Response, check external request/Application signal, both heads and fresh C read. No await/caller callback between the final synchronous check and local handoff. This is not a socket `headersSent` claim.                                                                        |
| Each body chunk        | Track/await one actual wire-reader read; clear its pending slot before termination joins; obtain fresh C read; compare chunk bytes incrementally against the authoritative cache at the actual cursor, rejecting excess/non-byte/different bytes. Verify final/source heads and external signal immediately before enqueue, with no intervening await. Keep cache private and enqueue an owned copy so consumer mutation cannot rewrite comparison evidence. |
| Full EOF               | Require actual wire EOF **and** exact total cache length (including empty byte streams). Join actual reader.closed, release lock and prior read/guard work; freshly validate original C bounds/native/head just before closing the retained Fetch stream. Record that local EOF transition, then await the same prepublished async C finish task before disposal/map removal. There is no fictional C read after finish has installed terminal.              |
| True bodyless response | Require genuinely absent wire body and zero owned bytes; freshly check head/bounds at local Fetch handoff. Own the async C finish task through actual A settlement before request cleanup. Never treat a response promise or boolean as socket completion.                                                                                                                                                                                                   |
| HEAD/local 405         | Outside onboarding publication membership; cancel/drain any actual generic body using existing behavior. No positive C finish for an unsupported method.                                                                                                                                                                                                                                                                                                     |

Local EOF/bodyless handoff precedes async terminal confirmation: stream close or returning a Response is an observable transport-side action, not a guarantee that A's later terminal admits publication. If C's final admission race returns actual abandonment after that local transition, retain it as abandonment; already released bytes cannot be withdrawn. Awaiting finish **before** EOF then claiming a fresh post-finish read would contradict actual C ports. This plan therefore distinguishes local handoff, confirmed A terminal and network receipt rather than inventing one universal atomic boundary.

Abort/cancel, output read error, changed head, unequal/extra bytes, early EOF or late original-clock failure initiate real cancellation independently of pending pull work. Join pending read/cancel/reader.closed, attempt actual release and detach hooks even after failure; then await one genuine handle abandonment (or producer abandonment if claim never completed). Termination's drain excludes its own pull/terminal completion promises. Preserve first source/body/cancel failure and directly observed distinct cleanup failures; do not traverse error graphs or guess SQL state. Ordinary retired Auth work-signal abortion is not an external publication cancel; no new budget, expiry, readiness/SQL guard or replacement signal is introduced.

On C fulfillment retain the exact returned result, including published **source-error** outcomes and real cleanup failure. Published body-error is not successful command execution, even with HTTP 200/void/matched. Unexpected C rejection stays failed/UNKNOWN with original evidence: D neither retries positive/cleanup/native operations nor labels rejection SQL-closed. Known COMMIT plus publication failure never authorizes resend. Application active-request ownership lasts through the actual terminal task; shutdown then preserves handlers → publication reservations → Auth/native cleanup. No Promise.race-as-settlement, discarded async rejection fallback or self-await.

## Adapter limits / precise additional producer

Current `application.ts` only owns Fetch Response creation, guarded stream enqueue/close/cancel and request disposal. `host.ts` forwards `application.fetch`. Actual `apps/backend/server/entry.ts` uses **srvx/bun** and returns `nitro.fetch(admitted)`; ingress retains the same Request. Its lifecycle plugin supplies shutdown only, not per-response header/finish callbacks.

Installed srvx 1.0.5 Node adapter writes headers **before** reading the web body (`node.mjs:59–62`), calls `nodeRes.end()` upon web EOF, and exposes reader closure/cancellation—not an Application publication acknowledgement (`132–161`). Its optional Node runtime `res` declaration is not a constructor-registered callback or a portable permission to adopt arbitrary transport metadata. Bun's adapter hands a native Response to Bun and exposes no corresponding per-response write-head/finish hook to Application.

Thus **D4 is closed only for these existing Fetch-visible transitions**. If the required oracle/spec instead demands a fresh A check at actual socket header write and async terminal coupling to real socket finish/error/close, the exact additional registering-caller boundary is `apps/backend/server/entry.ts` (a separate fifth-file/transport lease). It must connect a real adapter-owned per-response writer/finish producer for the same original Request and returned Response; a promise-return hook, ready flag, arbitrary `runtime.node.res` getter or interface-only receipt is insufficient. Current Bun plumbing does not supply that producer, so a concrete adapter capability/design must be approved before claiming such closure. Do not patch installed srvx or silently switch/activate transports in D4.

No universal hard deadline while a client never pulls, socket-flush/client-receipt guarantee or current runtime test is asserted. No transition occurs during a stalled pull; validity is checked before subsequent local output. Stronger transport observations remain a distinct hold, not preservation installer/observer scope.
