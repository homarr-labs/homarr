## Real services ported

`createRootCertificateStore` extracts the actual root inspection/ensure implementation, not a mock replacement. It retains one PEM certificate, 64-KiB byte bound, 128-character root filename rules, DER equivalence, CA/self-issuance/signature/current-validity checks, SHA-256/fingerprint/expiry metadata, `O_NOFOLLOW | O_NONBLOCK` bounded regular-file reads, exclusive temporary creation, file sync and hardlink no-replace publication. Identical concurrent bytes return one creation plus idempotent successes; different concurrent bytes produce one winner and `CONFLICT`. Cleanup-reporting failures cannot change the publication result.

`createCertificateFileStore({ folder, onTemporaryFileCleanupError? })` accepts only an explicit absolute folder or explicitly disabled custom files. It reuses root ensure for upload and retains built-in `tls.rootCertificates` plus mounted custom PEM contents. Loading/removal now use the bounded no-follow reader; loading/removal retain legacy safe filenames containing spaces. New uploads follow issue 18's root-only, 64-KiB, no-overwrite rule rather than the old generic 1-MiB overwrite path. Existing mounted contents are not silently rewritten or discarded; metadata lists report malformed/non-root entries. Packaging owns folder/volume/permissions and any external mount refresh policy.

`createCertificateService<TAuthority>` directly ports all six real router paths, with the required injected admin guard before file/store access:

`createCertificateTrustReader` returns server-only `{ ca, trustedHostnames, version }`. Version is a SHA-256 digest of actual CA bytes and sorted exact hostname/fingerprint pairs, not a counter pretending to persist across restarts. Add-trust commands require a readable prior snapshot and fail closed, notifying unavailability on a read failure. Revocation/cleanup skips that prior snapshot completely and performs authorized removal first; afterward it publishes the current version or `trust-material-unavailable`. Unavailable material alone does not undo or fail an otherwise completed revocation; failed retirement/effect delivery does reject honestly, including when the row/file was already removed. File mutation plus SQL deletion remains two resources, not a fictional cross-filesystem SQL transaction. Effects run after partial mutation failures; mutation and retirement errors are preserved together where necessary.

`createCertificateHttpRuntime` ports the real Undici agent, native HTTPS agent, Axios client and trusted Fetch choices with required injected Fetch, trust reader and explicit `{ httpProxy, httpsProxy, noProxy }` strings. It preserves CA/identity/lookup overrides, body timeouts, request timeout composition, scoped abort signals, source URL redaction and the four-entry content-keyed TLS-context cache. It also supplies `invalidateAsync` and `disposeAsync`; caller-provided dispatchers remain caller-owned. No `rejectUnauthorized: false`, global TLS setting, implicit SQL, global dispatcher registration or SSRF bypass is introduced. Server-controlled overrides must not be exposed as browser input; source caller authorization/SSRF/redirect gates remain required.

Managed Fetch rereads material and keeps at most eight body-timeout dispatcher configurations. Axios rereads material before each request. Changed/unreadable material retires owned clients; raw HTTPS agents cannot reopen with stale trust after retirement. Generation checks reject/retry in-flight stale material reads and stop late client construction after disposal. Host effects must invoke runtime invalidation; independent raw agent users cannot discover an external mounted-file change without that host lifecycle integration. Revocation invalidation destroys existing sockets, rather than allowing stale pooled TLS sessions to retain authority.

## r2 contract and lifecycle revision

The original six command signatures, metadata outputs, `TrustedCertificateHostnameStore` interface and effect union remain unchanged. The r2 effect semantics are important for composition:

r2-only writes are `certificates/runtime.ts`, `certificates/checks/trust.check.ts`, new `certificates/checks/revocation.check.ts`, `http/runtime.ts`, new `http/ownership.ts`, new `http/checks/lifecycle.check.ts`, `http/checks/tsconfig.json` under `packages/core/src/infrastructure/`, and this handoff. No other production source file was changed for this revision.

- `{ kind: "trust-material-changed", version: string }` carries the current material digest. Add-trust compares the prior digest, preserving idempotent ensure. Revocation always publishes a refreshed digest when readable, even if equal to an earlier digest: **the listener must still invalidate and await retirement**, not suppress it solely because the version matches.
- `{ kind: "trust-material-unavailable" }` is a mandatory retirement signal, not permission to keep old trusted clients or manufacture a version. Failed add-trust notifies it before returning an error. Completed revocation notifies it after removal without needing readable unrelated mounted CAs. Denied authority executes neither reads, mutations nor effects.
- An effect failure after removal yields an `AggregateError`; it is not rollback evidence. When both mutation and retirement fail, both errors are retained. These are server-only errors; adapters must retain their existing safe error rendering rather than exposing causes/credential diagnostics.

New **candidate** optional fields on `CertificateHttpResources` need coordinator review:

| Field               | Exact shape / obligation                                                                                                                                         |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `createDispatcher`  | `(options: HttpAgentOptions) => ResourceHttpAgent`; defaults to the real installed agent; return a fresh runtime-owned instance, never a shared/global singleton |
| `createHttpsAgent`  | `(options: AgentOptions) => ResourceHttpsAgent`; defaults to the real guarded native agent; same fresh ownership requirement                                     |
| `retirementGraceMs` | Integer 0–30000 ms, default 1000 ms; bounds graceful retirement before force-destroy, not an invented successful shutdown deadline                               |

No new public lease/release method is required. `ownership.ts` supplies internal tracked leases and preserves Undici's Promise/callback `close`/`destroy` overloads. Caller `close()` starts bounded graceful retirement; caller `destroy()` starts immediate destruction. The runtime intercepts those operations, unregistering only after confirmed terminal completion, including native HTTP/HTTPS socket `close` events. It keeps strong ownership while retirement is pending or failed, not after successful release. Closed Axios HTTPS agents are replaced rather than reused while still tracked for physical disposal.

Eviction removes a cache entry, starts tracked bounded graceful retirement, and inserts its replacement in one synchronous transition, with no awaited close between lookup and insertion. Concurrent same-key requests therefore reuse one entry; active cache capacity remains strictly eight. Retiring transports are tracked separately until disposal completes, so total pending transports can temporarily exceed eight. The ninth request does not wait on an old SSE/unread body. Its timeout starts before material acquisition, and waiting for material/invalidation respects the scoped/user/timeout abort signal; late completion cannot cause a cancelled request to call Fetch.

Invalidation forces and joins **all** outstanding retirements, including retirements already started by eviction or caller cleanup. Disposal stops new work, tracks destruction of the shared native HTTP agent too, joins all retirements using all-settled semantics, and returns one cached Promise across overlapping/repeated calls. A failed destruction cannot cause a later disposal to report success. Grace expiration forces destruction, but the runtime still awaits the transport's real completion callback/socket close; a stalled destruction leaves disposal pending, and a failed destruction rejects while retaining the failed ownership record. It does not fabricate resource cleanup. Factory adapters must honor the installed completion semantics.

### TLS root cause and repeatability

The system executable is `/usr/bin/openssl`, **LibreSSL 3.3.6**, run with `env: {}`. The previous fixture used one `root.conf` for two RSA roots and expected `req -x509 ... -config root.conf -subj ...` to distinguish them. Inspection of the emitted certificates in that exact invocation pattern showed **both subjects identical**, despite different requested `-subj` values and different public keys. Sparse leaves have no authority key identifier to distinguish those candidate issuers. A valid leaf verifies with the actual signer alone, but the complete trust set can select the other same-DN root and then correctly reject the signature. Root-only `openssl verify` was therefore an incomplete oracle: paired-root `openssl verify` fails too.

`tls-interop.mjs` isolates this without SQL, file-service mutation, runtime caches or revocation. Every generated leaf's signature is checked using the real root public key and explicitly fails against the other key. It then uses real installed `undici/index.js` Fetch, raw HTTPS and the installed native Axios HTTP adapter against one owned ephemeral target. Session caching is disabled in this probe. Across the same generated bytes, CA-only, SecureContext+CA, SecureContext-only, joined PEM and reversed root-order configurations agree on Bun's collision failures. Thus neither disabling session caching, removing SecureContext, concatenating PEM nor reordering the roots resolves the collision. No such production workaround was adopted.

The pending proxy deliberately reads incoming data and FINs and half-closes on peer end; it is not a paused peer falsely hiding an already-closed connection. It withholds CONNECT's 200 response and never opens a target connection. No timeout was configured on the native agent, so an arbitrary long agent tunnel timeout cannot substitute for immediate scoped cancellation or awaited disposal. The 50-ms interval is a bounded observation of a pending resource, **not** a fabricated promise that no future close could ever happen. Cleanup subsequently aborts and closes the **fixture-owned peer** and awaits its real close/request settlement; that intervention is explicitly not credited to production disposal.

**Diagnosed lifecycle cause:** native `createConnection()` returns a raw proxy socket marked as waiting for CONNECT. Native `_http_agent.createSocket()` postpones putting it in `agent.sockets` and handing it to the request until the tunnel/TLS callback. Therefore native `Agent.destroy()` and request abort do not see the pending raw connection. `ownNodeAgent`'s r2 snapshot of `sockets/freeSockets` also cannot join it, producing the observed early Node disposal resolution. ## r3: native connections owned before native pool registration

Historical r3 submission record; subsequently accepted by independent behavioral and standards review. Primitive-agent evidence alone did not release Bun's managed-runtime guard.

### Scope and exact handling

Production changes are limited to `http/https-agent.ts` and `http/ownership.ts`. `runtime.ts` and `transport-agent.ts` are unchanged. Certificate production/files/runtime/check sources, SQL hostname resources, manifests/lockfiles, integrations/providers/apps, exports and host mounting were not changed in this revision. Core already declares Axios and Undici; no additional dependency or custom proxy protocol is used.

`ResourceHttpsAgent` still extends the real native HTTPS Agent. It delegates native socket creation, TLS configuration, proxy parsing, CONNECT and pool scheduling to the pinned implementations. Its prototype `createSocket(request, options, callback)` bridge associates each native creation with the actual request, including queued creation. During that synchronous bridge, `createConnection` tracks both the **immediately returned raw socket** and any later callback-delivered stream in a strong Map, installing close listeners before returning to native pool registration. The bridge is present in the pinned Node/Bun prototype source but omitted from installed `@types/node`; one explicit structural signature covers that boundary. It uses no private native property, proxy symbol, pool mutation, raw handle or reimplemented CONNECT protocol.

Before delivery, a temporary wrapper on that request's public `destroy(error?)` destroys its associated pending streams and delegates to the original request destroy. This covers AbortSignal cancellation before native request socket assignment; waiting for the public request close/error event alone was too late. The wrapper is restored on socket delivery or request close without overwriting a replacement installed by another owner. Other requests' pending streams are not cancelled. Native `destroy()` marks this agent retired before destroying **all tracked connections**, then delegates normal pooled destruction. Closed streams are removed only on real `close`; streams arriving after cancellation/retirement are tracked and destroyed instead of registered as successful live connections. Undelivered raw close completes the native callback with a failure when needed so the request does not remain waiting for a callback that native destruction did not produce. A rejected CONNECT callback also destroys its undelivered raw stream, independently of whether native error forwarding retains that stream.

`waitForConnectionsClosedAsync()` is an internal native ownership join, **not a new consumer release API**. `ownNodeAgent` adds it to the existing pooled close joins, uses `Promise.allSettled`, and invokes `onReleased` only after successful joins. The class retains any synchronous stream/native destroy failures; these reject retirement rather than claim closure. Failed transports remain runtime-owned, other transports still settle, and repeated runtime disposal returns the same rejected/resolved Promise. A destroy failure does not assert that its socket closed. A missing/delayed real close event keeps the successful-close join pending; there is no timer declaring a socket closed. Resource factories must retain this base connection-tracking bridge when extending the native agent; substituting an untracked transport remains outside the accepted contract.

The resource interfaces, effect union, strict-eight Fetch cache, coalescing, material abort, trust invalidation generations, graceful dispatcher retirement, CA/SecureContext/identity overrides and Axios source adapter selection are unchanged. No TLS chain/hostname verification relaxation, CA pruning, legacy-DN rejection, ambient proxy environment read or diagnostic/auth configuration change is introduced.
