## Source and implemented functions

- `log-history-stream.ts` adapts `core/.../logs/transports/redis-transport.ts`, `redis/src/index.ts` and `api/src/router/log.ts`. `recordAsync` creates the same UUID/Date/formatted-string/level payload; `appendAsync` validates and serializes using the existing `loggerMessageSchema` and SuperJSON. No Winston/global logger import or recursive diagnostic logging occurs.
- `getRecentAsync` retains the 5,000-entry bound, invalid-log omission, oldest-first history, append order rather than timestamp sorting, level selection and default `["info"]`. Source history-read failure still becomes empty history; cancellation does not become a successful empty response.
- `subscribe` installs the listener before reading history, buffers racing live messages, emits the exact `{ type: "history", messages }` / `{ type: "message", message }` union, removes snapshot/live overlap by ID and serializes async delivery. Dedup remembers 5,000 IDs, not every ID forever. Both initialization and live queues are bounded; overflow closes with `LogBackpressureError`, not silent dropping or an unbounded queue.
- `SampleHistoryStore` adapts the actual `createChannelEventHistoryOld` methods: `pushAsync`, `publishAndPushAsync`, `clearAsync`, `getLastAsync`, `getSliceAsync`, `getSliceUntilTimeAsync`, `getLengthAsync`, and live-only `subscribe`. Sample history uses `{ data, timestamp: Date }`, newest-first storage/order and default 15. Inclusive/negative Redis-style slice endpoints remain. `getLastAsync` intentionally returns the **oldest retained** entry. The time helper intentionally excludes the last/oldest element, even if it is within the cutoff; this is existing source behavior, not a corrected policy. Malformed selected samples fail; unselected samples are not unnecessarily parsed.
- `sample-payloads.ts` supplies source-shaped factories for Dashdot CPU `integration:<id>:history:cpu` with **100** entries and OPNsense `integration:<id>:interfaces` with **15** entries. CPU values preserve per-core `load` and `temp`; OPNsense preserves raw cumulative `receive`/`transmit` bytes, without rate conversion, normalization, clamping or invented units. The source's possible `parseInt` NaN/infinite numbers are not silently rejected or zeroed. No upstream HTTP request or poll was added.
- `getDashdotLoadAveragesAsync` retains the 15-minute cutoff, per-core arithmetic average, newest sample for `1min`, `slice(0, 4)` for `5min`, `slice(0, 14)` for `15min`, and `Math.round`. Empty windows retain source NaN behavior; they are not manufactured zero measurements. The provider must call it only after awaiting its newest CPU `pushAsync`, exactly as the existing producer does. OPNsense still consumes `getSliceAsync(0, 1)` as two timestamped newest-first interface snapshots.

Source sample `publishAndPushAsync` publishes the **raw data first**, then records timestamped history. It is deliberately not changed into latest-value store-before-publish. Current Dashdot/OPNsense callers use `pushAsync`, not that method. Log append/trim/publish and latest-value STATE fanout are separate contracts; no generic fanout/backing implementation was duplicated here.

## Candidate interfaces: review before use

`runtime/backing.ts`, `LogAuthorizer`, and `SampleAuthorizer` are proposed injected boundaries, **not accepted production contracts**. The coordinator ledger still lists STATE's scalar `AtomicStateBacking` as unaccepted, and it does not itself provide ordered bounded-list append/fanout. Therefore this lane does not implement a SQL adapter or encode a list into a generic KV read/modify/write loop. STATE/DB must review the smallest compatible bounded-history extension or approved atomic composition before a production implementation exists.

Required backing semantics:

1. `LogHistoryBacking.appendAndPublishAsync` retains one SuperJSON payload in a bounded newest-first list and publishes in the same committed append order. Persistent append+trim must be atomic. Publish only successfully retained entries; don't retry ambiguous writes or claim all crash-window events are replayed. Concurrent awaited writers must not reorder live delivery relative to committed history. `readNewestAsync(5000)` is one consistent newest-first snapshot. Log backing maps to the existing logical `list:logging:history` / `pubSub:logging` identities; this API does not prescribe physical tables.
2. `SampleHistoryBacking.pushAsync` atomically pushes/trims by namespace, with no TTL added. Reads return consistent newest-first retained entries; clear is namespace-scoped. Sample publish is live-only raw SuperJSON data, separate from timestamped history. Preserve publish-before-push for the explicit legacy method.
3. Subscription establishment must either fail without retaining a listener, or eventually return an idempotent nonthrowing release function. The supplied `AbortSignal` must cancel acquisition/reads/writes and must never allow a late cancelled mutation to commit. If acquisition ignores cancellation and settles late, the domain adapter releases that late returned listener immediately. An operation that never returns or relinquishes resources violates the backing contract; fixture cancellation is not proof of SQL cancellation.
4. Physical atomicity, SQL drivers/tables, deadline/clock ownership, stop/drain and restart policy remain DB/STATE-owned. Use the approved direct-driver transaction constraints: synchronous SQLite callback, checked-out PostgreSQL client, no independent generic KV claims. Retained histories need both-engine restart/retention evidence. Existing SQL ZIP backups exclude Redis logs/samples; current-backup restore must not be described as containing those histories.

## Authorization, cancellation and delivery join

- Log direct history and subscription establishment require `other-view-logs` before any data/listener access. Direct reads recheck after the backing read; every queued snapshot/live event rechecks before async delivery. `revoked` must be the real identity/policy authority signal, aborted on expiry/revocation at the accepted latency. No timer/latency policy or fake permanently allowed production authorizer was invented.
- Sample `requireAccessAsync(name, read|write|subscribe, signal)` must close over the actual trusted integration/resource/principal and existing native policy. Channel strings alone do not authorize a resource; do not apply log permission to integration samples or infer a grant from a caller-supplied ID. Producer execution authority is distinct from a viewer's resource read authority.
- Subscriptions return synchronously with `readyAsync` and idempotent `dispose()`. Abort/dispose/revocation/error clear queued payloads/ID sets, abort the delivery signal, emit one `closed` notification and release an established or later-returned listener. Readiness rejects promptly on cancellation even if injected establishment has not settled.
- `nextAsync` is serial, receives the combined request/authority/disposal signal and represents actual sink backpressure. The host must honor it immediately before writing bytes and cancel/drop already pending output on closure. `closed` must clear private client output for permission/session loss; runtime callbacks alone cannot clear a browser terminal. No claim is made that an already written byte can be revoked.
- Queues bound entry counts, not bytes: up to 5,000 replay-buffered live messages, one up-to-5,000-entry history event, up to 5,000 live queued events and one in-flight delivery; dedup IDs also cap at 5,000. Sample live queue caps at its configured history bound plus one in-flight value. #124 still owns byte/framing/deadline/reconnect limits. Readiness means initialization is queued, not that the consumer has already written the history.
- Host shutdown/maintenance must join its lifetime signal to every producer/direct read/subscription signal, dispose streams and await actual sink/backing cancellation before closing resources. There is no new global subscriber registry, polling fleet or shutdown listener here.
