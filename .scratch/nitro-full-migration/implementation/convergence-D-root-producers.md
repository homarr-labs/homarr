## Independent copy owner and already-joined API requiredness

`packages/db/copied-sqlite.ts:53` currently has the distinct signature:

`createSqliteCopyEngine(config: { temporaryDirectory: string; migrationsFolder: string })`

It does **not** construct `PersistenceRuntime` and does not inherit the optional `PersistenceConfig`. Root capture is the private `const migrationsFolder = config.migrationsFolder` (`56`); `temporaryDirectory` is independently captured (`57`). All subsequent copy bundle/prefix/target/migration uses reference that local folder, including the migrator at `280`. There is no copy-root fallback and no root derived from a copied DB pathname, source readiness result, or source-runtime handle.

One precise capture limitation remains: current absolute-path validation reads `config.migrationsFolder` at `54`, then `56` reads it again for capture. Thus this entrypoint is **not yet a single read of an arbitrary caller's folder property followed by validation of that captured value**. A readonly caller type alone does not rule out a varying getter. The minimal future owning-boundary refinement, if separately released, is inside this existing constructor: capture the folder primitive once and validate/use that captured primitive, retaining the required signature and native ownership. It needs no callback, default, wrapper authority, fabricated directory, catalog redesign, or new interface. This is independent of D's `PersistenceConfig` type join and is not implemented here.
