# Router navigation implementation handoff

## Scope and preservation

Only new `apps/nitro/src/navigation/` sources and this handoff were written. Existing router, generated route tree, routes, features, manifests, backend and private-authority composition remain untouched. The active Query producer was not read or consumed. No duplicate RPC client, adapter utility tree, Query key namespace, QueryClient, process-global cache, validator or authorization implementation was introduced.

No checks, lint, typecheck, build, install, tests, application import evaluation, browser, live provider/SQL calls, listener startup, credentials/environment reads, Git mutation or nested agents were performed. Compilation and runtime behavior remain unverified; this is an unwired source seam, not a completed frontend migration.

Read-only verification: `apps/nitro/package.json` directly declares Router `1.168.8`, Query `5.101.2`, React `19.2.7` and oRPC Query adapter `2.0.0-beta.43`. Installed Router/Query package versions agree. The adapter is now directly declared, unlike the older declaration snapshot in `STACK-ADAPTER-APIS.md`; no manifest was changed here.

Context7 resolution was attempted once and returned `Monthly quota reached`. No retry, authentication change or installation followed. Current official-document evidence is the already-verified `STACK-ADAPTER-APIS.md` §3 and its official links; implementation signatures were checked against these installed artifacts:

- React Router `dist/esm/{index,link,useNavigate,useRouter}.d.ts` and `src/{link,useNavigate}.tsx`: native generic `Link`, `linkOptions`, `useNavigate`, intent preload and registered-router inference.
- Router Core `dist/esm/{router,RouterProvider}.d.ts`, `src/router.ts`: `navigate`, `preloadRoute`, native lifecycle subscriptions and unsubscribe functions. Both navigation methods are instance arrow functions, so retaining their references does not lose their receiver.
- oRPC adapter `dist/index.{d.mts,mjs}`: exported `QueryOptionsOut`, tagged query keys and adapter-generated query functions forwarding Query's signal. No handwritten option producer is substituted.
- Query Core `src/queryClient.ts`: installed `ensureQueryData`, `fetchQuery` and `prefetchQuery` behavior. Types are imported through directly declared React Query, not an undeclared direct core dependency.

## Exact ownership and effects

- `owner.ts`: accepts the actual `ReturnType<typeof createAppRouter>` through a type-only import. Reuses `router.options.context.queryClient` and retains the native generic `router.navigate` and `router.preloadRoute` functions unchanged. `useNavigationOwner` gets the live Router and asserts the component provider uses that identical QueryClient. The memo is component-local; it does not create a cache or RPC utility tree.
- `index.ts`: aliases the native `Link`, `linkOptions` and `useNavigate` directly. Their original literal `to`/`from`, relative routes, params, validated search and masks remain intact. No `AnyRouter`, widened navigation facade, navigation-option cast or invented option is used. Internal routing uses native typed `to`/`params`/`search`; these aliases do not sanitize arbitrary external hrefs or replace an external-application URL policy.
- `navigationRouterDefaults`: typed against actual Router options, exposes `defaultPreload: "intent"` and **`defaultPreloadStaleTime: 0`** for the later central-router join. It is not applied while existing router ownership is frozen. Native Link supports `preload="intent"`; imperative preloading is native `preloadRoute(options)`, not a fake `navigate` flag or independent prefetch cache.
- `query-loader.ts`: accepts the adapter's native `QueryOptionsOut` and keeps its query key/query function, runtime metadata and other produced properties. `createRouteQueryLoader` closes over the supplied owner QueryClient. Route loader calls must pass `context.queryClient`, the actual producer's finite `.queryOptions(...)` output and `abortController.signal`. Components must use the same producer/options and provider client.
- Critical policy is mandatory. `freshness: "cache-acceptable"` uses `ensureQueryData` with an explicit `revalidateIfStale` boolean: existing stale data can be returned; revalidation is background-only. `freshness: "fetch"` uses `fetchQuery` with `staleTime: 0`, awaiting a Query-owned fetch or deduplicated in-flight fetch rather than authorizing from a stale cache. Neither mode supplies server authorization or guarantees transaction/current-permission authority. The returned loader data is the query-function output, not an observer `select` projection.
- `prefetchFiniteQuery` delegates to the same client's native `prefetchQuery`. It returns a promise for optional warming, does not block navigation unless explicitly awaited, and inherits native swallowed-error behavior. Critical failures use `loadFiniteQuery`, not this prefetch method.
- Only finite ordinary queries with real input belong in these loader helpers. Do not pass disabled/skip-token queries or live/streamed/infinite options; their structural option compatibility is not proof of finiteness or adapter provenance. Streaming activation and its lifecycle remain the producer owner's responsibility. Query retries, transport, cache identity and per-principal transitions are not reimplemented here.
- `scope.ts`: a scope abort rejects only the local wait, removes its AbortSignal listener and suppresses late success delivery. It never changes the adapter query function's signal and never calls `cancelQueries`, removes shared cached data or cancels someone else's Query request. Query settlement also removes the listener, and detached query rejection is handled. Underlying work can continue after local abort.
- `intent.ts`: component-local `open` supersedes a prior intent; `close` ends it; `run` bounds an asynchronous local result to its intent and closes it on settlement. Installed Router `onBeforeNavigate` and `onResolved` close current intents; effect cleanup unsubscribes both listeners and closes on unmount or Router replacement. No subscriptions run at module evaluation, during render or SSR. Opening requires the mounted effect scope. Call `close` when its UI intent closes; an `open` caller must check its signal before applying an awaited result, or use `run` for suppressed late completion. This is UI result ownership, not network cancellation or server-mutation rollback.
- Native `navigate` retains its original completion promise and blocker/redirect behavior. Await it directly when Router completion is needed; scope it with `waitForNavigationScope` only to stop a local wait. An open UI intent is intentionally invalidated when navigation begins, including navigation it triggers; do not treat intent completion as a navigation-commit receipt or evidence that a mutation was undone.

## Current route coverage

Type coverage derives from the unchanged generated tree, not a new list of legacy destinations: `/`, `/about`, `/about/status`, `/about/runtime/$section`, `/manage` and `/management`. The generated tree also has `/about/` as a full path. `/about/runtime/$section` requires `section` and retains the existing optional `view: "summary" | "details"` validated-search inference. Its loader's existing `section === "foundation"` check is not replaced by a permissive validator. The management entries do not become authorized or implemented through this seam.

No current route consumes the new helpers yet. No legacy board, auth, setup or management route has been converted here. Existing authorization, private-loader gating and frontend route audits remain held.

## Required later joins

1. After A01/A02 route/router audit release, the router owner applies `navigationRouterDefaults` centrally, without creating a replacement Router or a competing QueryClient. Reconcile central context with the approved Query producer's actual exported owner/client types; do not import the mutable producer as accepted evidence now.
2. The approved producer supplies native adapter `.queryOptions(...)` outputs to finite loaders and component Query hooks. Bind search-dependent query input through real validated search and `loaderDeps` in the route owner. Choose cache-acceptable versus fetch deliberately for each route; fresh Query data still cannot authorize backend operations.
3. Route/feature owners switch internal user links to native `InternalLink` and imperative navigation to the native hook/owner functions. Use typed options, preserve recovery/blockers and close open-intent scopes on UI dismissal. Scope local asynchronous results separately from shared Query cancellation.
4. Preserve existing SSR success-and-positively-public-only query dehydration and `shouldDehydrateMutation: () => false`; this seam changes neither callback nor publication policy. Request-local authorized clients/caches and browser principal/permission-transition isolation still need the owning composition join. Do not expose private query results in HTML by adding metadata alone.
5. Dedicated `@tanstack/react-router-ssr-query`/`@tanstack/router-ssr-query-core` integration is not installed and is not imported. Retain the installed Router hydration callback path unless its owner explicitly selects, installs and verifies the compatible exact family. Do not combine both hydration owners or install latest implicitly.
6. Backend/private authority, new route composition, producer integration, SSR disposal/serialization and compilation/runtime checks remain pending owner approval. This handoff makes no all-routes-converted, production-readiness, fresh-authorization or server-mutation-rollback claim.
