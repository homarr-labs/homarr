## Actual CSRF contract and browser ownership

Source basis is frozen `packages/auth/nitro/production-sessions/origin.ts:63–128`, `onboarding.ts:795–814`, and `packages/auth/nitro/session-primitives/index.ts:26–35`:

1. Exact **GET `/api/onboarding/claim`**, no query/fragment/body, returns a default-200 actual Response with **JSON `{ token }`**, application/json, no-store and the issuer-produced Set-Cookie. GET permits absent Origin or the canonical origin; Fetch-Site permits absent, same-origin or none. Canonical Request URL/Host admission remains server-owned.
2. The token is **64 lowercase hex nonce characters + `.` + absolute expiry milliseconds**, generated by the issuer's configured clock/lifetime. The cookie name is configuration-derived: `${hostPrefix}${prefix}.issuer-csrf-token`, where secure hostPrefix is `__Host-`; no concrete prefix/name is invented. Its encoded value contains `token|HMAC`, with Path=/, HttpOnly, SameSite=Lax, configured Max-Age and Secure when configured. It is distinct from both Core `/api/auth/csrf` and `homarr-onboarding-claim`.
3. Every write uses the **unchanged GET-returned token** in **`x-homarr-csrf-token`**. Server POST admission requires canonical Origin, rejects cross-site, compares header to the single issuer-cookie token, verifies its origin/cookie-name-bound HMAC and validates configured expiry bounds. The browser never computes a nonce/signature, sets Cookie, reads an HttpOnly cookie, or manufactures Host/Origin/Sec-Fetch-Site/forwarded headers.
4. Browser GET/POST use same-origin credentials, no-store, redirect:error and the initiating signal. Validate GET status/content type and finite object/token shape, safe positive expiry and local non-expiry before caching or POST. Do not guess the configured TTL or claim to verify HMAC. Browser JS cannot inspect Set-Cookie: authentic issuance is grounded in A's actual Response; actual C forwarding and browser cookie application require later proof.

The CSRF cache belongs to the browser onboarding transport lifetime and canonical origin, not a user DTO, SSR/global server singleton, TanStack query data, localStorage, log or mutation input. Claim and the generated write link share this same source; authenticated-admin writes also acquire genuine GET CSRF rather than borrowing anonymous claim authority. Headers resolve it immediately before SDK transport; caller abort/currentness/origin and token expiry are checked again before fetch.

Use one coordinated in-flight GET/cache generation. Do not overlap cookie-replacing refresh with an admitted claim/RPC POST; concurrent cache consumers must not independently rotate the issuer cookie and strand another token. An aborted/stale GET cannot populate a newer generation. The later installer must bind disposal/reset to its actual browser lifetime; a missing installer is not supplied by a static module export.

Reset cached token/GET ownership on disposal, origin change, expiry, unsuccessful/malformed GET, or write authority/transport failure. Before a **new explicit intent**, an expired/missing token may trigger a new non-mutating GET, under that intent's bounded signal/lifetime. Refresh does not extend claim expiry, restore authority, reset server clocks or retry the previous mutation. Once POST fetch has begun, abort, network loss, malformed output, ordinary error, ambiguous settlement or publication failure must never trigger an automatic second POST, nonce/force substitution or implicit claim reacquisition. A refreshed CSRF cookie is not reconciliation of a possibly committed command.
