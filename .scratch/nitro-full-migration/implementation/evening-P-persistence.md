## 2. Ready infrastructure epoch join versus Auth adoption

**Ready proposal:** coordinator adds public DB subpaths `./runtime-state` and `./runtime-history` in `packages/db/package.json` (currently absent). H's fixed private main-owner composition awaits SQL/content readiness, then the existing epoch initializer once, then constructs state/history with that exact returned epoch and explicit owner lifetime/budgets/registrations. Initialize before consumers/jobs/subscriptions; dispose consumers/Auth before main. No new schema, migration, counter service, reseed, environment discovery or default limits are needed for this join.

Ordinary restart retains `homarr_runtime_meta.id=1`, persistent values, absolute expiry and history sequence heads. A sentinel is initialized; missing/malformed metadata rejects. Initialization ambiguity is a failed startup requiring reconciliation, never automatic replay. Main readiness must remain unpublished until initialization settles; track the underlying task separately from any ready wrapper awaiting disposal.

**This infrastructure epoch is not `Principal.sessionRevision`, credential lifetime, permission generation or a database-replacement revocation ledger.** Foundation `packages/contracts/src/request.ts:1–3` requires real credential revision. Current `session`/`apiKey` schemas (`schema/sqlite.ts:38–46,102–114`), fixed session contracts/statements and A's snapshots contain no durable revision/adoption evidence.

The existing `AUTH-CREDENTIAL-REVISION-DESIGN.md` is explicitly a recommendation, not an accepted storage implementation. Its smallest concrete candidate is two credential evidence columns plus one enduring Auth singleton (`namespace/head_sequence/initializing-or-ready`). This is an additive authority model, not runtime-state keys: public state mutations create their own transaction and copied-runtime reset clears those keys. Preserve same-token renewal lifetime, separately advance private write evidence, conserve all original credentials/profile/accounts/grants, and never infer new lifetime from grants or expiry.

## 3. Board source seams and the smallest atomic tranche

Current `BoardMutationResources.execution` has **only** `kind: "hold"` (`packages/api/src/nitro/routers/-board-mutations/resources.ts:13–17`). All17 candidates are held before handlers (`board-mutations.ts:96–122`). `createBoardContribution` registers only the nine existing read leaves (`routers/board.ts:16–46,233–240`). R must not register all candidates simply because a producer exists for a subset.

`handleTransactionsAsync` is the alias of the driver selector in `packages/db/transactions.ts:16–25`; it does not begin a native transaction or bind an actor. Async Board handlers cannot be wrapped wholesale in bounded SQLite: awaited relational reads and DNS violate its synchronous contract. API's static schema is SQLite-shaped; PG must use its actual engine schema/fixed engine-qualified statements, not casts.

**Recommend first producer: only `saveUserBoardPermissions` and `saveGroupBoardPermissions`.** Their complete source operation is permission check then delete-and-replace, including empty arrays (`board-mutations.ts:1242–1316`). No layout repair, DNS, media/style or name-predicate work is required. Move both checks and the entire replacement into one fixed bounded producer, rather than retaining the outside `throwIfActionForbiddenAsync` as authority. Other15 candidates remain HOLD.

Proposed P-owned files: new `packages/db/runtime-board.ts`, `packages/db/runtime-board/{contracts,statements}.ts` (roots globbed absent), plus the fixed method in `packages/db/runtime.ts` and an opt-in fixed PG board admission in `packages/db/transaction-gate.ts`. Reuse the typed SQL-generator/execution shape in `runtime-auth-session/statements.ts:19–20,318–339` for separate synchronous `.all/.run` and awaited PG execution. No generic `nativeAtomicApply`, caller SQL batch, authorization callback or DB→API import.

Proposed exact initial mutation contract:

```ts
type BoardPermissionsMutation = {
  readonly kind: "replace-user-permissions" | "replace-group-permissions";
  readonly boardId: string;
  readonly permissions: readonly {
    readonly principalId: string;
    readonly permission: BoardPermission;
  }[];
};

boardPermissionsMutationAsync(
  operation: BoundedTransactionOperation,
  mutation: BoardPermissionsMutation,
  credential: BoardCredentialEvidence,
): Promise<void>;
```

`BoardPermission` is the existing definitions type. `BoardCredentialEvidence` must be the accepted DB/Auth-private discriminated session/key witness: original locator/user/provider, exact stored expiry or verified bcrypt hash, and selected durable lifetime/write evidence when activated. Not a principal permission array, public revision string or caller-created authority receipt. A alone extracts it from a lease it actually owns; the full runtime/method remains private to that fixed binding. P captures the mutation before awaits and rereads credential/actor/memberships/expanded grants on the **same** native transaction before first Board DML. API-key bcrypt stays outside SQLite, followed by exact locked witness revalidation. Missing adopted evidence cannot default to a usable witness.

SQLite: synchronous immediate admission protects current authority, current Board creator/grants, deletion and all replacement rows through root COMMIT. PG: fixed preamble verifies READ COMMITTED; reconcile the accepted global credential/writer lock order first, then lock actor and relevant user parents canonically, exact credential, relevant group parents canonically, and Board parent `FOR UPDATE`; reread complete global and Board grants after locks. Board parent serializes **every** grant/content/repair/placement writer, including insertion into empty grant/layout sets. Relevant user/group locks must also cover authority-changing deletion cascades; locking only existing child grants is insufficient. Any incompatible enabled writer blocks mounting, not merely that writer's own endpoint. Preserve actual full/modify/view/global expansion and missing-as-NOT_FOUND policy; no admin shortcut.

Keep actual authority expiry bound in `operation.deadlineAt` **before** native gate creation, joined credential/config/owner/request lifetimes, and held SQL facts through G's scope/tail drain and COMMIT. A separate currentness read before/after COMMIT is not the protocol. PG generic callbacks cannot issue `LOCK TABLE` because `statementKind` forbids transaction control; any required absence/table admission belongs in the fixed native preamble, not a widened SQL escape.
