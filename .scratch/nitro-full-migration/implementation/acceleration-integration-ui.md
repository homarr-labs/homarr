## Direct client and provider contract

`index.ts` exports the pages, create modal, catalog, form, embedded editor, access settings, completion and feature provider. `client.ts` derives all procedure/client input/output types from `RouterClient<Pick<ReturnType<typeof nativeFactory>, ...>>`. No old tRPC client hooks, tRPC-derived UI result types, Next API wrappers, arbitrary data/controller callbacks, or demo integration rows are used by these feature components.

The injected `IntegrationFeatureClient` requires these actual procedure members:

- `integration`: `all`, `byId`, `getKinds`, `testConnection`, `delete`, `create`, `update`, `getIntegrationPermissions`, `saveUserIntegrationPermissions`, `saveGroupIntegrationPermissions`.
- `certificates`: `addCertificate`, `trustHostnameMismatch`.
- `app`: `selectable`, `create`.
- `user`: `selectable`.
- `group`: `selectable`.

Its integration types derive from the frozen `createIntegrationManagementProcedures` and `createIntegrationOperationsProcedures` factories, not from a substitute router. Other types derive from the actual certificate/app/user/group factories. The factory references currently use type-only relative imports because not all native factory modules have public package exports; no factory is imported into the browser at runtime. Prefer public type-only entrypoints if the coordinator publishes them, especially the integration, integration-operations and certificate factories.

`IntegrationFeatureProvider` consumes the direct client, canonical `BackendPrincipal`, `readOnly` and an opaque **non-secret** `authorityKey`. The host must change that key on session/identity/authorization scope transitions. The provider remounts the feature scope, drops drafts/notices, scopes query keys and suppresses late create/app-selection callbacks from a replaced scope. It does not mint authority or infer permissions from untrusted UI flags. Native backend guards remain authoritative.

Query keys start with `["native", authorityKey, userId, "integration"]`; detail and grant keys append their actual integration IDs. Integration writes invalidate that prefix and `["native", authorityKey, userId, "widget"]`. If the widget lane settles on a different key scheme, the coordinator must reconcile this invalidation contract before mounting.

Queries pass TanStack Query abort signals directly to oRPC. Mutation retries are disabled. Certificate bytes, names, issuer fields, serial numbers and fingerprints are displayed/sent as returned; the UI performs no credential-substring redaction, PEM re-encoding, trust-policy repair or grant-policy repair. A successful certificate mutation merely enables retry, not a successful connection claim. Q18 and all existing native execution/authority holds remain unresolved by this lane.
