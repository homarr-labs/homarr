### Independent review P2 — certificate-only correction

Re-read the source `map-test-connection-error.ts`: `mapCertificate` derives the public issuer, subject, serial number, fingerprint256, PEM, Dates, self-signed flag and recursive issuerCertificate directly from X509Certificate. They are canonical certificate material/identifiers, not credential-bearing diagnostics. A valid one-character API key `A` caused the prior substring redactor to turn `CERTIFICATE` into `CERTIFIC[REDACTED]TE`; matching characters inside PEM, identifiers or the issuer chain could likewise corrupt certificate import/hostname/trust workflows. This rationale is source comparison, not an executed reproduction.

The sole code correction passes `mapped.data.certificate` through directly and deletes `redactCertificate` plus its sole unused `MappedCertificate` type import. The original mapped object and full issuer chain are neither rebuilt nor traversed: their material/identifiers remain byte-exact. `createSecretRedactor`, `redactMappedError`, common name/message/cause redaction, status URL redaction and every other helper/router/resource operation are unchanged. No global credential-redaction disablement, raw private-error exposure, new parser/validator/library, TLS/mapper-foundation repair or policy change was made. This patch lease touched only the named helper and this handoff; all other code remains frozen.
