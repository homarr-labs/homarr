## Exact contracts and safety semantics

`WidgetEditorClient` is `RouterClient<{ widget: ReturnType<typeof createWidgetProcedures>; customWidget: ReturnType<typeof createCustomWidgetProcedures>; integration: ReturnType<typeof createIntegrationManagementProcedures> }>`. `BoardEditorClient` is `RouterClient<ReturnType<typeof createBoardMutationProcedures>>`. Inputs/outputs use `InferClientInputs`/`InferClientOutputs`; `BoardDraft` is the actual `saveBoard` input and is not a parallel schema.

`WidgetDraftWriter.stage` is only an integration seam, with `create`/`configure` changes and `staged`/`rejected` results. No implementation is supplied. A reported staged draft is checked against source `boardSaveSchema`, board ID, item presence/kind, item identity on configure, and exact options/integration IDs/advanced options. This is local acceptance checking, not proof of atomic persistence, correct layout allocation, or complete producer invariants. The coordinator must supply and review the actual whole-board producer before enabling this flow.

Embedded editors must implement `submitIfDirty(): Promise<boolean>` and `isDirty(): boolean`. Close checks query handles at close time rather than relying on a stale render. Integration editing requires full access; picker membership requires use access. Permission props are UX gates, never a substitute for native server admission. Embedded and secret saves can precede board staging and are not described as a shared transaction.

Read-query functions pass TanStack cancellation signals to native calls. Mutation handlers use local locks and do not automatically retry. Authoring preview creation/load workers use generation and mounted checks; changes invalidate preview evidence locally, and stale child preview results cannot restore an invalidated preview. Editing preview options requires a new preview. Actions default to simulation; live enablement has explicit confirmation. Action confirmation dispatches its captured session/request/parameters, not a newly parsed mutable draft. Tested persistence uses only `createFromPreview`/`updateFromPreview`; the server decides evidence sufficiency. Ordinary create/update is not represented as a tested save.

JSON configuration fields retain malformed text drafts and report nested invalidity instead of committing invalid JSON. Source default/version normalization updates configuration only when editable. Definition/template/source forms keep stable identities rather than remounting on every background version change. Template patches retain the original captured revision so concurrent changes fail rather than silently replacing the dirty baseline.

## Validation hold

### Bounded four-P2 fix lease — frozen for independent rereview

Only `apps/nitro/src/features/widgets-editor/` and this handoff were changed for this lease. The four requested corrections are implemented by source inspection, not validated by execution:

1. `contracts.ts`, `widget-editor.tsx`, `custom-widget-configuration.tsx`, `release-repositories.tsx`, and `widget-secrets.tsx`: `SpecializedOptionProps.onDirtyChange(property, dirty)` reports field-local draft dirtiness separately from `onValidityChange`. Dirty-close checks include malformed Custom JSX option JSON, unsaved release-token text, and repository modal drafts. JSON text is compared with its captured pristine text even when parsing fails or only formatting changes. Reverting a field clears its flag; successful token writes clear the corresponding flag, while failures retain it. Token reporters pass only field identity and a boolean, never token contents; no secret text enters editor state, preview options, or the dirty metadata. Unmount cleanup removes field registrations. Future genuine specialized bindings must report their local drafts through this contract; missing bindings remain held.
2. `widget-editor.tsx`: local option/title/integration updates use functional current-state merges. Preview receives a distinct callback bound to the captured editor generation and preview lifetime; it checks both before enqueueing and inside the functional updater. Local edits, local-draft reports, size changes, close/discard intent, staging, and integration creation invalidate retained preview callbacks synchronously. Preview lifetime also changes with state, identity, transport, renderer, settings, size bounds, permission/lock eligibility, and open/discard transitions; layout-effect cleanup removes the active lifetime on unmount. Obsolete patches cannot replace newer integration IDs, advanced options, or option keys. Cancelling discard does not revive a pre-close callback; cancellation itself is not authority for a preview result. No renderer or preview implementation was supplied.
3. `widget-editor.tsx`: the rounded/clamped initial size is captured once as `pristineSize` and also initializes size state. Dirty comparison uses that baseline, not the unclamped caller size. A 10-column Assistant entering a 3-column destination therefore begins clean with respect to size; changing size away from and back to the captured baseline restores cleanliness.
