## Candidate contracts for review

- `PolicyIdentity` is anonymous or authenticated `{userId, groupIds, permissions}`. It contains no cookie/token/credential DTO. Identity resolution must supply current server-derived memberships and **expanded** permission keys, not browser input or indefinite cached credentials. Resource authorization captures immutable identity arrays across awaits via `snapshotPolicyIdentity`.
- `AuthorizationDecision` is `allow` or `deny` with `unauthenticated | forbidden | not-found | invalid-claim | wrong-step | demo-read-only`. `AuthorizationError` contains only that reason and a safe message; the backend owner maps protocol codes/messages. Booleans/decisions are not capability tokens authorizing later unrelated resources.
- `ResourceAuthorizationRepository<TIntegration>` supplies `findBoard(identity,id)`, `findBoards(identity,ids)` and `findIntegrations(identity,ids,allowedKinds)`. Rows include actual user/group grant IDs, not only permission values. The physical owner must provide scoped, coherent immutable snapshots from explicit resources; these ports implement no SQL/global DB initialization. Defensive filtering does not authorize exposure of unfiltered repository rows.
- `IntegrationExecutionEvidence` extends the source policy row with saved `name/url/externalUrl` and encrypted `kind/value/updatedAt` rows. This is **server-only**. Repository selection/ACLs/placement/URL/ciphertext must refer to one coherent snapshot; all authorization must succeed before any codec or upstream work. Execution callbacks receive only explicit saved metadata/decrypted secret kinds, never ACL or ciphertext DTOs.
- Execution options require explicit identity/demo mode/selection/allowed kinds and discriminated action/operation. Interact/full are mutation-only and are checked again at runtime. Full execution also requires authentication. Caller-supplied paths/methods/origins cannot enter a native-query operation merely because that caller can view a public board.
- `SecretCodec` is an injected four-function codec; `createSecretCodec` supplies the source-preserving explicit-key implementation. Restore may supply its reviewed conversion codec separately; this production codec does not resolve legacy key acquisition, zero-key archive recovery, key rotation or all-family conversion.
- Public field projection requires the existing source `integrationSecretKindObject`, not a private-field allowlist invented by this module. Plaintext execution is callback-local and its response must pass a public JSON projector/redaction. This boundary is not a universal data-loss-prevention guarantee: domain owners still enforce their concrete schemas, bounds, log redaction and trusted outbound destinations.
- `SetupAuthorizationEvidence` accepts only server-validated claim status/current no-users/current-step evidence. #109 owns hashing/expiry/claim storage/locking and transactional onboarding transitions. A claim never creates an administrator identity. Domain callers must combine demo mutation, setup and resource gates as in source; the pure individual decisions are not a blanket authorization service.
- `SecretSourceBinding<TAuthentication>` is a candidate adapter shape for the existing Custom JSX binding algorithm. Its auth comparator must be the real domain helper. Assistant destination-change clearing, Custom JSX source/config-token ownership, source-ID matching/auth-kind validation, network/origin validation and arbitrary HTTP path/method/confirmation enforcement remain with their existing feature/runtime owners. No new provider policy is implied.
