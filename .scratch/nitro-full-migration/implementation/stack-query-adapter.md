## Frozen typed seam

`createExpansionQueryScopeOwner(ownerQueryClient, runtime)` accepts the existing QueryClient and an explicit `browser`/`server` lifetime. A WeakMap keyed by the supplied QueryClient reuses its owner; it creates no global or replacement QueryClient and does not share a server cache between requests. Reusing that QueryClient with a different runtime is rejected. The request owner must still provide a genuinely request-local QueryClient/cache and authorized client; this seam cannot repair a shared server cache.

`owner.acquire(client, identity)` accepts only the type-only `ExpansionApiAssemblyClient` public contract from `@homarr/api/nitro/assembly/client`. `ExpansionQueryUtils` is the actual library `RouterUtils<ExpansionApiAssemblyClient>`: no `AnyRouter` erasure, manual query adapter, DTO remapping, procedure inventory or result controller. The existing assembly's 161-leaf composition inventory is retained through inference, not independently runtime-counted or certified here. API router/server implementations are not imported at runtime.

The immutable copied identity requires six nonempty, non-secret cache partitions: `cacheLifetimeId`, `clientCacheId`, `principalCacheId`, `permissionRevision`, `boardCacheId`, and `boardRevision`. The adapter receives one deterministic string prefix derived from these fixed fields. Within one supplied QueryClient, identical identity values and the same client instance return the same scope and utility tree. Rebinding that identity to another client is rejected. Retired prefixes cannot be reacquired; active entries are dropped on retirement while prefix tombstones prevent old handles from colliding with a replacement.

These strings are display/cache isolation identifiers, not authorization evidence. Their non-secret provenance and revision accuracy belong to the caller; nonempty validation is not a secret detector or authority check. Never supply session cookies, bearer tokens, preview/configuration tokens, principal DTOs or credentials as cache identity. Changes in principal, permission, board revision or client authority require a different identity and retirement of the old scope. oRPC client context is still excluded from operation keys; changing context alone does not partition the cache.

The returned frozen shell exposes `queryClient` (the exact supplied instance), `orpc` (the actual stable utility tree), `identity`, `runtime`, `state`, `isCurrent`, `assertCurrent`, `invalidate`, and `retire`. The lifecycle is `active -> retiring -> retired`. `ExpansionQueryRouterContext` freezes the intended consumer type: `{ queryClient, orpc, queryScope }`; construct all three from that same scope. Freezing the shell does not recursively freeze the library's lazy utility proxies.

## Actual Query behavior

- Components, loaders and preloads must use the same leaf's real `.queryOptions({ input, ...options })` and the same `scope.queryClient`. All concrete input optionality, output/error inference and native Dates remain library-owned. No serializer, guessed Date transform, custom hash or JSON-mapped output is added.
- Query cache operations use real `.key()` and `.queryKey({ input })`; mutations use `.mutationOptions(...)` and `.mutationKey()`, passing input to `mutate(input)`. A real per-procedure adapter plugin rejects explicit custom operation-key overrides and fixes mutation options to `retry: false`, without mutating QueryClient defaults. There is no competing handwritten procedure-key namespace.
- The actual adapter query/live/streamed/infinite interceptors check the owning QueryClient, generated prefix, currentness and Query's real AbortSignal. They await and retain the real adapter execution promises, not cancellation flags or fabricated result records. The installed adapter still supplies that same signal to client calls; the eventual transport owner must preserve fetch `init` and its signal/headers/body.
- `invalidate()` only calls `invalidateQueries` on `orpc.key()`, checks currentness before and after, and uses Query's normal active-refetch behavior. It never invalidates other scopes or clears the whole QueryClient.
- `retire()` synchronously marks the scope noncurrent and tombstones its identity before any asynchronous work. Its one idempotent promise then awaits prefix-local `cancelQueries`, awaits all tracked underlying adapter query promises, and only then removes that generated query prefix. Waiting for underlying execution prevents a late native stream cache write from recreating the retired prefix after removal. A transport/iterator that ignores cancellation and never settles keeps retirement pending; no timeout or fake completed disposal is reported.
- Retirement removes only already-settled mutation cache entries matching this prefix. Pending mutations are not aborted, removed, awaited or retried. Mutation interceptors reject new execution under a retired scope and reject stale successful delivery after an already-started call resolves; this is not an undo, abort or assurance that a server mutation did not commit. Mutation inputs, optimistic writes, global/per-call callbacks and delayed effects still require consumer-owned currentness checks.
- Server scopes reject native live/streamed execution before RPC invocation. Ordinary/infinite query execution rejects an async-iterator result, invoking its available native `return()` first rather than caching an iterator as a snapshot. SSR owners must choose a genuinely finite snapshot procedure; the seam does not turn endless subscriptions into finite snapshots or start any prefetch. Native browser live/streamed behavior remains the actual adapter's behavior.

`assertCurrent()` and `isCurrent()` are local lifecycle checks, not server permission/COMMIT proofs. Network interceptors cannot guard a caller's direct `.call`, a cache hit, manual `setQueryData`, or arbitrary callbacks. Consumer joins must check currentness before a cached loader/read/write and again after awaited work, unmount old consumers before replacement, and await retirement before claiming disposal. Route-exit abort is not Query cancellation: never broadly cancel a shared query simply because one loader exits.
