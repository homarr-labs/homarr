## Outcomes and genuine errors

- **Admitted:** means the current legacy connector can attempt the real protected request, not native admission or guaranteed write success. Preserve the actual `void` resolution as the view's `confirmed` result; do not manufacture request records.
- **Unknown write:** any rejected/ambiguous request stays unknown with its original error. Send remains disabled. Label: “The request outcome could not be confirmed. Refresh the integration and check whether the request exists before submitting again.”
- **Reconciliation held:** a resolved write followed by failed cached-read reconciliation stays `reconcileheld` with original input/result/error. Label: “The request was accepted, but cached results could not be refreshed. Retry refresh; do not send the request again.” Existing view Try-again runs only the stored reconciliation closure.
- **Unknown refresh control:** since the shared view has no unknown retry, the connector can add one small read-only refresh control when the real mutation is errored. It invokes the same target-bound reconciliation/read path, never `mutate`, `mutateAsync`, `reset` or a new modal automatically. It cannot clear the shared unknown outcome or re-enable Send based on a read. Show its actual pending/error state locally; no empty catch/no-op hides failure.
- **Read failure:** present actual integration/options-query errors through a small Mantine error/output region and a gated read-only retry. Keep the pure content/table and its existing translations. For technical details narrow `unknown` with `instanceof Error`; no `any` or string-cast. Do not conflate options failure with an upstream write failure.
- **Stale completion:** the view may record its genuine local outcome while still mounted, but no stale success/error notification or close is permitted. In particular a completed write followed by stale reconciliation must not return artificial success from `onRequested`; reject/hold without resending.

Existing translations retain title, Cancel, Send, table and Try-again. The locale inspected has no specific unknown/held media keys, so the two explicit truthful connector labels do not pretend such keys exist. No translation-file lease or visual redesign is proposed.
