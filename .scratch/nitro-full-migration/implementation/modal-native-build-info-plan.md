## 3. What these two reader bodies actually establish

**Container dispatch, not full container decoding:** buildinfo.go reads16 initial bytes, then delegates to elf.NewFile for ELF prefix, pe.NewFile for MZ, macho.NewFile for thin Mach-O prefixes, macho.NewFatFile for two fat prefixes (selecting first arch), xcoff.NewFile for two prefixes and plan9obj.NewFile for imported magic constants. Constructors and format definitions are outside the admitted files. We cannot derive all header offsets, load-command layouts or exact magic/CPU constants from these calls. [B] lines115–163,273–282; imports13–29.

**Container-specific location/mapping is partly visible:** DataStart selects a named build-info section or a data segment; DataReader maps virtual addresses to a file-backed region. [B] lines101–110,165–178.

| Container                | Visible selected region /mapping rule                                                                                                                                                             | Missing definitions; no target-format assertion                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Mach-O                   | Prefer `__go_buildinfo` section Addr/Size; otherwise first nonzero file-backed segment with Prot and Maxprot both3. DataReader covers Addr through Filesz, skipping `__PAGEZERO`.                 | macho.NewFile /load, segment and section on-disk layout, endian/magic/CPU constants and file-offset mapping. [B]522–555 |
| ELF                      | Prefer `.go.buildinfo`; otherwise PT_LOAD with masked execute/write flags equal PF_W, using Vaddr/Memsz. Reads map via Vaddr/Filesz.                                                              | elf.NewFile /header, section/program layouts, constants and file mapping. | PE                       | First nonzero initialized readable/writable section meeting exact characteristics mask; DataStart uses ImageBase+VirtualAddress and VirtualSize, reads use raw Size after subtracting image base. | pe.NewFile /optional-header, section/file-offset layouts and image-base interpretation. Memsz/VirtualSize may exceed physical Filesz/Size: declared address ranges cannot be treated as file bytes or padded with invented zeroes. Every selected range and address→offset mapping needs primary definitions and physical bounds. [B]445–467,484–515,522–555.

**Blob discovery:** magic is14 bytes `\xff Go buildinf:`; header32 bytes; alignment16. searchMagic searches the selected virtual data range, rounds its start upward to alignment, checks range addition overflow and scans bounded chunks (1MiB), returning the first aligned instance. This is not a whole-file ASCII/strings search. A proposed reader must retain absolute virtual/file coordinates and accumulate offsets correctly; it should require a unique candidate in its selected range rather than choose arbitrarily among duplicate headers. Uniqueness is a proposed stricter safety rule, not the Go reader's first-match policy. [B]55–63,335–412.

**Header mode:** offsets14/15 are ptrSize/flags; version-pointer location16. Flag bit0 gives pointer endianness; bit1 chooses inline versus pointer mode. Inline mode follows the32-byte header with Uvarint-length-prefixed GoVersion then module text; pointer mode uses4- or8-byte pointers to Go string headers, each containing data pointer and byte length. Nonempty version is required. In inline mode the reference does not use ptrSize to decode strings. [B]191–261,284–333.

**Missing helper semantics:** decodeString delegates length decoding to binary.Uvarint and its MaxVarintLen64 constant; nonpositive consumed-count rejects invalid/truncated/overflow varint. The actual numeric maximum/bit accumulation and terminal-byte overflow rules are in an unadmitted helper. readData delegates allocation/read behavior to saferio.ReadDataAt; a builtin reader over one fixed-size Buffer can instead enforce explicit slice bounds without claiming to port saferio. [B]284–318,414–438.

**Module framing:** a nonempty decoded version can coexist with empty module info. The reader strips16 leading/trailing bytes only when module bytes have length≥33 and a newline at len−17; otherwise it replaces module text with empty. Its comment names modload.infoStart/infoEnd but does not supply sentinel byte values. Preserve raw framed bytes and report framing status; never turn malformed/unverified framing into a provenance-success empty module. [B]259–270. runtime ReadBuildInfo strips framing and injects runtime.Version for a running binary; this route must not be invoked. Offline Read instead assigns GoVersion from the decoded binary string. [M]20–37; [B]88–98.

**Textual records:** BuildInfo holds GoVersion, main package Path, Main module, ordered dependency modules and ordered Settings. Module has Path/Version/Sum/optional Replace. VCS keys are settings (`vcs`, `vcs.revision`, `vcs.time`, `vcs.modified`), not proof-bearing independent fields. They may be absent. [M]40–95.

ParseBuildInfo recognizes newline-terminated `path\t`, `mod\t`, `dep\t`, `=>\t`, `build\t` lines. Module lines have2 or3 tab-separated fields after their prefix, with empty Sum when omitted; replacement requires3 fields and an existing preceding module association, then clears that association. It does not independently authenticate module sums or revision syntax. Preserve raw line/offset and absent-versus-empty fields. [M]167–237.

Build setting key/value split is at an equals sign after any quoted key. Unquoted key must be nonempty and avoid `=`, space/tab/CR/LF/double-quote/backtick; unquoted value avoids space/tab/CR/LF/double-quote/backtick. Quoted keys use strconv.QuotedPrefix/Unquote; values use Unquote. These are Go quoting semantics, **not JSON.parse or a hand-waved escape replacement**; exact helpers are outside these bodies. [M]97–105,238–297.

Important permissiveness to NOT promote into verified output: ParseBuildInfo drops unterminated trailing data, ignores unrecognized line prefixes (including `go\t`), overwrites repeated Path/Main entries, and appends settings without uniqueness validation. Proposed static reader must retain raw data and HOLD on unknown/malformed/ambiguous records or duplicate singleton/VCS/settings keys rather than silently lose evidence. Strict immediate replacement association and unknown-record rejection are conservative subset policies, not claims about identical Go parser behavior. GoVersion must come from the binary header string, never the textual `go\t` line, host runtime, reference version or package gitHead. [M]110–112,153–175,199–297; [B]88–98.
