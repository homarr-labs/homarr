# EXPANSION35 Search frontend

## Freeze status

New candidate components live exclusively in `apps/nitro/src/features/search/`. They are not mounted, registered routes, or proof of accepted backend/runtime authority. Shared routes, providers, manifests, API implementations, and legacy files are unchanged. The global-tools owner retains spotlight opening, global shortcuts, modal chrome, context registration, settings providers, and session transitions.

Public exports:

- `SearchContent`: mounted search content, mode/query selection, keyboard results, app child actions, web/bang selection, integration results, and media child requests.
- `SearchEngineManagement`: `list`, `create`, and `edit` views supplied by the route owner.
- `createSearchRpcClient`: a same-origin, credentialed oRPC client using actual procedure-derived types. No hard-coded endpoint, request-on-construction, tRPC adapter, JSON guessing, or replacement backend.
- Typed `SearchBinding`, `SearchRuntime`, `SearchSession`, `SearchSourceHelpers`, context results, route intents, and management view contracts.

`SearchBinding.kind = "held"` is the truthful default until dependencies and helper provenance are accepted. Each native capability also requires an explicit ready/held authority. There is no inferred readiness from the presence of a constructor or a successful frontend type import.

## Authority and dependency holds

1. **Deletion remains unavailable.** The base native search-engine router lists deletion as pending. `search-engine-deletion.ts` provides a candidate but explicitly lists `searchEngine.delete` as binding-held. Its same-session dual-engine transaction and lifecycle authority have not been accepted here. The feature contains no delete client member/call, optimistic removal, confirmation-to-nowhere, or success notification. Users with `search-engine-full-all` see a disabled action and a visible reason.
2. **Bangs require accepted dataset resources.** `bangs.ts` records a held normalized dataset/trusted-fetch/cache lifecycle. `bangs-search.ts` is a real candidate constructor, not evidence of composed readiness. Keep `authority.bangs` held until its owner confirms composition/resource acceptance. No browser-supplied dataset or direct DDG request is used.
3. **Integration operations require owner acceptance.** Use native integration search/media constructors only after their snapshot, permission, execution, cache-generation, disposal, and request authority is accepted. The frontend never collects integration secrets or changes those resources.
4. **Missing workspace edges are not repaired here.** The inspected `apps/nitro/package.json` declares React, Mantine core/hooks, TanStack Query/Router, oRPC, and Zod; it does not declare `@homarr/api`, `@homarr/common`, `@homarr/spotlight`, `@homarr/validation`, `@homarr/forms-collection`, `@homarr/ui`, or translation packages. Existing dependencies were verified before authoring. Native API/source schema/helper references are type-only relative imports; no undeclared workspace package is loaded at runtime. The manifest owner must accept public type/helper edges before mounting.
5. **The source helper bridge is intentionally unbound.** `filterCatalog` is entangled with legacy client hooks and has no pure public spotlight export. `buildSearchUrl` is exported from a legacy tRPC-dependent component module; `parseBangQuery` and `localResultSort` are private. A source-owner extraction/export is required for the actual functions, alongside `shouldShowContextSpecificResult`, `queryCacheDefaultStaleTimeMs`, safe URL helpers, and the shared search-engine schema. Do not satisfy `SearchSourceHelpers` with copied matching/parser bodies or a legacy provider mount. The signatures avoid pulling the legacy tRPC graph into the browser bundle.
6. **Routes are intents only.** The route owner must map `/manage/search-engines`, `/manage/search-engines/new`, `/manage/search-engines/edit/$id`, and existing app/integration edit intents to registered TanStack routes using params, not interpolated `to` strings. `runtime.navigation.kind = "held"` reports its reason instead of pretending navigation succeeded. No shared/generated route file was edited.
7. **Chrome/provider binding remains external.** Supply current principal permissions, resolved search preferences, a scope containing principal/session revision, `isCurrent`, native endpoint, query provider, active-board context, and close/navigation handlers. Mount only while open and remount for changed scope/open intent. Global-tools owns context registration, settings refresh, focus containment/restoration, and global shortcuts. The content owns neither another provider nor global listeners.
8. **Visual/source edges remain frozen.** Icon URL editing is present; the source icon picker needs its undeclared workspace UI dependencies. English content labels are present, not a claimed completed translation port. Those integrations require the respective owners; no new icon library, translation provider, or fake icon catalog was introduced.

## Lifecycle and result truthfulness

- Queries consume React Query's AbortSignal directly in typed oRPC calls. Query keys isolate content and management, principal/session scope, native path, and query/target/scope input. Prefix invalidation does not append an undefined input segment. Closing search cancels only content reads, not management reads.
- Old queries remain in their own keys; only results matching the immediate settled token/query and ready source authority can be selected. Media scope `[]` means no eligible targets, not "all integrations."
- The host's current-session guard is checked before navigation and writes and again after asynchronous completion. No optimistic setting/search-engine/media mutation is presented as confirmed success. Unmount aborts pending writes; abort is not a rollback guarantee.
- Unknown write outcomes disable resubmission and direct users to verify actual state. Media success is shown only after the integration confirms its native request. Search-engine success is shown only after its native mutation returns.
- UI browse/interact checks preserve source behavior but do not replace backend authorization. Requested TV seasons and already-in-library movies are protected before submission.

- **Navigation lifetime:** both result-route and app-edit navigation capture a mounted, open content-intent revision. Query changes, mode changes, child entry/back, target return, close, unmount, and navigation/session/close-binding retirement invalidate pending intent and abort its controller. The guard runs before deferred owner dispatch and before completion/error updates. A stale completion cannot close a newer/reopened search or attach an old navigation error. The owner receives the real `AbortSignal` and `isCurrent` through `SearchNavigationLifecycle`; owners that support cancellation/currentness should consume them. This does not undo already-dispatched navigation when an owner ignores cancellation or cannot roll it back.
- **Open binding:** the host must still mount only while open and remount for a changed principal/session scope or open intent. `opened={false}` explicitly unmounts bound content; changing `openIntentRevision` remounts it even for the same principal. If these optional props are omitted, the existing host mount/remount obligation remains. Closed content is not made current merely because a callback binding changes.
- **Child focus:** app entry focuses the first usable owned open/edit/back control, with safe-link and disabled-action fallback. Media entry focuses its first usable control, Back to results. Owned refs and React layout effects perform this handoff only while current; there is no focus timer, new hook dependency, listener, layout redesign, or style change. Escape returns from a child without propagating to host close handling; the search input receives focus again on return. Existing pending-media-request back protection remains.
- **Preserved boundaries:** typed source matching helpers, safe destination validation, and disabled deletion remain intact. Native capability acceptance, private helper extraction/provenance, undeclared workspace/public type edges, and legacy-free browser-bundle acceptance remain held. No shared route, manifest, backend, legacy file, or active-peer implementation was edited.
