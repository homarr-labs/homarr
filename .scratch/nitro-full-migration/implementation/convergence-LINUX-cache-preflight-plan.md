## Evidence ceiling: do not overclaim

An ordinary number annotation establishes a TypeScript input requiring transpilation; it does not establish that a tiny input exercises a persistent-cache write path. Two successful runs with unchanged `/work` inventory establish only the observed result for this pinned dummy and envelope. They are not application dependency, startup, native, or future-fixture parity evidence.

Readonly root prevents successful ordinary writes there; it does **not** establish that an attempted write would necessarily fail the Bun process. A runtime may tolerate cache-write failure. Numeric zero therefore cannot prove no attempted cache writes, and before/after inventories cannot exclude transient create/delete activity. Do not label this probe a global no-write audit or independent proof of the cache implementation. The reviewed literal empty cache setting supplies the disabling rationale; the probe supplies narrow execution/inventory corroboration. No tracing, cache-mode permutations, larger fixture, or additional probe is required for that limited claim.
