Implementation uses only public guarded `.all/.run/.execute`, never native client/session/reflection access or `sql.raw`. The current website advertises newer beta work; no newer API was adopted in the pinned implementation.

## Exact implementation plan

1. Export local structural state operation/condition/write/snapshot interfaces matching `packages/redis/src/state/backing.ts`, without a DB-to-Redis dependency. Require the actual admitted PersistenceRuntime, captured initialized epoch, explicit backing lifetime, immutable server-owned exact-key/prefix registrations and finite operational caps. Registration is storage admission only, never authorization. Refuse excess concurrent operations without retaining a queue.
2. Provide separately invoked explicit epoch initialization. Use G3 bounded native transactions, lock PostgreSQL epoch row 1 FOR UPDATE before validating/locking mutex row 2, validate both metadata rows, generate a UUID only if row 1 is still the catalog sentinel, and return the committed installed winner. No imports initialize, reseed, open pools, or start timers.
3. Read through one materialized SQL-clock/epoch/requested-key SELECT, including empty requests. Decode unknown rows and reject stale epochs/malformed physical values. Preserve exact serialized strings and explicit null absence. Use G3 bounded execution to retain actual acquisition/native settlement ownership; SQLite's currently accepted bounded gate uses BEGIN IMMEDIATE even for the single-statement read.
4. Mutations use G3 bounded SQLite synchronous BEGIN IMMEDIATE or PostgreSQL epoch FOR SHARE followed by state-mutex FOR UPDATE. After locks, observe SQL wall clock once, read the bounded key union in parameter chunks, and check every exact condition before any write or cleanup. A failed condition returns the requested same-observation snapshot without state changes.
5. Precompute and validate the complete ordered write plan, including repeated keys, before physical DML. Preserve fractional expiry; null TTL is persistent, nonpositive set TTL deletes, increment TTL must be positive. Canonical Redis decimal counters use checked signed-64-bit bigint and reject invalid lexical forms/overflow. Execute ordered upserts/deletes with bound values and validate native effects. Return a detached post-write snapshot at the original observation.
6. Recheck host signal/lifetime/deadline and SQL wall-clock expiry of originally satisfied non-null expiring conditions before returning to G3's actual COMMIT-dispatch fence. Refreshing or deleting an owner row cannot bypass its original expiry. Never retry ambiguous COMMIT. G3 owns rollback/cleanup/quarantine/native drain. Optional physical sweeping and all scheduling remain unmounted/held unless implemented explicitly in this scope.

### Exact host join

1. Supply the admitted main `PersistenceRuntime` after SQL/content readiness. Await `initializeRuntimeStateEpochAsync({ runtime, lifetime, maxOperationMs }, { signal, deadlineAt })` explicitly before consumers. Do not automatically retry an ambiguous initialization commit.
2. Construct `createRuntimeStateSqlBacking({ runtime, epoch, lifetime, registrations, limits })`. Registrations are bounded immutable exact-key/prefix declarations provided by the server; no key string grants permission. Runtime initialization/provider/session/authorization policy is not inferred.
3. `limits` requires every field: `maxPendingOperations`, `maxOperationMs`, `maxKeys`, `maxConditions`, `maxWrites`, `maxKeyBytes`, `maxValueBytes`, `maxInputBytes`, `maxObservationBytes`, `maxSnapshotBytes`. Operational values remain an explicit host choice. Hard implementation ceilings are 256 union/read keys, 512 conditions, 512 writes and 512 registrations; SQL reads use at most 128 keys per chunk. No default policy is silently selected. Overflow refuses admission without a queue/replay.
4. Consumer owner must confirm structural assignability to `AtomicStateBacking` when wiring. Coordinator must add the package subpath export `./runtime-state` if consuming it externally; no manifest was edited here. The approved runtime catalog/migrations remain prerequisites, not generated by this backing.

### Atomicity argument from source, not executed proof

- Every mutation uses G3's tracked native transaction. SQLite owns synchronous BEGIN IMMEDIATE with the accepted scoped zero busy timeout. PostgreSQL owns one checked-out client, epoch row 1 FOR SHARE, then mutex row 2 FOR UPDATE; all awaited statements remain on that client. Initializers instead lock row 1 FOR UPDATE before row 2; no shared-to-exclusive upgrade exists.
- Database wall time is observed only after mutation locks. The entire condition/write/read key union is read with expiry predicates against that same observation. Every exact raw-string/null condition is checked before any state DML. Failed conditions make no state writes, including no cleanup.
- The entire ordered write plan is validated before its first DML. Repeated keys preserve supplied order; nonpositive set TTL deletes, null TTL persists, increment TTL must be positive, and positive fractional TTL is stored without rounding. Unrepresentable clock-plus-TTL arithmetic fails. Counters reject whitespace, plus signs, leading zeroes, negative zero, fractions, noncanonical text and signed-64-bit overflow; missing/expired counters start at 1.
- Each actual upsert/delete validates native `.changes`/`.rowCount`. Requested post-write keys are physically re-read under the same lock with the original observation, decoded and compared with the validated plan. Returned objects contain detached primitive strings/null values only, and frozen records safely preserve even keys such as `__proto__` via `Object.fromEntries`.
- Originally satisfied non-null conditions retain their original expiry separately from the write plan. After all DML and response decoding, a fresh SQL clock rejects an expired original fence, even if the writes renewed/deleted it. This is a pre-COMMIT SQL observation, not a new SQL-clock hook at the native COMMIT dispatch. G3 separately fences actual dispatch with host abort/lifetime/deadline. A lease can advance during the subsequent native dispatch/commit interval; no hard-real-time SQL-clock-at-durability guarantee is claimed.
- Validation/SQL/expiry failure before dispatch rolls back all writes through G3. Already-dispatched commit/cleanup failures propagate G3's `TransactionCommitAmbiguousError` unchanged, with zero automatic retries or payload replay. Native contention/races/clock edge cases remain pending coordinator execution.

### Lifetime and bounds argument from source

Constructor captures epoch, lifetime, limits and registrations. Each call captures its payload and operation signal/deadline before asynchronous checkout; later caller mutations cannot alter admitted keys/writes. Both backing lifetime and operation abort/deadline are checked at entry, after queued locks, around every chunk/DML and before returning to G3. Host wall deadline and monotonic elapsed budget are separate from database expiry time. Per-backing admission remains active through awaited native COMMIT/rollback/cleanup/release; `finally` decrements only after G3 settles. Runtime maintenance/close still fences and drains its actual native resource, not a caller-side timeout promise.

No timer, listener, pool/connection creation, ambient DB, Redis import or sidecar exists. SQL suppresses oversized value transfer rather than truncating/fabricating a value; live oversized values fail decoding. Input, observed mutation rows and returned snapshots have independent explicit byte caps. NUL-containing or ill-formed Unicode text is rejected rather than being changed by PostgreSQL text encoding. Extremely small positive TTLs that cannot advance the current IEEE-754 timestamp fail instead of being rounded into a different policy.

### Held, not implemented/claimed

- No physical expiry sweeper/scheduling: expiration is logically enforced by SQL predicates, nonpositive TTL/delete performs exact physical deletion, and ordinary overwrites replace expired rows. Optional bounded sweeping requires a later concrete allocation/join; failed CAS never cleans rows.
- No package export/host mounting, generation/cache/status wrapper, local publication, cross-process fanout, authority/session decoding, maintenance restore/reset/export policy or provider operation. History/jobs use their independently allocated frozen contracts; none of their mutable files was read.
- Read-only snapshots deliberately use one SELECT inside G3 bounded execution. SQLite's frozen bounded surface uses BEGIN IMMEDIATE even for these reads; contention can therefore surface as unavailability. No runtime/gate extension was invented to hide this limitation.
- G3 cannot promise hard-real-time cancellation of native pool acquisition or already-dispatched COMMIT. Pending acquisition remains runtime-owned until settlement; post-dispatch ambiguity is not a successful/rolled-back claim.
- No lint/typecheck/build/tests/format/install/live SQL/runtime execution or Git action ran. Dedicated source reads/searches and documentation retrieval only. Mandatory final lint/typecheck, relevant existing checks and integrated disposable native-SQL contention/CAS/owner-expiry/cancellation/restart proof remain required after independent freeze review.
