# Seeded SQLite file startup — preservation route plan

## Decision and authority

**A genuine memory-born ready credential domain can be carried into an existing-file MAIN startup without file first adoption. The native snapshot/copy/reopen primitives exist. A closed, exact-record preservation proof is not available through today's callback-free MAIN ports; its fixed observation/export join and finite filesystem consumer remain prospective.** Do not represent this as a completed proof, restore, ordinary self-hosted installation, or accepted fresh-file adoption.

The requested sequence is the right prospective SQLite route: new memory initialization → K → real epoch → empty adoption → genuine local-user/password/session writers → native source snapshot → complete copy conversion/reset/seal → one new final synthetic file → normal existing-file MAIN → genuine session/permissions observations → physically closed restart. Source below supports the individual transitions, not automatic execution of the whole sequence.

The current memory proof is also **future**, with `metadataSourceDeviation` review pending, as supplied by the coordinator. Conditional source-plan approvals and the historical accepted native metadata/481-statement observation do not authorize another initialization or replay. `accepted_native` must continue to mean genuine newly opened `:memory:` provenance only; it must never label this imported file's first adoption. Prior bootstrap report acceptance/result wording is historical, not a release for this plan.

This lane writes only this new report. No command, hash, stat, compiler, evaluation, test, network, Engine/native SQL, product write, nested agent, production environment/database/image/private-configuration/data read, live copier/raw-index output read, or old-B access was performed. Current source/manifests and relevant existing planning reports were inspected; no runtime result is asserted.

## Prospective owned sequence — not an execution grant

### 1. One genuinely new memory source

Obtain an independent one-contained-proof release, including new source/closure, actual schema/custom initialization, canonical default seed, epoch/adoption, finite observations/export and cleanup. The bare old memory child closes its runtime and returns sanitized facts; it supplies neither a live DB nor seeded bytes. Do not extend its consumed authority, reuse its output, attach another connection to its result, or rerun the metadata experiment.

The new private owner retains exactly one `createPersistenceRuntime` result. Open/migrate schema; use only the existing fresh seed initializer for default setup content; migrate content; require actual K readiness. Then invoke the real epoch producer and one canonical empty adoption on that same runtime. Adoption is before the genuine user/session writes. Recheck K and ready-domain eligibility through real consumers; the adoption return value is comparison data, not a recipe for file tables.

MAIN's normal startup config requires an absolute protected file path, so this memory source is a contained proof owner, **not** production MAIN configured with `:memory:`. No accepted host-path rule is relaxed. `createNativeMainPersistenceResourcesAsync` privately constructs its own runtime; its returned guarded runtime has no adoption or snapshot method. Do not inject the source runtime into its generic factory shape or retrieve its private runtime via `runAsync`.

### 2. Real local-user/credential/session production

After actual ready-domain adoption, construct the production SQL issuer on the same memory runtime with explicit synthetic-only origin, real clocks, finite budgets, genuine synthetic secrets and credentials-only provider configuration. LDAP/OIDC resources remain genuinely absent, not fake successful providers. Keep issuer-origin `now` and SQL `now` the same actual clock function as required by onboarding configuration.

Consume the existing public fixed onboarding preparation/dispatch ports for claim → nextStep → initUser. Preserve actual original Request identity, real issuer CSRF cookie/token, claim cookie, validation and current native predicates. The wire planner owns the four-command transport, codec/body/handler/enrollment/publication work; this plan does not duplicate it. A route-based consumer is conditional on that owner's accepted real writer ports. A separately approved direct private Auth-port proof uses the ports' actual canonical source-body contract and proves only those writers, **not** the unresolved RPC wire bridge. It must not pass an oRPC packet to a raw source-JSON preparer or invent a transport shim.

The minimal credentials-only branch does not execute initialExternalGroup. initUser ends at **setup**, not finish; completeSetup remains held and is not introduced. Its void result is not automatic login or full onboarding completion. Perform actual credentials login using the genuine issuer HTTP executor and original client CSRF/session exchange, await confirmed native persistence plus physical response/request settlement, then retain the actually emitted session cookie privately. No direct `authSessionMutationAsync` DTO, manually constructed account/session, default password hash or fake verifier is admitted by this consumer.

Credentials setup writes a `user`, not a fabricated OAuth `account`. Preserve the actual account family, including its genuine emptiness if no account was produced. Session creation must use the real signed64 allocator; record its actual domain head/lifetime/write associations, not assumed values. Observe the positive session's real request-user/permissions through its issuer reader and lease currentness. A null-token `admitOpaqueSessionAsync(null, ...)` returns anonymous without a domain read and cannot establish readiness; issuer construction alone cannot either. The real session HTTP observation and positive admitted session are required.

Drain all writer/body/hash/native/response/retirement tasks and close the memory issuer before exporting. Do not carry its request handles, authority leases or controllers into file startup. Closing the issuer does not replace closing the DB after its export settles.

### 3. Capture, convert and seal once

Call the existing memory `snapshotSqliteAsync` once to one separately owned absent staging path. The snapshot is actual source contents, not invented migration/adoption metadata. After its complete maintenance/native/FS task settles, read only that newly owned output through the future bounded no-follow file consumer, preserving unchanged bytes and original ownership. No access to concurrent copier/raw-Bun-index stage outputs is needed.

Create one copy with `createSqliteCopyEngine({temporaryDirectory, migrationsFolder})`; use only its real owner-returned copy. Exact existing compatibility signature:

`assertCompatibleAsync(metadata: {dbDialect:"sqlite"; homarrVersion:string; exportedAt:string}, copy: CopiedSqliteDatabase, signal?: AbortSignal)`.

Its current body checks dialect/phase and authenticated catalog prefix; it does **not** authenticate version/export time or confer adoption authority. Bind metadata to the actual selected source generation/version and export observation. Root `package.json` currently declares **2.4.1**, which is source-version evidence only; future frozen-artifact/source association still needs review. Timestamp comes from the actual export, never an old accepted envelope or invented version/provider fact.

Run existing compatibility → schema migration → content migration → reset → seal. No `copy.run`, caller transaction/SQL callback, hand-inserted table, encryption conversion or backup-apply path is part of this consumer. Existing product methods retain their genuine SQL internals.

Reset is mandatory for this **sealed copy** contract. It clears only runtime history-entry/history-stream/state/meta and installs a new owned epoch plus NULL mutex. It does not clear Auth domain, credential keys, session, account, password, permissions or business rows. The legitimate expected epoch transition is memory **E0 → copy E1**; MAIN and its restart read **E1**, not two newly minted epochs. Never reset the final live file or call this runtime-state conservation. A direct native snapshot could retain E0 with fewer operations, but does not return this copy engine's sealed result; it is not interchangeable with the requested sealed-copy sequence.

`sealAsync(): Promise<{dialect:"sqlite"; bytes:Uint8Array}>` validates full target/reset/no runtime referrers/no temporary objects, VACUUMs, closes its native handle and returns bounded bytes. Keep those bytes private and unchanged. Await `disposeAsync()` and all staging/source close tasks; preserve a seal result alongside any cleanup failure without admitting it as a clean candidate.

Do **not** use `prepareLegacyBackupAsync`: `packages/api/src/backup-runtime/index.ts:156–164` deletes sessions, verification tokens and the onboarding claim before reset/seal. That violates this session-preservation target, and backup apply remains held. Existing inspection counts are not exact-record equality and do not supply a fixed MAIN conservation producer.

### 4. One new synthetic final file, then two sequential existing startups

There is no inspected public API that installs sealed copy bytes as a final MAIN database. The existing copy writer's native FS sequence is usable precedent: exclusive/no-follow 0600 open, unchanged-byte write, sync, close in a private protected parent. A **new finite private consumer**, not a fake installer factory, must perform this transaction under a separately reviewed file lease. It must not overwrite, hardlink, rename over, or patch an installation, and may create only its explicitly named new candidate and SQLite-owned sidecars.

Complete source/copy/FS physical closure before first MAIN admission. Use normal **mode:existing** startup validation and the actual native MAIN constructor, fresh local ownership and real Auth enrollment. K validates exact ledger/physical target/native definitions; genuine positive session reader validates stored native keys, clock/expiry, user/provider and joined permissions. Keep the same explicit synthetic core/CSRF/encryption configuration required by those genuine consumers; no ambient production configuration or fabricated authority DTO is supplied.

First startup must not login again, renew/delete the chosen session, perform setup completion or dispatch App/Board writes merely to obtain a success response. Select a genuine non-mutating admitted session/permission observation; session HTTP may renew depending on configuration, so it is not automatically read-only. If the existing selected port cannot avoid mutation, stop at that port rather than change expiry/update-age to hide it.

Dispose first MAIN/Application, await its requests, publication reservations, underlying native work, scopes and strict DB close. Only then reopen the **same new file** with a second new MAIN/Application owner, again existing mode, and repeat K plus the same positive session/permissions and conservation comparisons. Restart has new process-local authority and stored E1; it is not re-adoption. No fresh mode, additional initialization/reset, credential remint, fallback or automatic retry is allowed.

## Conservation contract and concrete missing producer

Preservation concerns **stored values and native representations**, not physical SQLite byte identity after VACUUM. Retain exactly the actual user/password hash/provider, accounts, sessions/tokens/expiry, domain namespace/head and native INTEGER lifetime/write keys, groups/owners/members/permissions and board/integration permission families. Signed64 observations must preserve canonical TEXT projections plus native storage checks, not unsafe numeric coercion. Encryption ciphertext remains unchanged with the same synthetic key; no decrypt/re-encrypt operation is justified. SQLite media is `media.content` BLOB plus its real metadata (`schema/sqlite.ts:232–242`), not an external image fixture. Serialized widget/settings/source strings remain byte-exact; parse/restringify is not preservation.

The source default/user/session writers do not establish nonempty OAuth accounts, encrypted fields or media. Equality of empty families must be reported as empty-family preservation, not populated-account/encryption/media proof. A positive specimen in any such family needs a separately accepted genuine fixed writer; no manual fixture SQL is permitted. Custom migrations run on copy and each normal reopen; their idempotence for the actually captured records is an acceptance condition, not a blanket source assumption.

**Today's source does not close the exact-record comparison under the no-SQL-callback constraint.** MAIN exposes `runAsync` and readiness, but no fixed bounded complete-record snapshot/comparison or guarded native export method. K proves schema/ledger/meta shape, not all business values; the real Auth reader proves its selected session/user/permissions, not untouched media/encrypted/serialized families. `snapshotSqliteAsync` supplies a pathname, and `sealAsync` supplies bytes; neither returns a registered preservation witness or compares a reopened MAIN to it. Counts, equal file size, copied path attributes and public DTOs cannot fill this gap.

If exact complete-family comparison is required before admission, request a separate **DB-owned fixed observation producer + MAIN-owned fixed consumer** source plan. Its implementation must read the actual retained native source/reopened connection, authenticate full target, enforce finite row/value/aggregate limits, capture native scalar/BLOB/string representations and retain a private baseline for comparison. It may not accept caller SQL, table lists, row readers, database factories, asserted native provenance, supplied password hashes or a callback returning expected records. A public type brand/setter is insufficient. Crossing a real process restart requires an explicitly owned private baseline transport and fresh fixed observations; process-local WeakMaps cannot be serialized into authority.

No such strict field/method currently exists in `PersistenceConfig`, `MainPersistenceConfig`, `ProductionSessionIssuerConfiguration`, `snapshotSqliteAsync` or the copy metadata signature. This report intentionally does not pretend that a proposed callback factory closes it. The smallest possible optional MAIN export field would be a **fixed retained-runtime method**, `snapshotSqliteAsync(destination: string): Promise<{engine:"sqlite"; path:string}>`, registered/drained by the actual native owner, not an injected exporter. That alone still lacks finite bounds and logical comparison and is **prospective, not an existing port**. Stop for that narrow producer/consumer review rather than add a generic authority framework or weaken file adoption.

If instead the requested boundary insists on `mode:fresh` **file** first adoption, the separate native gap is exact: `openAsync` retains `freshCredentialOwner` only for fresh `:memory:` and no supported native opened-file continuous-ownership/adoption producer exists. No pathname stat, empty file, copy receipt, migration ledger, `Database.handle` index, existing singleton or memory `accepted_native` fact can replace it. The existing-file route avoids needing that provenance; it does not solve or accept it.
