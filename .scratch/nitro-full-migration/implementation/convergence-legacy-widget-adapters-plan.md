## Common controller rules

Use the correction at `convergence-legacy-media-modal-plan.md:107–138` as vocabulary, not a new service framework.

1. Keep shared views pure and unchanged. Docker and QuickAdd get named **modal-mounted** local controllers with local `createModal(...).withOptions(original.options)` definitions. Hooks run unconditionally in named components/hooks, never click callbacks. Caller hook-result snapshots are not the modal's live query/mutation state.
2. Capture the real provider presentation owner in a mount layout effect; publish an active mount record and latest committed session/permission/intent observations there. Disable dispatch before publication. Effects update refs, not speculative renders. Operations capture that particular mount/intent record, and check its identity/activity, presentation epoch and current committed observations before each side effect and around every await. Close retires the record before delegating. Cleanup and real provider shutdown/close/cover/replacement retire snapshots; cleanup alone is insufficient for immediate presentation invalidation.
3. Bind admission to the observed session **object plus copied identity fields, permission values and expiry**, authenticated status and exact selected intent. A committed loading/sign-out/object replacement/field change/permission loss retires the admitted record permanently. A→B→A never revives its old callbacks; a genuinely new selection/mount gets a new record. No timer, clock-derived permission, invented Auth epoch or always-current callback. Stable callbacks read committed refs; ordinary callback recreation or pending renders do not manufacture a new generation.
4. A resolved real write remains known, even if its owner subsequently retires. Separate reconciliation from the mutation; do not throw after a resolved write to relabel it unknown. Rejected/ambiguous dispatch is unknown and cannot resend automatically. Keep the original input/result/error. Cache-refresh failure after known resolution is reconciliation-held; retry only retained reads, never the write. Existing pure Docker/QuickAdd/UploadMedia state machines already supply this distinction.
5. Use mutation hooks with `retry: false`, without legacy `onSuccess`/`onSettled` notification/cache side effects ahead of owner checks. Check the captured owner before every reconciliation call and after settlement. Typed invalidations use their real third `{throwOnError: true}` option and are awaited, not fire-and-forget. Public icon search is intentionally public; do not invent an authentication requirement for it. Permission-dependent upload/write/refresh resources remain gated by their real permission and current owner.
6. Supply explicit truthful labels: unknown means “Outcome could not be confirmed; refresh/check before another submission”; reconciliation-held means “Saved, but refresh failed; retry refresh, not the write.” Retain real errors, existing outcome controls and CSS/Mantine presentation. Unknown read retry never clears the write outcome or re-enables Submit.

These owners prove observed UI association only. Existing legacy RPC authentication/permission middleware remains the per-call server gate. Default Next remains default; no native authority, unseen revocation detection, through-COMMIT guarantee or admission increase follows.
