### Host and transport order

1. Before bind, parse/capture the explicit config, verify listener/origin agreement and create the sole startup lifetime. Validate missing/invalid inputs without allocating a DB. The transport adapter is the replacement Nitro entry, not a second server launched from SSR.
2. Retain Nitro's real asset routing and lazy SSR service. First real SSR/service Fetch calls backend host initialization, which publishes its promise before construction and awaits the prepared constructor plus application readiness before handing back a response. Later requests await the same promise. Lazy bind is not SQL readiness: announce only listener binding until an actual readiness request settles. Failed initialization stays failed; never retry into a foundation host or alternate path.
3. Pass the captured startup signal, caller culture options and U's prepared renderer to compose. Asset/render functions are real application callbacks, not placeholder hooks. Startup cancellation remains owned outside request/native admission.
4. Signal callbacks only publish a shutdown request and fence new transport/application admission; the transport entry's owning async control flow awaits that request and awaits shutdown. Do not depend on EventEmitter awaiting an async callback. Publish the shared closing task before abort, initialization settlement or any disposer invocation.
5. Begin application cancellation/drain and transport `close()` together, retain and await both outcomes; application lifetime abort releases active response bodies/streams before native disposal. Invoke real Nitro close hooks through the public hook API, coalescing the same host-close task. Preserve all failures and report unsuccessful exit; no force timer, detached close, swallowed hooks or native-close-before-operation-settlement.
6. Close never runs inside an admitted SQL callback or the request it must drain. Auth/resource transitions return an outcome to the outer owner; they do not await whole-host disposal from an active request. Programmatic and signal shutdown use this same task. Close during lazy import/initialization must prevent later owner publication and await same-owner cleanup.

Installed Nitro's `entry` and explicit `output.{dir,serverDir,publicDir}`/`buildDir` declarations, public Nitro app APIs and srvx `manual`, `gracefulShutdown`, `serve()`/`close()` implementations support this narrow adapter. Compiled singleton identity and shutdown behavior still need validation; source correspondence is not proof.
