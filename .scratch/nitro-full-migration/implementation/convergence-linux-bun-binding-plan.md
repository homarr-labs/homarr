## Supported API behavior and unavoidable side effects

Primary source basis is the already reviewed **reported** Moby commit `8af9fe3a36bab3e039862a2ab1cef1880c9b4d03`, not VM binary attestation:

- [Archive router](https://github.com/moby/moby/blob/8af9fe3a36bab3e039862a2ab1cef1880c9b4d03/daemon/server/router/container/copy.go): GET calls `ContainerArchivePath`, sets base64 JSON `X-Docker-Container-Path-Stat`, returns `application/x-tar`, and defers archive close. PUT is the separate extraction operation and is forbidden here. Request identity encoding to avoid compression/decompression.
- [Archive implementation](https://github.com/moby/moby/blob/8af9fe3a36bab3e039862a2ab1cef1880c9b4d03/daemon/archive_unix.go): locks the container, stats the selected path, chooses only its basename for a file, streams tar, closes its filesystem view/unlocks on reader close, and records an **archive-path daemon event**. It does not call container startup or run Bun.
- [Filesystem view](https://github.com/moby/moby/blob/8af9fe3a36bab3e039862a2ab1cef1880c9b4d03/daemon/containerfs_linux.go): mounts the container filesystem, sets up its configured mounts, creates a private mount-namespace view on a daemon thread, and uses `os.Lstat` for PathStat. `Close` waits for operations, unmounts volumes/root. The view is explicitly **live/read-write**, not an immutable snapshot or guaranteed RO mount merely because HostConfig.ReadonlyRootfs is true. Mount setup may stat sources and create missing mountpoint placeholders; it is not a zero-daemon-filesystem-side-effect operation. No application/source/SQL payload is selected or traversed by this file archive, but normal daemon mount setup touches mount metadata, including the already configured asset bind.
- [Vendored archive producer](https://github.com/moby/moby/blob/8af9fe3a36bab3e039862a2ab1cef1880c9b4d03/vendor/github.com/moby/go-archive/archive.go): uses lstat, regular-file read and PAX-capable headers; modtime is truncated to seconds, names are rebased and security.capability xattr may be read. Some producer errors are logged, not faithfully propagated as HTTP failure. Therefore require a complete matching stat/header/payload/archive, never HTTP200 alone.

Accept only this ordinary metadata/stat/read/mount/event scope. It is **not** an Engine mutating API action, workload process, native initialization, migration replay, or a guarantee of no internal writes. If review forbids these internal mount/setup/event effects, this archive route is unavailable under that stricter policy; do not disguise them as pure image-layer access. Client timeout/EOF is not a universal daemon-thread/unmount-completion certificate; cleanup errors can be ignored internally. No cleanup/control action is added.

## Strict file/archive oracle

Candidate limits: inspect bodies≤1048576 bytes each; HTTP response headers≤16384 bytes each; selected stat header≤4096 encoded bytes and≤3072 decoded bytes. Bounds are enforced while receiving, not only after an unbounded buffer. Reject duplicated stat header, malformed base64/UTF-8/JSON, duplicate JSON keys/nonfinite constants, wrong keys/types or trailing data. Require the PathStat object `{name,size,mode,mtime,linkTarget}` with `name:"bun"`, integer `0<size≤134217728`, unsigned integral Go FileMode regular (no type/special bits beyond0777), at least one executable permission, `linkTarget:""`, bounded valid timestamp. Do not use POSIX S_IFREG bit interpretation for Go FileMode; regular type bits are zero. Header Name alone is not a canonical full-path observation.

The full **uncompressed tar body** ceiling is `134217728 + 65536 = 134283264` bytes; fixed512-byte framing, no decompression. Exact member payload size must equal the stat size. Never tar-extract to disk or follow filesystem/link/archive names. Hash only the actual Bun regular-member payload for `bunExecutableSha256`; separately hash raw archive bytes for receipt integrity. Tar-header checksum is framing validation, not that SHA.

- Exactly one logical filesystem member, literal name `bun`, ordinary regular type `0`/NUL; empty linkname/prefix, expected size, mode permission equality to PathStat, modtime equal to PathStat truncated to seconds (matching producer contract). Reject directory/symlink/hardlink/device/FIFO/sparse/whiteout/duplicate/absolute/traversal/renamed member or extra payload. A normal single-file archive cannot prove source nlink1; do not invent it.
- The producer is PAX-capable: permit at most one bounded local PAX metadata header before Bun,≤16384 bytes, only timestamp keys `mtime/atime/ctime` with finite bounded numeric values and consistent effective mtime. No global PAX, path/linkpath/size/uid/gid overrides, GNU long-name/link, sparse keys, xattrs/capabilities or unknown extensions. It is metadata for the one file, not another permitted filesystem member. Reject any unexpected extension instead of letting a tar library silently apply it or launching a replacement request.
- Require complete size-delimited payload, zero alignment padding, at least two terminal zero512 blocks, then only bounded zero tar padding to real HTTP body EOF. Check the physical stream too: a logical tar iterator ending at the first zero block is insufficient to exclude concatenated/trailing members or missing terminator. No truncated-content hash is publishable.
- Optionally inspect the first64 payload bytes as static ELF identity: ELF64/little-endian/AArch64 machine183; record observed values, reject a conflicting architecture. No loading, execution, disassembly, strings scan, shared-library resolution or self-reported-version substitution.

PathStat uses lstat on the leaf but ordinary resolution can follow parent symlinks. No header proves parent canonicality independently. The already accepted canonical `/usr/local/bin/bun` probe plus same immutable image/read-only-root/unaffected mounts/owned continuity supplies that **supported association**, not a new ancestor-stat measurement. Do not resolve an unseen LinkTarget or add parent/directory GETs to manufacture stronger proof.
