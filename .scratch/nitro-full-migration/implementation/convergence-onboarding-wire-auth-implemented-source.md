Genuine native cleanup faults are retained from the producer's explicit cleanup facts, independently of an ordinary rejected request.

Ordinary work retirement aborts the work controller, releases the real lease and drains tasks, but publication clocks use the separately captured **original external** request/lifetime signals. The detached native slot pins only exact operation/invocation/clock/handle/packet-reader associations; it contains no SQL owner, Runtime, configuration object or bound SQL graph. Actual reader consumption/disposal occurs at terminal publication, with original/observed deadline checks. Its strong association is cleared on successful disposal. Unassigned native slots are disposed after underlying work settles on owner close.

Without the new startup source, legacy retirement disposes untransferred native slots as before its publication seam is activated. With the startup source, the native slot can survive ordinary retirement for the real later error/output registration; no registration may invent evidence for a dispatched request whose slot has already been disposed. A caller enrolling a legacy positive response must register it before disposing that request. The new wire caller must supply the approved startup producer to support post-retirement SDK error-response registration.

Failed response readiness automatically starts a separately prepublished abandonment settlement after readiness rejection; it does not await itself. Owner close waits output/native completion and real cancellation/release before disposing/clearing active registrations. Publication-readiness rejection is associated through a weak owner identity so an ordinary request error does not become an owner cleanup failure. Genuine cleanup faults use the existing first-cause/distinct-failed-retirement saturated summary; no generic history/owner framework or exception-cause traversal was added.
