- Capture the original finite absolute deadline, original operation signal and combined operation/owner/feature-closing lifetime. One wall-plus-monotonic remaining budget covers collection, native work, decoding and delivery; no renewal, timer race or abandoned native task. The runtime owns its separate maintenance lifetime and native timeout/COMMIT behavior.
- Publish the tracked task before invoking external/reentrant domain code. The frozen scope exposes only dialect and `queryAsync`; query calls narrow/copy exact source requests and observe deferred rejection immediately. Collection closes synchronously when the one invocation returns its Promise. Observe the domain rejection before native dispatch.
- Require exactly one of the five ordered groups below. Empty/partial/duplicate/mixed/wrong-order/wrong-dialect/unsupported/late collections fail; a retained scope cannot launch another SQL operation. A private first-failure latch prevents caught query rejection or delayed unsupported SQL from manufacturing success.
- SQLite calls **one real `boundedTransactionSync`**, whose synchronous callback executes the complete group and returns detached rowsets, never a Promise. PostgreSQL calls **one real `boundedSnapshotAsync`**, executing fixed group queries sequentially. No independent-query fallback, additional continuation transaction, raw handle or native-control SQL.
- Resolve deferred row promises only after the runtime returns/fulfills, including actual COMMIT/cleanup. Every failure rejects the group and awaits deferred/domain settlement; native runtime failure is retained separately and rethrown unchanged, so an earlier callback latch cannot conceal dispatched-COMMIT ambiguity. A later domain/delivery failure is not a rollback claim.
- `closeAsync` publishes its shared promise before abort, gates new admission synchronously and awaits tracked native/deferred/domain settlement. Only this feature closes; main persistence/trust are never closed. The source task does not invoke or await its own close/drain. Arbitrary reader-created promise cycles are not a guarantee beyond the reviewed finite reader bodies.
