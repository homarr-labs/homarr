Revision consumed: accepted `homarr.backend.source-port.v2` context/procedure/contribution spine. Outcome: **18 additional unmounted native oRPC leaves, 20 exact source identities accounted for, two specifically pending identities.** No central registration, manifest/export, physical persistence runtime, frontend/form/navigation, original router, auth policy or app-host file was changed. No whole-app or complete search capability is claimed.

Original inputs, output schemas, REST/MCP candidate projection metadata, source path/kind/access/demo metadata, permission distinctions, queries and returned DTOs are retained.

Authenticated users retain source visibility of all apps; anonymous visibility derives from actual public-board app and bookmarks SuperJSON options. - `routers/-apps-search/search-settings.ts`: real source search-setting query, SuperJSON/default merge and single-row update helper bodies. No opaque settings-service callback, global DB reference or dialect/default replacement is imported.
- `routers/-apps-search/bangs.ts`: the actual token normalization, localeCompare lower-bound search, contiguous prefix matching and bounded result loop from `services/duckduckgo-bangs.ts`, with request abort checks and a typed dataset-read resource. `routers/bangs.ts` preserves the original input schema and pending source binding, but registers no native endpoint without the missing runtime resources.
- `routers/-apps-search/resources.ts`: typed source table/operator/schema/generator/effect resources, discriminated native/pending bindings and request admission/completion guards. SQL/domain bodies stay in their owning controllers/helpers.

Both native family contribution factories invoke `defineBackendContribution(v2)`, which checks actual nested route identity against the source descriptor and exact leaf list. The check combines the families without touching the global spine. Source bindings include the actual original source file; checks verify all twenty source leaf declarations and all eighteen native query/mutation kinds against the frozen inventory. There is no tRPC tunnel, `createCaller`, stand-in domain controller, unavailable-success endpoint or no-op mutation.

## Resource contracts and stop lines

App resources are injected source `apps`/`items`/`integrations`/`icons` tables, exact Drizzle operator signatures, the source select-app output schema, the source ID generator signature and `invalidateIntegrationResponseCacheAsync(integrationId): Promise<void>`. The latter is an exact cache-generation effect supported by accepted STATE v2, not an opaque app controller. Its presence is required at factory construction, so a missing effect cannot silently turn an update/delete into a partially implemented success. State backing/admission and actual host lifecycle joining are still the resource owner's obligation.

Engine resources are injected source `searchEngines`/`users`/`serverSettings` tables, exact operator signatures, ID generator and `warn(Error)` diagnostic sink. Reads and SQL writes themselves are implemented here against `context.db`. Search-setting helpers use the existing pure `@homarr/server-settings` defaults and real SuperJSON representations.

All DB/schema/output-schema imports used to describe resources are type-only. Production controllers do not import or initialize global legacy DB/env/auth/API helper roots, call the held persistence factory, or implement new driver/transaction code. The trusted host must supply coherent tables/operators/DB for its real engine. The accepted spine currently exposes its normalized SQLite-shaped Database type; PostgreSQL mapping/runtime acceptance remains with persistence/composition, not a cast added by this lane.

Request signal admission/completion fences and between-read/write fences prevent starting SQL after an already observed cancellation. Native SQL/upstream operations already begun are not claimed reversible: already committed single writes still require their source cache effects, and this code does not claim rollback or cancellation of uncancellable backing calls. No asynchronous callback is run inside a Bun SQLite transaction. No ping is invoked by these source app leaves; app ping URLs are preserved, while actual ping scheduling/widget execution belongs to its existing owners.

`NormalizedBangsDataset.getDataAsync(signal)` is a candidate exact data-read seam for the unmounted helper, not an accepted production DDG provider. Its snapshot must preserve the source fetcher's normalization, removal of empty tokens and localeCompare ordering. The cache/fetch/timeout implementation remains specifically pending rather than being hidden inside a service callback.
