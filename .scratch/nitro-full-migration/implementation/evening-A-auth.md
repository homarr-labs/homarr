# Evening A — smallest MAIN authenticated producer join

## Decision

Reuse the existing production SQL issuer, its private owner, and its request-reader projection. Do not build another session engine or reader. Authenticated read admission is already implemented; MAIN construction/enrollment, request identity adaptation, and honest response publication are not. Genuine login/renew/logout HTTP success cannot currently be mounted: all persistence outcomes explicitly hold publication, and the old publication function always throws. A confirmed native commit is not permission to emit the prepared cookie.

This is ordinary current-source investigation under the evening sprint, not protected evidence admission or a new runtime acceptance. Historical narrow acquisition leases are not applied to ordinary product reads. Prior A owner/deadline, B logout/closing-guard, SQL-reader and auth-helper reports were reused; no sealed captures were opened. No commands, compiler, runtime, native SQL, tests, installation, environment/data/credential access, Git or delegation occurred. Only this initially and immediately prepatch absence-checked report is written.

## Current MAIN blockers, not hypothetical rewrites

1. **Full same-owner runtime is hidden.** `apps/backend/src/server/runtime-composition/native-main-persistence.ts:352-375` returns a guarded runtime exposing engine/phase/run/readiness only. The Auth factory needs the full actual `PersistenceRuntime`, including bounded transactions/snapshot and `authSessionMutationAsync`. Passing this facade, casting it, constructing another pool, or using root global `db` is wrong. Its construction at 316-329 pins `logger: undefined`; P/H must confirm actual factory logging behavior before credential reads, not rely on the Auth `disabled-by-resource-owner` literal alone. This report does not duplicate the ongoing four-file factory review.
2. **MAIN is still public-only.** `runtime.ts:62-141` constructs only public settings/culture/RPC; `public-settings.ts:58-74` always resolves anonymous and denies protected access. `assembly.ts:145-173` registers no auth owner/routes. `host.ts` still calls the separate foundation-only `composeApplication`. H owns actual enrollment/startup, not A.
3. **Backend principal falsely demands a revision.** `packages/contracts/src/request.ts:1-3` requires `sessionRevision: string`; the genuine reader has no such revision. Do not use token, expiry, fingerprint, random request ID or epoch guess to populate it. The minimum shared-contract amendment is an authenticated subject/credential-type projection with no purported revision, while private lease association remains server-side.
4. **Principal copying can break private association.** `application.ts:88-92` spreads/freeze-copies the resolved principal. If the adapter binds principal-to-lease in a WeakMap, that copy destroys the binding. Preserve the actual frozen returned principal object, or serialize a request-keyed association contract with H/R instead; do not recover a lease by subject alone.
5. **API user projection is not the lease DTO.** `packages/api/src/nitro/context.ts:9-16` requires the real `SessionUser` projection including color scheme. The reader intentionally supplies no name/email/image/color scheme. Supply those via one bounded selected-user read over the same main resource, associate exact user/provider facts, and reassert the original lease before private output. Do not create a second authority read or use a dummy color scheme/profile. R owns consuming the resulting real user plus lease into native BackendContext.
6. **Publication is absent.** `sql-persistence.ts:62-71,619-721` returns only held dispositions; committed native results and logout dispositions stay in private WeakMaps. `persistence.ts:198-201` always rejects publication. The staged `Response` is closure-private proposal data, not a response capability. Logout deliberately stages no response at `service.ts:574-576`.
7. **Read currentness is not protected mutation authority.** `authority.ts:561-570` and critical-writer contracts still explicitly hold the same-native credential/principal/grant/validity-through-COMMIT join. Fixed SQL establishes/renews/revokes genuine session rows, but its mutation contract has no original permission/grant CAS witness. A pre-dispatch assertion and post-commit reread cannot fill that join. P/R must keep protected domain writers disabled until genuinely bound; this adapter cannot authorize them with a boolean callback.

## Concrete request producer

1. H supplies the captured main native runtime, main lifetime, explicit trusted configuration and actual LDAP/OIDC resources. Construct `createProductionSqlSessionIssuer` once, obtain `getProductionSessionRequestReader(issuer)` once, and retain both privately. If construction fails, await issuer/main dependent cleanup in correct ownership order; do not publish a partially ready host.
2. For ordinary requests, capture the real request signal plus application/main lifetimes and a finite absolute request deadline. Read the configured cookie with `readSingleCookie` and legacy `ApiKey` header with exact `id.token` grammar. Pin transport precedence explicitly; present invalid API-key input must not silently fall back to a cookie. Duplicate credential headers/cookies must reject. A generic JWT/Bearer interpretation is not a replacement for the existing product header.
3. Call exactly one selected admission method. Missing credentials yield anonymous; malformed/disabled/unavailable authority yields a sanitized denial/unavailability, not an authenticated DTO. Register lease release immediately with `onDispose`, releasing it locally if registration or subsequent projection fails. Track real admission settlement so shutdown cannot forget late SQL/bcrypt work.
4. Retain genuine request/principal-to-lease association privately. Principal subject comes only from `lease.identity.userId`; global/group permissions come only from its real expanded identity. Fetch the minimal real user projection if needed, verify its identity/provider association, then await `lease.assertCurrentAsync` before returning private material. Clamp opaque request work to `hostDeadlineAt`; API keys receive no invented expiry. New requests get fresh admission, never an extended old lease.
5. Request-service `authorize` uses the actual associated lease and policy helpers for the concrete action/resource; unknown mappings deny. R can let the protected RPC envelope require authentication while individual procedures enforce actual domain permissions, but `authenticated => allow every action` is not the route authorization implementation. Mutation admission still requires P's genuine native authority path.
6. Await currentness immediately before private serialization/publication and propagate real lease invalidation to cancellation of private response work. Existing host stream retention only listens to request/application signals and does not itself revalidate credentials. No cross-process revocation subscription is implemented by these leases; do not describe local token fencing as one. Public output must not become private merely because a principal exists.
7. Auth routes need an explicit exception to generic credential admission: issuer preparation itself owns its opaque lease/CSRF/authentication. `createApplication` resolves principal before even phase-auth routes. Acquiring an outer request lease for renew/logout and then joining its lifetime to request cancellation would self-cancel the successful mutation when renewal changes the witness or logout drains matching leases. For exactly owned auth endpoints, resolve anonymous at the generic transport layer, dispatch a public auth contribution, and let its real issuer perform admission. This is not anonymous logout permission: `prepareSessionMutation` still requires canonical POST/origin/signed CSRF and a genuine selected session.

## Honest login, renewal, logout completion

Keep the existing public issuer prepare/persist/discard API for investigation and add a bounded HTTP completion method owned by the same SQL issuer; never publish by inspecting a caller-supplied disposition. It must synchronously claim once, retain exact native result/error and settlement, and publish only from its own private association after required joins are genuinely satisfied.

- **Credentials/LDAP login:** reuse `prepareCredentials` parsing, real bcrypt/LDAP verification, body settlement, selected full-user witness and 48-random-byte opaque token. Fixed establish SQL rechecks actual password/profile/provider witnesses, performs actual session insertion and sign-in/everyone/existing external group effects in one native unit. Response/cookie stays held until native confirmation and critical cleanup/currentness/delivery conditions; no speculative cookie effect at preparation time.
- **Due renewal:** existing `prepareSessionMutation("renew")` computes `previousExpiry - maxAge + updateAge`, preserves the token and requests strictly increased expiry. SQL uses exact token/user/**previous expiry** conditional match. The old lease's expiry witness necessarily becomes stale: after successful renewal, use the genuinely newly admitted same-reader lease for final currentness/delivery, not another assertion on the old witness. Existing persistence already does fresh admission and then releases it; HTTP completion needs genuine publication association rather than retrieving a released capability.
- **Not-due renewal:** currently no SQL mutation is generated, persistence returns `held-without-dispatch`, and preparation still contains a session JSON/cookie response. Implement a separate private read-only completion state requiring current original lease, real projection, body settlement and disposal. Do not reinterpret every `held-without-dispatch` as success. The due path and no-write path must be distinguishable by private state, not caller opinion.
- **Logout:** retain the accepted `logoutMutationFor` association and `revokeOwnedSessionAsync` call. Its genuine token fence rejects/marks overlapping admissions, drains matching leases and retains exact native ambiguity. Only confirmed deletion **and** successful critical settlement can produce the agreed logout HTTP response plus expiry of the exact configured session cookie (Path=/, HttpOnly, SameSite=Lax, matching Secure choice). Never reread/assert the deleted session to certify logout. Native zero-row/precondition failure is not automatically successful already-logged-out; no such policy is currently implemented.
- **Ambiguous COMMIT or confirmed-commit settlement failure:** emit no success/session cookie/private payload; retain honest sanitized reconciliation-required state. Never retry, compensate, report rollback, or accept client-provided success evidence. An orphan committed login session after delivery failure is possible; sweeping/retry policy is a separate writer obligation, not a reason to fake atomic DB+HTTP delivery.
- **OIDC non-mutating actions:** `prepareOidc` supports sign-in/CSRF/providers reads, but `mutationFor` currently requires exactly one login-effect for every non-renew operation. Thus pure provider/redirect/CSRF preparations do not have a valid persistence completion path. Add a private no-login-effects branch preserving genuine Auth-core protocol/body/provider settlement; do not claim those paths work by mounting callbacks alone. Callback sessions/account linking still use the fixed establish unit and verified OIDC identity, with PKCE/state/nonce and existing linking policy intact.
- **Base path:** current issuer hardcodes `/api/auth`, exact callback paths and redirect URLs (`service.ts:188-193,373-376,435`). MAIN allows a nonempty basePath. Initial honest synthetic enrollment may require basePath empty; preserving nonempty deployment requires a serialized real route/basePath amendment, not request URL/Host spoofing.

Fresh read assertions do not by themselves protect native domain mutations through COMMIT, nor guarantee credentials cannot change after an HTTP header is emitted. Define/prove the actual delivery boundary and keep the stronger unsupported claim held.

## Retained keys and password policies

- Keep stored local password hashes and existing `comparePasswordsAsync`; hashing remains bcrypt cost 10 in `packages/auth/security.ts`. No forced rehash, new complexity rule, trim normalization, new password codec or migration-time hash rewrite. Credentials verifier preserves lowercase name/provider-scoped lookup and password mismatch denial.
- Retain existing API-key rows/hashes and the `ApiKey: id.token` product transport. The authority reads hash/user/provider, bcrypt-verifies outside SQL, then rereads and compares the exact credential before issuing current grants. No display-session one-day timestamp becomes API-key expiry. API-key create/replace/delete require their actual admin/compatible-writer join; possession-only deletion remains blocked.
- Keep actual retained encryption key when composing `createSecretCodec`: exactly 64 nonzero hex chars, existing AES-256-CBC `ciphertext.iv` storage format. Its keyed fingerprint is not a session revision. Do not regenerate encryption key on each boot or use core/CSRF/session keys as substitutes. No real key value was read here.
- Pin core/CSRF secret ownership, trusted external origin, cookie prefix/Secure decision, max/update ages, skew and row/body/deadline bounds explicitly. Migration-time session invalidation versus retained API keys/password hashes remains the existing approved policy, not a consequence inferred from copying the database or retaining encryption keys. No live import/cutover is part of this tranche.

## Fail-closed activation gates and synthetic prerequisites

Ready-to-allocate source work: factory leaf/export, same-owner request adapter and real user projection, and private completion state design. MAIN-authenticated **reads** may be proven independently; HTTP login/logout/renewal success waits real completion/delivery closure. Protected writes wait native credential/grant/validity-through-COMMIT and every enabled writer's compatibility. Merely changing held strings/throw sites or supplying `securityApproved: true` is not implementation.

After source freeze/review, coordinator-owned isolated checks need a fresh disposable SQL installation, synthetic user/password hash/groups/session/API key, independent synthetic retained encryption/core/CSRF keys, actual migration assets, explicit credential-query logging suppression, verified clock/skew/deadlines and a fresh nonprotected loopback port. Existing protected ports/outputs and real data stay untouched. Required focused cases:

1. Genuine credentials login cookie only after actual insertion; wrong provider/password/body/CSRF/origin rejected without session effects; selected password hash replacement between verification and SQL fails.
2. Fresh request admission sees actual user/grants; invalid/duplicate credentials cannot fall back or forge a principal; API-key replacement/remap during bcrypt fails; retained hash/key behavior survives restart.
3. Due renewal changes only expiry, preserves token, rejects old-expiry races and uses fresh genuine lease; not-due renewal performs zero writes and has its own actual read-completion evidence.
4. Logout deletes exactly the authenticating session, leaves unrelated session/API-key rows intact, blocks/settles overlapping token admissions, clears only the matching cookie after confirmed settlement, and remains deleted after restart.
5. Native commit ambiguity, cleanup failure, abort/reentrant close, late admission and response cancellation preserve honest nonretryable states and real drains. No disposal awaits a task that is awaiting that same disposal.
6. Private SSR/RPC never relies on a fabricated revision/profile; stream/currentness boundary and lease invalidation are exercised. Domain mutation races remain separate P/R proof, not counted as covered by a read.
7. OIDC read-only redirects/provider/CSRF flow and actual callback settlement are exercised against isolated synthetic provider infrastructure before claiming enabled OIDC; LDAP similarly needs its real isolated client disconnect/settlement proof. Do not quietly disable configured providers to pass a credentials-only demonstration.

No tests were added or run in Phase 1. The later checks are prerequisites, not claimed evidence or authorization to access real installations.
