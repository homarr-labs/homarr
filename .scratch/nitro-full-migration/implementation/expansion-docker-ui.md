It does not install a route, provider, physical RPC link, endpoint descriptor, Docker client, container, demo, or listener. `heldDockerFeatureAdmission` is the supplied held state. An admitted binding is an explicit host integration seam, not evidence that admission has occurred. The active native-backend peer is not imported or consumed.

Private admission remains held on real current administrator authority, owned Docker-enabled/read-only configuration, application providers, dependency declarations, same-origin physical oRPC transport and native cleanup binding. ## Eleven typed direct calls

`client.ts` freezes a source-limited oRPC `Client` projection from the legacy router's type-only `RouterInputs`/`RouterOutputs`. There is no runtime tRPC client, unknown/JSON response fallback or active-peer router dependency. `subscribeLogs` projects the source string emission into a cancellable async iterator, which the future native physical transport must satisfy. This is a contract boundary, not proof that a physical stream exists.

| Leaf                       | Consumer                                                                            |
| -------------------------- | ----------------------------------------------------------------------------------- |
| `docker.getContainers`     | Scoped inventory query; omitted/empty endpoint selection means all                  |
| `docker.getEndpoints`      | Configured endpoint status and capabilities; no TLS credentials/descriptors exposed |
| `docker.reconcileServices` | Actual source-assisted setup candidates                                             |
| `docker.getServiceHealth`  | Open reconciliation panel's source layer statuses                                   |
| `docker.refreshInventory`  | Explicit refresh mutation followed by scoped invalidation                           |
| `docker.startAll`          | Row/selected action group                                                           |
| `docker.stopAll`           | Row/selected action group                                                           |
| `docker.restartAll`        | Row/selected action group                                                           |
| `docker.removeAll`         | Confirmed row/selected removal                                                      |
| `docker.logs`              | Separate historical xterm snapshot                                                  |
| `docker.subscribeLogs`     | Ordered live iterator with its own history tail                                     |

Lifecycle and removal use source `lifecycle`/`remove` capabilities; logs use `logs`. Known legacy endpoint records without capabilities preserve the source default, while unknown endpoint identity is disabled rather than silently authorized. Groups enforce the source 1–100 target bound without slicing/chunking requests or creating endpoint policy. All targets contain both endpoint ID and native container ID. Results remain in returned order and display each success/error separately; missing target results are unknown, not successes. Mutations do not retry automatically or optimistically invent inventory. Abort/failed responses do not establish rollback; scoped reads are invalidated so users can inspect before resubmitting.

## Log ordering and cleanup

The terminal is loaded and opened before acquiring a log stream. Live mode sends `tail: 200` by default, or an explicitly applied 1–1000 tail. Raw string chunks are written in iterator order without sorting, parsing, deduplication or a polling substitute. History uses `docker.logs`; live uses the subscription's own history tail. Mode/tail changes replace the terminal, never concatenate a snapshot with a duplicate live history. No event IDs, reconnect guarantees, resume policy or terminal command input are invented. Retry/reload is explicitly user initiated.

Stop and unmount abort the actual call signal and request the iterator's `return()`. A late iterator acquisition still reaches return. The return promise is retained and acknowledged once; a non-done return or rejected return is an error. The UI stays in cancellation-requested state until acquisition/consumption and browser return finish; it does not use a timeout to manufacture settlement. Callback writes and state updates are suppressed after disposal. Terminal/addons are disposed by the terminal owner; no resize, process, server or Docker listeners are added. Fit is a user action.

Browser iterator termination is explicitly not native cleanup attestation. Native late initialization, Docker stream destruction, request abort, transport disconnect and host disposal must still be joined and reviewed. Streams are held separately until the host binds them. Component cleanup cannot await React unmount; replacing a screen requests cancellation but cannot guarantee the old physical native stream has already settled. This feature does not clear that hold or guarantee zero overlapping native resources.
