# EXPANSION35 native transport ownership — frozen, unmounted HOLD

## Delivered scope

Only new `packages/core/src/infrastructure/http/nitro-transport/{boundaries,capacity,index}.ts` and this handoff were written. The adapter always returns `kind: "unsupported"`; there is no ready branch, HTTP/Fetch/Axios request launcher, connector replacement, new CONNECT parser, runtime registration or public package export. This is a bounded ownership/cleanup candidate around actual supplied `node:http.Agent`, existing `ResourceHttpsAgent`, `ClientRequest` and native streams, not a competing transport. Existing HTTP/certificate/authorization sources, manifests, guard and peer work are untouched.

`createNativeTransportOwnershipAdapter` provides:

- Synchronous, identity-owned reservation of pending capacity before any binding, bounded by explicit `maxPending` and `maxOwned` (1–4096). No asynchronous acquisition queue, scheduling/reordering, native pool mutation, native counter mutation or limit adjustment exists. Pending + active + quarantined records occupy the same total budget; quarantined pending records also retain pending-budget occupancy, even after late public attachment. The acquisition timer is real, bounded to 1–30000 ms and unrefed.
- `reserveRequest(...).bindExistingRequest(actualClientRequest)` attaches bounded observers to an existing actual request. Native socket attachment moves an outstanding pending record to active without opening another slot. Socket reuse is observed through the actual request's socket, not a guessed routing/pool key. This binding is **not** an admission hook and does not establish pre-I/O ownership or a native physical concurrency bound.
- Request-specific abort/deadline cancellation calls that request's actual `destroy`, retains any destruction failure and quarantines a bound reservation. Cancellation does not destroy an unrelated agent or assume native queue removal. The acquisition timer clears at attachment; the signal remains until actual request close/cancellation/drain. A completed request is not subsequently destroyed through an old cancellation association.
- An unbound reservation may be explicitly released/cancelled: its local settlement resolves because no request/transport was bound or launched by this adapter. This is the **only** successful reservation release. Reservation is not permission to dispatch a new request before ownership support exists.
- Physical close observers attach before destruction to known request/pool streams. `closed` is used only as the documented already-emitted-close state; `destroyed`, response consumption, iterator progress, readable end, timeout and native pool removal are never physical settlement evidence. Physical observers survive a request close or failed drain and detach their own error listener on actual stream close. A once-only socket observer retained after pre-socket request close covers a possible late public attachment without claiming it captures hidden connector callbacks.
- `drainAsync`/`disposeAsync` retire local admission synchronously, cancel owned request acquisitions, snapshot immutable native pools, call both actual agent destroy methods, independently destroy observed streams and start the existing HTTPS independent join even if destroy threw. Every available observed stream-close and bound request-close join starts before reporting those failures. Late public socket attachments remain observed and destroyed during retirement. There is one scoped drain watchdog (1–30000 ms); its expiry rejects, stops the local joining task and retains quarantine, never establishes closure. An independently rejected HTTPS join does not bypass other observed close joins.
- Repeated drain/dispose returns the exact same Promise, including rejection. Drain **always rejects** with the unsupported-boundary error aggregated with captured cleanup errors; even all observed closes cannot prove absence of hidden initial streams, pending callbacks or native queue tombstones. Bound request `settledAsync` rejects with that drain result, never successfully settles on request/response completion. Capacity remains occupied by bound records. Known stream/request registries and per-record failure retention are bounded; observation overflow is a failed/held boundary, not discarded-success ownership. Agent objects remain strongly retained, including native pools not fully observable within the registry bound.

## Exact unsupported boundaries

The returned typed boundaries are:

1. `native-admission-and-pending-capacity-hook-unavailable`: existing `ResourceHttpsAgent.createSocket` associates requests synchronously, but has no complete earlier admission bridge. The source native counters increase after delayed connection delivery, not at initiation. Local reservation bounds bookkeeping, **not** existing native maxSockets/maxTotalSockets or hidden physical acquisitions.
2. `native-queued-cancellation-removal-hook-unavailable`: request destroy may leave a native queued tombstone until socket assignment. No queue splice, placeholder stream, counter adjustment or private hook is used. Closed/cancelled bound records remain quarantined, rather than freeing capacity prematurely.
3. `native-pre-pool-and-late-connector-settlement-hook-unavailable`: the actual HTTPS tracker has no exported transaction-registration/terminal/late-callback stream enumeration. Public socket observers do not see every initial/raw/detached stream. No guessed native callback injection is added. Undici's pinned builder return remains void in its public types and pre-return allocation/throw capture remains unresolved.
4. `native-routing-and-proxy-tls-public-hook-unavailable`: the supported native public surface does not expose the accepted resolver or outer proxy-TLS trust customization. No route is guessed or parsed by this module.
5. `resource-https-independent-join-can-reject-before-physical-drain`: the frozen existing tracker checks failures before its connection-map wait, while the existing retirement wrapper can reject immediately after destroy throws. The new adapter joins all of its observed streams independently; it cannot fix or prove drainage of hidden source records without a separately released source lease.
6. `trusted-fetch-response-does-not-expose-physical-settlement`: frozen `fetchWithTrustedCertificatesAsync` returns a Response promise; it does not return the physical `settledAsync` required by the accepted Bangs trustedFetch resource. This module deliberately does not implement that resource through response-body iteration or a fake cleanup callback.

Supplying `caOverride` to a reservation fails before reservation/timer/binding with `q17-ca-override-undecided`. This does not implement, approve or infer override scope.
