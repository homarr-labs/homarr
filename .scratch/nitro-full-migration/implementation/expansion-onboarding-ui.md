## Claim, identity and secret boundaries

`OnboardingFrontend({kind: "unsupported"})` renders a hold without constructing a client, reading a database or inventing an environment. `source-snapshot` requires every source environment field, the actual source helper/component references and a native client; it is a presentation dependency boundary, not authority evidence. `hasUsers`, `canConfigurePrivileged`, available boards, driver and service URLs must come from the genuine reviewed server bootstrap. Missing producers must remain unsupported, not substituted with false booleans, null boards or empty arrays.

`claimTransport: "unsupported"` makes claim-requiring screens fail closed. `"source-http"` is a future source-compatible transport selection only, not a declaration that a native claim route is installed. The client accepts only issued/active success with a finite safe-integer future expiry; locked and administrator-required remain distinct. Cross-site/unavailable/malformed responses fail closed. It never reads, returns or serializes the HTTP-only claim token. Actual source-ready access has no fabricated claim expiry. Claimed access expires at the returned timestamp and hides setup/account controls; renewal requires an explicit action. Browser time and HTTP expiry metadata are defensive UX, not proof of server-time validity, no-users exclusion, origin policy or transaction authority.

Initial-user success clears the password fields and displays the source sign-in recovery destination. Automatic credentials sign-in is expressly unsupported: no new issuer, JWT, session callback, principal or successful-authentication assertion is supplied. Existing Auth/identity frontend work was not imported. The native user/group calls remain unmounted preparations and require their real authority/COMMIT bindings before production composition.

The narrow P2 account lifecycle correction is frozen for rereview. Both mutations forward their component-owned abort signal through the existing native client options. Layout-effect cleanup retires the owner and request generation on unmount or replacement of the ready claim, client, source or specific mutation target. The studio passes its actual ready claim object, not a fabricated claim. Each asynchronous success, error and finalizer checks owner identity, generation, abort state and claim expiry before changing state; retired failures cannot invalidate renewed authority, and retired group successes cannot navigate. A synchronous owner-pending guard also prevents duplicate dispatch before a React rerender. Cancellation is best-effort transport cancellation, never rollback of a dispatched native write. Inputs, source schemas/UI, sign-in recovery and native transition/completion/issuer/Q16 holds are unchanged.

Secrets live only in component drafts and the direct integration-test request. They never enter query keys, shared QueryClient state, local/session storage, logs, review summaries, URLs generated by this feature or MCP configuration. The test snapshot retains the existing immutable draft rather than JSON-serializing credentials. Integration tests own an abort signal and ignore stale/unmounted feedback; abort is not claimed to undo a remote operation. MCP key issuance is absent and its button is disabled. Raw unknown RPC/provider error text/data is never shown.
