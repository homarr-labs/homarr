These changes are not newly runtime-validated or certified deployable.

1. **Canonical snapshot refresh:** `editor.tsx` reloads a new same-ID canonical board automatically only when the draft is clean. A dirty draft keeps its original baseline and displays a conflict with an explicit reload/discard confirmation; discard adopts the latest received canonical board, not the obsolete baseline. `snapshot-draft.ts` gives settings/access the same captured-baseline and explicit discard/reload policy. A failed settings/access refetch with existing data displays the original error without unmounting the draft. Save actions remain disabled.
2. **Peer callback ownership:** `editor.tsx` binds peer application to the active widget-editor generation, edit-mode generation, captured baseline, and captured item ID. Cancellation, finish/discard, canonical baseline replacement, lost modify access, unmount, or opening another widget editor invalidate prior callbacks. Application and reducer-time checks use current received grants and current admin permission; existing item A cannot be changed into item B or resurrected after removal. New item IDs are reserved by the board owner using the existing source `resources.common.createId`; `BoardWidgetEditorInput.itemId` supplies that reservation and mismatched peer IDs are rejected. Missing source generator composition disables creation; no substitute ID generator/controller was introduced.
3. **Settled name availability:** `management.tsx` associates each existence result with the requested name. Creation/duplication submission requires a successful, fetched-after-mount, non-placeholder result for the current name, idle fetch status, and `exists === false`. Stale cached availability while revalidation is pending, paused, or failed cannot enable submission. Mount revalidation is required. Native server uniqueness and errors remain authoritative; rename uniqueness remains server-owned.
4. **Layout field snapshots:** `layout-editor.tsx` keys fields by layout ID instead of column counts. Clean fields adopt the current name, breakpoint, columns, gutters, and full layout snapshot after undo/redo or another update. Unapplied dirty fields retain their baseline and expose an explicit discard/reload conflict; apply/reset cannot silently reapply undone values. An incoming layout matching the local field values acknowledges those values as current. Apply/reset also verify the source layout reference inside the draft transaction so a queued stale handler fails closed.

Source schemas, layout projection/provenance, protected Mobile/Base roles, catalog ownership, source ID primitive, and the unchanged whole-domain atomic-save hold are retained. There is no new permission, multi-mutation persistence, canonical-cache optimistic write, registry, manifest, route, backend, or active renderer/editor/Auth/Integration peer edit/read in this correction.

Remaining rereview/composition joins stay open: native current-authority repair and atomic writer; grid nested/cross-targeting, eight-direction resize, swaps, selection/clipboard, rail/nested fitting and portals; persisted collapse; route/unsaved-navigation/viewport ownership; actual widget renderer/editor using the owner-provided `itemId`; domain/workspace export edges; theme/branding/translation and request-scoped provider bindings; app client, thumbnails, principal directories and image/media pickers.
