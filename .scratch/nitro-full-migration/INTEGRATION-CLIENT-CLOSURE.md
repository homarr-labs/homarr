# Integration client closure

## Decision and evidence boundary

Planning only. No implementation, execution, validation, provider calls or exposure approval. Source evidence: `packages/integrations/src/base/{creator,integration,session-store}.ts`, source classes/interfaces/protocol helpers, `stats/{providers,existing,stats-integration}.ts`, frozen `runtime/`, frozen own `nitro-bindings/`, and package manifests. Active Widget/G3/HTTP/UI/Auth/host implementations were not used to design this plan.

**89 factory identities are not 89 migrated clients.** `base/creator.ts` has 89 entries; `stats/providers.ts` supplies 30 native Stats kinds; `nitro-bindings/native.ts` refuses the other 59 through `assertClassResources`. All 30 remain resource candidates, not production approvals. Their complete public surface is `getStatsAsync`, `getHttpAuthenticationAsync`, `testConnectionAsync`, and `publicIntegration`. `StatsIntegration` has no additional provider-specific public controls: no missing non-Stats business-method family was found for those 30. Authentication can execute provider I/O and testing calls Stats; neither is covered merely by counting a Stats result. `testingAsync` there is protected, not a public operation.

The 59 require the entire public surface below, not just Stats projections. `stats/existing.ts` additionally defines projections for 56 of those kinds, including the explicitly synthetic `mock`; `bindery`, `ical`, and `wazuh` have no projection there. Preserve each existing metric/pick/null/unit conversion. Do not invent projections for the other three or transplant the ambient `withHttpRequestSignalAsync` wrapper.

## Source/type obstacle and recommended seam

`IntegrationInstanceOfKind<K>` is `Awaited<ReturnType<IntegrationCreators[K]>>`, not a structural capability interface. `Integration` owns protected configuration/helpers and a private URL helper; individual classes additionally own private SDK/session/protocol state. The factory's `satisfies Record<IntegrationKind, ...Promise<Integration>>` does not erase those nominal obligations. A detached object implementing a feature interface cannot replace a concrete factory result. Subclassing/importing an unchanged legacy class does not remove its ambient imports. Casts, monkey-patching Core, prototype replacement and a second provider registry are not solutions.

**Preferred strategy:** additive, source-backed protocol modules in the six directories below; one later coordinator join makes the genuine original classes delegate to them and removes legacy ambient imports. Keep class identities, inheritance, factory generics, public signatures, original schemas and error/result contracts. Port endpoint construction, pagination, normalization, authentication, retry/fallback and SDK use from the named source; do not reimplement from product descriptions. Private algorithms cannot currently be imported safely: their extraction/delegation is an explicit coordinator obligation, not something a wrapper already accomplishes. Existing source casts must be replaced by narrowing/validated wire types in the new modules, not copied as authority.

A type-only public projection such as `Pick<IntegrationInstanceOfKind<K>, keyof IntegrationInstanceOfKind<K>>` can check adapter public parity without exposing private/protected state. It is not executable wiring and does not by itself change `executeNativeAsync`'s concrete-class contract. If Oracle instead selects detached clients, independently review that public-contract change across factory/executor/bindings and preserve all public getters and method properties; do not silently widen to `Integration`, `unknown` or an untyped method dispatcher. The preferred genuine-class route needs no such factory return-type change.

### Narrow resource contract proposal — Oracle review required

Ordinary HTTP operations can reuse `IntegrationTransportLease`, `withIntegrationTestingAsync` and the genuine bound `IntegrationTestingInput`, despite their testing-oriented names. `transport.runAsync(context, closure)` only fences/tracks a closure; it does not redirect imported Core functions. Every request, response body and SDK subrequest must actually use the lease and operation signal.

Propose one additive, discriminated protocol-lease capability on `IntegrationRuntimeResources`, defined centrally in `runtime/contracts.ts`: owned Node HTTP(S) agents for SDK/DAV/cookie transports, or an owned WebSocket dial capability for raw `ws` clients. Each branch exposes actual typed transport primitives, operation context and awaited physical release, never `getSystemInfo`/other business-result producers. The binding owns TLS material, lookup/proxy policy, agents, sockets, late acquisition and retirement; bucket code owns SDK construction and wire algorithms. Cookie agents must be created with the SDK's actual jar under the same owner. SSE uses an HTTP streaming lease with source body-timeout behavior and tracked reader/body retirement. Exact SDK request/agent types must be established before implementing each branch; an incompatible SDK remains held, not cast to fetch/Axios.

Also propose a narrow integration image-URL service preserving the source ImageProxy registration inputs/results for `plex`, `immich`, `tracearr`, and `gotify`. No direct construction of ambient `ImageProxy`, no credential-bearing public URLs and no identity/pass-through substitute. Its real producer is a coordinator dependency; unrelated client methods can port first. Use existing runtime logging or a reviewed typed metadata adaptation; do not import logger/env initialization or drop source error semantics to avoid the join.

These additions do not supply principal authority, new currentness, COMMIT coherence or a new trust policy. Frozen config/CBC-HMAC/session-CAS/cache producers and the acquisition cancellation fix stay unchanged. Missing protocol/image capabilities fail closed. Q16/Q17/Q18, production guard/authority, PG lease COMMIT and physical settlement remain holds.

## Central dependency/export join — exact requested scope

Coordinator only, after bucket acceptance:

- `packages/integrations/package.json`: retain existing direct `@ctrl/deluge`, `@ctrl/qbittorrent`, `@ctrl/transmission`, `@homarr/node-unifi`, `@immich/sdk`, `@jellyfin/sdk`, `axios`, `ical.js`, `proxmox-api`, `timezones-ical-library`, `tsdav`, `undici`, `ws`, `xml2js`, `zod` and applicable Homarr contracts. No new SDK/vendor or automatic switch to `maria2`/`octokit` is required.
- Direct-dependency gaps: source uses `dayjs` (root catalog `1.11.21`, absent from this package's dependencies), `http-cookie-agent/http` (UniFi runtime), and type-only `node-fetch` (current DAV bridge). Add `dayjs: catalog:` centrally if retained. Resolve and explicitly declare the existing compatible cookie-agent package/version before retaining that path; no version is established by the inspected manifests. For DAV, either establish the exact existing Node-fetch type dependency or remove that bridge using an accepted SDK-native type, not a cast. No install/lock change under bucket leases.
- `runtime/contracts.ts` and `runtime/index.ts`: reviewed protocol-lease/image-URL types and public reexports; physical resource construction remains in the owned binding, not feature buckets. Reuse exported runtime/session/error helpers and existing source schemas; no new general-purpose utility package.
- Proposed single new `@homarr/integrations/native-clients` entrypoint: type-safe named module exports/composition only, with its central `src/native-clients/index.ts` and manifest export added at the join. No second kind map, provider registry, catch-all result dispatcher or eager legacy-root import. Host-facing owned-binding exports must also be explicit at that same join; current manifest exports do not expose `nitro-bindings`.
- Coordinator redirects the original class imports/delegation and construction probes, preserves `base/creator.ts` as the sole kind-to-client authority, joins the 56 existing Stats projections without ambient Core signal wrappers, and only then revises per-kind/per-method holds backed by evidence. Existing factory/resources/schema/manifests/routes and frozen own bindings remain untouched until this join. No host/API route wiring is performed by these buckets.

## Order, acceptance and infeasible cases

1. Oracle chooses genuine-class delegation and approves the narrow raw-resource contract, dependency gaps, source extraction ownership and authority classification. If that decision is withheld, additive protocol ports may be designed but cannot truthfully be wired as complete clients.
2. Proceed first with ordinary HTTP protocol ports in buckets 2–6 using the existing lease; bucket 1 records complete native Stats public-surface closure without rewriting providers. SDK/stream/image branches depend on their accepted seams, not on opening unrelated production holds.
3. Freeze each bucket with a method-by-method source-origin map, exact wire/normalization preservation, resource acquisition/release paths, remaining physical dependencies and proposed coordinator edits. Independent review must cover auth refresh, probes, redirects/proxy/TLS, fan-out/body drain, cancellation/late settlement, state fencing and mutation uncertainty. Source parity is an acceptance requirement, not a claim already established here.
4. Coordinator performs the single physical join and separately authorized validation afterward. Full-client closure requires all 89 identities' source public surfaces plus applicable Stats projections to be wired and accepted. A runnable client with missing controls/streams/images or unbound authority is not full coverage. This planning lease ran no checks and offers no runtime/production approval.

**Not feasible under additive-only/frozen-original wiring:** intercepting legacy Core imports; satisfying private-field class types with structural objects; constructing SDKs with unverified agent/fetch signatures; preserving TrueNAS static connections without lifetime reownership; publishing original image outputs without a real registration producer; treating abort or `socket.close()` as physical settlement. Any SDK whose internal transports cannot be injected or retired remains specifically held pending a narrow source-owned refactor/contract review. Do not work around it with tRPC tunnels, host-supplied business-result controllers, fake resources/currentness or a competing factory.

Physical saved SQL snapshots/revisions, native principal/authorization, management-test principal binding and SQL/state COMMIT coherence remain separate mandatory joins. Non-cooperative work and signal-less currentness waits can still keep shutdown drain pending. No client-port approval resolves Q16/Q17/Q18 or grants production, trust override, PG lease COMMIT or physical-settlement authority.
