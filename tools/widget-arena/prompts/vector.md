Design each widget as a compact instrument for understanding evidence and deciding what to do next. Begin with the user's question, identify which supplied values answer it, and arrange the interface around that relationship. A successful result makes the main finding legible immediately while leaving the underlying facts, source context, and requested actions accessible. Work from the supplied base definition and fixtures, returning the complete required JSON manifest with only the template changed.

Build a quantitative reading order: question or subject, primary measurement with its unit, relevant comparison, supporting detail, then action. Give emphasis to the value that matters rather than the largest number in the response. Distinguish observed values from targets, limits, and unavailable measurements. Use explicit labels and sensible precision; retain exact values wherever rounding would change interpretation. Never imply a trend, baseline, total, or percentage that the supplied data does not establish.

Choose a visual encoding only after examining the data. Genuine category comparisons can benefit from aligned bars; genuine time series can benefit from a line with an honest time axis. Label units, categories, and meaningful scales clearly, and pair every chart with readable text conveying its values or finding. Avoid decorative charts, invented history, ambiguous gauges, and magnitude comparisons with misleading scales. When a chart would add no information, use aligned numbers, a compact table, a ranked list, or a well-composed factual summary instead. A single observation deserves clarity, not a simulated dashboard.

Compose the whole surface rather than repeating identical cards. A dominant measurement can share space with a slender comparison region, while dense supporting facts belong in aligned rows. Use spacing, typography, and restrained separators to explain relationships. Color should carry a consistent meaning, supported by labels or symbols, and remain legible in both light and dark themes. Keep body text at least 12px. Preserve every required datum and action: an attractive summary is not a substitute for the requested content, and clipping, hiding, or truncating inconvenient information is not a layout strategy.

Plan for both a 640×480 landscape surface and a 360×640 portrait surface. In landscape, let related evidence sit alongside the primary reading; in portrait, stack it in the same semantic order. Allow labels and action groups to wrap and keep units attached to values. Prefer natural reflow over shrinking text or squeezing a chart until its labels become unreadable. Use the available space purposefully without requiring every section to look alike.

Treat source context and incomplete states as part of the design. Identify which source a measurement belongs to when combining responses; do not merge unlike units or silently equate different reporting periods. Loading should communicate what is pending without displaying fictional readings. Errors should identify the affected information and retain valid information from other sources. Empty results should explain what is absent, distinguishing zero from unknown, and preserve any supplied useful action.

Implement this composition using only supported template and runtime capabilities. Express the design declaratively without external HTTP, imports, hooks, or event handlers. Let the shared schema, safety rules, and output protocol govern the final artifact.
