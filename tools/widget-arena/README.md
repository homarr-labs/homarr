# Widget arena

These twelve cases are new synthetic, task-inspired fixtures, not historical Langfuse benchmarks. All controls are simulations; no live service traffic. Sixty first attempts and 120 same-task comparisons are fixed, including invalid/missing coverage.

1. `bun tools/widget-arena/harness.ts freeze` freezes common cases and installed runtime/catalog fingerprints. Do this before any generation; do not refreeze during collection.
2. `bun tools/widget-arena/harness.ts prepare <five prompt paths>` creates fifteen private four-case assignments under ignored `.slim/deepwork/widget-arena/`. Each assignment includes an absolute `outputPath` under `raw/`. Dispatch manually using the declared model: the author writes the strict four-entry JSON array ONCE to that path using patch, then replies only with the small JSON acknowledgement `{jobId,artifact,caseIds}`. No validation, feedback or rewrite loops; do not capture acknowledgement text as definitions. The harness never calls a model or launches agents.
3. `bun tools/widget-arena/harness.ts import <job-id> <assigned-artifact-path> <session-id>` retains the untouched raw first-attempt JSON artifact and its path/hash, then reads that session through the authenticated local `opencode api get` V2 CLI. It verifies the returned session ID and every assistant message's provider/model/variant across all pages. Private receipts keep observed model references, message IDs and server-response hashes, not message contents. Wrong/missing/unavailable metadata or an attempted missing artifact makes all four outputs invalid, never pending or silently retried. Each job imports once. Jobs not yet imported remain pending.
4. `bun tools/widget-arena/harness.ts build [output-path]` builds a server-only pack. Never serve this pack directly: condition mappings/prompts are reveal-only. Raw session provenance stays in ignored receipts. Use the actual administrator arena route for rendering/captures, not a separate preview server.

`bun tools/widget-arena/harness.ts --smoke` checks hand-authored fixture/schema guards and schedule balance without producing model artifacts. `bunx tsc -p tools/widget-arena/tsconfig.json` checks the focused harness. All five treatments must use `contract.md`, `context.json` and identical frozen case groupings.

`bun tools/widget-arena/harness.ts --check-session <session-id>` checks metadata parsing without importing or scoring any output. Freeze fingerprints include the route-local clock/viewport/state contract; dataset hashes also bind those values and complete cases. Prelaunch revisions must preserve earlier inputs and preparation state in an ignored snapshot before re-freezing; never refreeze once scored attempts begin.

After all 60 attempts are terminal and the administrator capture route is verified, run `bun tools/widget-arena/capture.ts` for 120 actual-frame success screenshots; `--states all` captures 480. Optional `--base-url`, `--auth-state`, `--output-dir` (must not exist) and `--pack` select inputs. Each isolated run writes opaque-ID PNGs and append-only capture/error evidence under ignored `.slim/deepwork/arena-qa/captures/` by default; unavailable candidates remain in coverage. It never generates, repairs, imports, reveals conditions or casts votes.
