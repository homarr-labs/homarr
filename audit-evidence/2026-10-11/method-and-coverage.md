# Audit method and coverage

Baseline: bab8e2a2dad837365a2237263b58b658d23abe69 on dev; branch feat/measured-memory-audit. Pinned Node 24.18.0 and Bun 1.4.2, exact dependencies from bun.lock (baseline.json). Twenty-four domain workers and seven direct-code overview reviewers used GPT-6 Luna in waves within the actual 17-slot limit, including coordinator. Each assignment lists exact paths, dependencies, questions and expected evidence. Large files received dedicated complete passes.

All 4,201 tracked paths have an inventory entry. All 2,387 assigned production paths have per-file evidence: 2,386 reviewed and one generated vendored Mantine patch excluded from individual review, with its installed implementation and callers inspected. The complete manifest has no pending paths. The other 1,814 paths have individual exclusion reasons for prose, tests, metadata, generated data or assets. Assets and generated runtime data were assessed through imports, loading paths and byte counts rather than individually reviewing repetitive data. Executable docs code and its styles/UI were reviewed (161 paths), independently of documentation prose.

Findings in leaf reports are source observations unless a later measurement/decision explicitly confirms impact. A suspicious source pattern does not establish a measured leak, bundle, or transfer result. Later measurement decisions supersede earlier static wording, especially collapsed board forms, cache expiry, modal retention, database pool defaults and integration-barrel startup reachability.

Measurements use synthetic data and serialized workloads. Inspection and exclusive source edits run in parallel; heavy browser, generator, analyzer and query measurement jobs do not overlap. Other user-owned development servers run on this machine; they were not stopped, so timing variance may include unrelated host contention. Isolated child processes and fresh browser contexts avoid cross-variant application state, but do not eliminate host contention.

Nine alternating pairs are used for short repeatable scenarios. Node heap samples use explicit GC and an event-loop yield after releasing query results. Chromium samples use CDP forced GC. A sampled maximum is not an exact peak; RSS includes allocator reservation and code, and does not equal reachable heap. ArrayBuffers are a subset of external memory and are never added again. LDAP fixture process memory includes its local synthetic peer and is not claimed as production server-only memory. Calibration sentinels in DOM measurements are synthetic, not estimates of real widget memory.

Next.js experimental-analyze uses the installed production Turbopack graph and emitted module/chunk code, but does not produce an application build. Selected raw graph data, checksums, dependency contributions and route evidence are preserved. Analyzer gzip-oriented estimates, fixture HTTP compressed response bytes, serialized database-result bytes, and deployed API/RSC/WebSocket bytes are distinct quantities. Unobserved deployed traffic is marked unmeasured. No combined or whole-application RAM percentage is inferred from isolated fixtures.

The cache expiry exploratory baseline accidentally used shell Node 25.1.0 instead of pinned Node 24.18.0 and used no empty-cache or invalidation controls. Its flat populated-to-idle heap is consistent with retention, but cannot attribute it to the cache. It is discarded as improvement evidence, retained only as an inconclusive rejected experiment. All retained paired results must record the correct pinned Node runtime.

No new unit or E2E tests, Docker builds, broad test suites or monorepo builds are part of this audit. Existing focused checks and necessary targeted production graph analysis validate retained changes. Heap snapshots remain local under /tmp; only derived synthetic retention metrics are archived.
